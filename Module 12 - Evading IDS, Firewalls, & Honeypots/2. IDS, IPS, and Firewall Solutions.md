## 1. Intrusion Detection using YARA Rules
**Source:** [https://yara.readthedocs.io](https://yara.readthedocs.io)

YARA is a multi-platform malware research tool (Windows, macOS, Linux) that allows security analysts to detect and classify malware via a **rule-based approach**. Security analysts create “rules” (descriptions of malware families) using text or binary patterns. YARA can also use hexadecimal patterns, plain texts, and special operators.

### YARA Rule Syntax
A YARA rule comprises a Boolean expression and strings. Each rule starts with the word `rule` followed by the rule name. It is comprised of three parts:

1. **Metadata (`meta`):** General information identifying the files gathered.
2. **Strings (`strings`):** Defines the strings to be searched within the files (hexadecimal strings, text strings, or regular expressions).
3. **Condition (`condition`):** Boolean expressions determining when the result will be true (a match).

**Example of a YARA rule:**
```yara
rule silent_banker : banker 
{
    meta: 
        description = "This is just an example" 
        threat_level = 3 
        in_the_wild = true
    strings: 
        $a = {6A 40 68 00 30 00 00 6A 14 8D 91} 
        $b = {8D 4D B0 2B C1 83 C0 27 99 6A 4E 59 F7 F9} 
        $c = "UVODFRYSIHLNWPEJXQZAKCBGMT"
    condition: 
        $a or $b or $c
}
```
*(In this example, any of the three strings matched will flag the file as the "silent_banker" Trojan. Note the combination of both hex and text patterns).*

## 2. YARA Tools

### yarGen
**Source:** [https://github.com](https://github.com)
A tool used for **generating YARA rules**. It creates rules from strings identified in malware files while removing strings that appear in goodware files. It includes a large goodware string and opcode database as ZIP archives that must be extracted before use.
* Dependencies are installed via: `pip install -r requirements.txt`
* Run help via: `python yarGen.py --help`

## 3. Intrusion Detection Tools

Intrusion detection tools offer real-time, zero-day protection by reading network packets, reconstructing sessions, scanning for attack signatures, and finding statistical anomalies.

### 3.1 Snort & Snort Rules
**Source:** [https://www.snort.org](https://www.snort.org)

Snort is an open-source NIDS capable of real-time traffic analysis and packet logging. It detects buffer overflows, stealth port scans, CGI attacks, SMB probes, and OS fingerprinting. 
* Uses **libpcap** library (UNIX/Linux) or **Winpcap** (Windows).
* Deployed in **promiscuous mode** to decode all packets passing through the network media.
* Can be used as a straight packet sniffer (like `tcpdump`), a packet logger, or an NIPS.

#### Snort Rules Principles:
Snort rules must be **robust** (maintain a hard check) and **flexible** (act immediately).
1. **Single Line:** No written rule must extend beyond a single line.
2. **Two Logical Sections:** 
   * **Rule Header:** Contains the action, protocol, source/destination IPs, ports, and direction.
   * **Rule Options:** Includes alert messages and inspected packet contents.

#### Rule Actions and IP Protocols:
* **Six default actions:** `alert`, `log`, `pass`, `drop`, `reject`, and `sdrop`.
* **Three supported protocols:** `TCP`, `UDP`, `ICMP`.

#### Direction Operator and IP Addresses:
* **Direction Operator:** `->` indicates single direction. `<>` indicates bidirectional (handy for recording both sides of a telnet/POP3 conversation). Note: There is no `<-` operator.
* **IP Addresses:** Can be a single IP, CIDR block, list (e.g., `[192.168.1.1,10.1.1.24]`), or use the keyword `any`. 
* **Negation (`!`):** Matches all except the specified IP/range.
  * *Example (Alerts traffic from outside the local network):* 
    `alert tcp !192.168.1.0/24 any -> 192.168.1.0/24 111 (content: "|00 01 86 a5|"; msg: "external mountd access";)`

#### Port Numbers & Negation:
Ports can be static, `"any"`, ranges (`:`), or negated (`!`).

**Examples of Port Definitions:**
| Protocols | IP Address & Port | Action |
| :--- | :--- | :--- |
| **Log UDP any →** | `192.168.1.0/24 1:1024` | Log UDP traffic from any port going to destination ports 1 to 1024. |
| **Log TCP any →** | `192.168.1.0/24 :5000` | Log TCP traffic from any port going to ports ≤ 5000. |
| **Log TCP any :1024 →** | `192.168.1.0/24 400:` | Log TCP traffic from well-known ports going to ports ≥ 400. |

### 3.2 Suricata
**Source:** [https://suricata.io](https://suricata.io)

Suricata is a robust threat detection engine for real-time IDS, inline IPS, Network Security Monitoring (NSM), and offline pcap processing. 
* Uses extensive rules and signature language.
* Provides **Lua scripting** support for complex threats.
* Outputs standard **YAML and JSON** for effortless integration with SIEMs, Splunk, Logstash/Elasticsearch, and Kibana.
