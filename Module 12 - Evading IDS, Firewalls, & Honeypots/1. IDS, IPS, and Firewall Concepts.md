## 1. Intrusion Detection System (IDS)
An **Intrusion Detection System (IDS)** is security software or a hardware device used to monitor, detect, and protect networks or systems from malicious activities. It alerts security personnel immediately upon detecting an intrusion.

### Main Functions of IDS:
* Gathers and analyzes information to identify possible violations of security policy, unauthorized access, and misuse.
* Often acts as a **"packet sniffer"** intercepting packets (usually TCP/IP).
* Analyzes captured packets.
* Evaluates traffic for suspected intrusions and raises an alarm.

### Where IDS Resides in the Network:
* Commonly placed near the firewall (inside or outside).
* When inside, it is ideally near the **DMZ**.
* Best practice: **Layered defense** with one IDS in front of the firewall and one behind it.

### How an IDS Works:
* Uses **sensors** to detect malicious signatures in packets. Advanced IDS includes **behavioral activity detection**.
* If a signature matches, it performs predefined actions (terminating connection, blocking IP, dropping packet, raising alarm).
* If a signature matches, **anomaly detection** is skipped; otherwise, traffic patterns are analyzed for anomalies.
* Once all tests are passed, the IDS forwards the packet to the network.

## 2. Intrusion Prevention System (IPS)
An **Intrusion Prevention System (IPS)** is an *active* IDS capable of both detecting and preventing intrusions. IPS sits **inline** in the network (between source and destination) behind the firewall as an additional layer of protection to actively analyze and make automated decisions.

### IPS Actions:
* Generate alerts for abnormal traffic.
* Continuously record real-time logs.
* Block and filter malicious traffic.
* Detect and eliminate threats quickly.
* Identify threats accurately without false positives.

### Classification of IPS:
1. **Host-based IPS**
2. **Network-based IPS**

**Advantages of IPS over IDS:**
* Can block and drop illegal packets (unlike IDS).
* Monitors activities in a single organization.
* Prevents direct attacks by controlling network traffic.

## 3. How an IDS Detects an Intrusion

IDS uses three primary methods to detect intrusions:

### 1. Signature Recognition (Misuse Detection)
Compares incoming/outgoing packets with binary signatures of known attacks using pattern-matching.
* **TCP flags** can be defined as binary signatures.
* **Problems:** 
  * Innocuous packets containing the same signature trigger **false positives**.
  * Improper signatures trigger false alerts.
  * Massive signatures needed; requires high bandwidth.
  * New viruses like **URSNIF** and **VIRLOCK** require completely new signatures because altering a single bit invalidates the previous signature.

### 2. Anomaly Detection (Not-Use Detection)
Maintains a database of anomalies. Detects when an event falls outside the **tolerance threshold** of normal traffic (a deviation from regular use).
* Based on fixed behavioral characteristics.
* **Challenge:** Establishing a model of "normal" use due to statistical variations and unpredictability in network traffic.

### 3. Protocol Anomaly Detection
Analyzes network traffic for deviations from established protocol standards/behavioral patterns (e.g., misconfigurations or malicious activity).
* **Baseline behavior:** Learning expected structure, sequence, and timing.
* **Anomaly identification:** Unusual packet structures, unexpected sequence orders, protocol violations.
* **Detection rules:** Rules defining an anomaly based on protocol specifications.

## 4. General Indications of Intrusions

### File System Intrusions:
* New, unknown files/programs.
* Escalation of privileges (changing files from read-only to write).
* Unexplained modifications in file size, ownership, access permissions.
* Rogue **SUID** and **SGID** files on Linux.
* Executable files with strange/double extensions.
* Missing files, unexpected disk space usage, slow performance, file crashes.

### Network Intrusions:
* Sudden increase in bandwidth consumption.
* Repeated probes of available services.
* Connection requests from IPs outside the network range.
* Repeated remote login attempts.
* Sudden influx of log data (indicates DoS/DDoS).
* Unexpected changes in network config/firewall rules.
* Unusual outbound connections to malicious domains.

### System Intrusions:
* Sudden short/incomplete logs.
* Unusually slow performance.
* Missing logs or logs with incorrect permissions.
* Modifications to system software/config files.
* Unusual graphic displays or text messages.
* Gaps in system accounting, crashes, reboots.
* Unfamiliar processes, AV/IDS alerts.
* Artifacts like shell history files or remnants of attacker tools.

## 5. Types of Intrusion Detection Systems

### 1. Network-Based Intrusion Detection Systems (NIDS)
Checks every packet entering the network. Placed in **promiscuous mode** on the network as a "black box" to monitor traffic (DoS attacks, port scans). Analyzes anomalies at the router and host levels.

### 2. Host-Based Intrusion Detection Systems (HIDS)
Analyzes a single system's behavior (installed on a desktop/server). Detects unauthorized insider activity and unauthorized file modifications. HIDS is more platform-centric (greater focus on **Windows OS**, but UNIX is supported).

---

## 6. Types of IDS Alerts

| Alert Type | Description |
| :--- | :--- |
| **True Positive** (Attack - Alert) | An actual attack triggers an alarm, or a drill using hacker tools successfully triggers an alarm. |
| **False Positive** (No attack - Alert) | IDS treats regular system activity as an attack. Weakens user reactions to actual events. |
| **False Negative** (Attack - No Alert) | IDS fails to react to an actual attack event. **Most dangerous failure.** |
| **True Negative** (No attack - No Alert) | IDS successfully ignores acceptable behavior without raising an alarm. |

## 7. Firewalls & Firewall Architecture

A **firewall** is a software or hardware-based system at the network gateway that protects private networks from unauthorized access. Examines all messages entering/leaving the intranet. 
* Works closely with router filters.
* Restricts incoming traffic to POP/SMTP.
* Logs attempts to access services.

### Firewall Architecture Elements:

1. **Bastion Host:** Acts as a mediator between inside and outside networks. Has two interfaces: Public (Internet) and Private (Intranet).
2. **Screened Subnet:** A protected network (DMZ) created with a two- or three-homed firewall behind a screening firewall. Responds to public requests while keeping the intranet isolated.
3. **Multi-homed Firewall:** A node with multiple NICs connecting to two or more networks, offering deeper protection like a back-to-back firewall.

---

## 8. Demilitarized Zone (DMZ)
The DMZ is a neutral area hosting computers (sub-network) between the internal network and untrusted external networks. Services like **email, web, or FTP** that provide access to external users reside in the DMZ. Web servers communicating directly with sensitive databases should not reside in the DMZ.

---

## 9. Types of Firewalls

### Types of Firewalls Based on Configuration

1. **Network-based Firewalls:**
   * Dedicated firewall device placed on the perimeter (e.g., **Cisco Secure Firewall ASA**, **FortiGate 7121F**, **Palo Alto PA-7500**, **Check Point 28000 Quantum**, **Juniper SRX**).
   * **Advantages:** High security, high speed, minimal interference (separate component).
   * **Disadvantages:** Expensive, difficult to implement, consumes space.

2. **Host-based Firewalls:**
   * Sits between application and OS networking components on an individual PC (e.g., **Microsoft Defender Firewall**, **ZoneAlarm Pro**, **Comodo Firewall**, **Norton Smart Firewall**, **McAfee Firewall**).
   * **Advantages:** Less expensive, ideal for personal/mobile use, easy to configure.
   * **Disadvantages:** Consumes system resources, difficult to uninstall, slow response times.

### Types of Firewalls Based on Working Mechanism

#### OSI Layer Table:
| OSI Layer | Firewall Technology |
| :--- | :--- |
| **Application** | Virtual Private Network (VPN), Application Proxies |
| **Presentation** | Virtual Private Network (VPN) |
| **Session** | Virtual Private Network (VPN), Circuit-Level Gateways |
| **Transport** | Virtual Private Network (VPN), Packet Filtering |
| **Network** | VPN, NAT, Packet Filtering, Stateful Multilayer Inspection |
| **Data Link** | VPN, Packet Filtering |
| **Physical** | Not Applicable |

*(Note: Additional firewall solutions based on working mechanism include **IPFire**, **pfSense**, **SonicWall TZ**, **BIG-IP Advanced Firewall Manager**, **Sophos Firewall**, **WatchGuard Firebox**, **FortiProxy**, **ZYXEL VPN Firewall**, **DrayTek Vigor2765**).*

#### 1. Packet Filtering Firewall
Works at the **Internet layer** (TCP/IP) or **Network layer** (OSI). Forwards or drops packets based on:
* **Source / Destination IP Address**
* **Source / Destination TCP/UDP Port**
* **TCP flag bits** (SYN, ACK)
* **Protocol in use**
* **Direction** (entering/leaving)
* **Interface**

#### 2. Circuit-Level Gateway Firewall
Works at the **Session layer** (OSI) or **Transport layer** (TCP/IP). Forwards data without verifying the content, but checks the **TCP handshake** to validate the requested session. Hides private network information.

#### 3. Application-Level Firewall (Proxies)
Filters packets at the **Application layer**. Restricts traffic to supported proxy services (filters application-specific commands like `HTTP GET`/`POST`). Can inspect payloads to catch worms hidden in legitimate protocols.
* **Active:** Rejects/denies known vulnerabilities (SQL injection, XSS).
* **Passive:** Checks requests against vulnerabilities but does not actively reject them.

#### 4. Stateful Multilayer Inspection Firewall
Combines packet filtering, circuit-level gateways, and application-level firewalls. Remembers packets that passed through earlier (stateful). Performs deep packet inspection. **Cisco PIX** firewalls are stateful.

#### 5. Application Proxy
A proxy server that filters connections for specific services (e.g., FTP proxy). Gives the user the illusion they are talking to the real server. 
* **Advantages:** Understands application protocols (good logging), caches requested data (reduces load).
* **Disadvantages:** Lags behind non-proxy services, requires application modifications.

#### 6. Network Address Translation (NAT)
Hides internal IPs by modifying the source/destination addresses.
* Schemes: Single external address translation, Dynamic allocation without port changes, Fixed mapping with port mapping, Dynamic allocation with port pairing.

#### 7. Virtual Private Network (VPN) Firewall
Provides secure transmission over an untrusted network via **encapsulation and encryption**. Establishes a virtual point-to-point connection.
* **Advantages:** Hides traffic, avoids attackers.
* **Disadvantages:** Vulnerable to attacks on the destination network.

#### 8. Next-Generation Firewalls (NGFWs)
Sophisticated solutions incorporating **deep packet inspection, application awareness, IPS, and cloud-based threat intelligence**.
* **Advantages:** Integrated IPS/antimalware, visible user activity, blocks zero-day/APTs.
* **Disadvantages:** Expensive, highly complex to manage, deep inspection introduces latency.

## 10. Firewall Limitations

* Can restrict users from accessing valuable services (FTP, Telnet, NIS).
* Cannot prevent **internal attacks** (disgruntled employees, backdoors).
* Security relies on a single point of failure (can cause bottlenecks).
* Cannot protect against **social engineering** or **data-driven attacks** (malicious links via email).
* Cannot protect against already infected **external devices** (USBs, laptops) connected directly to the internal network.
* Unable to protect against all **zero-day** viruses.
* Faulty network design or configuration renders it useless.
* Does not block attacks from a higher level of the protocol stack.
* Cannot understand **tunneled traffic**.
* Does not prevent attacks from **dial-in connections**.
