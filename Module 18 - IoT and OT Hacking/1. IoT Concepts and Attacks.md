## 1. What is the IoT?

The Internet of Things (IoT), also known as the Internet of Everything (IoE), refers to computing devices that are web-enabled and have the capability of sensing, collecting, and sending data using sensors, and the communication hardware and processors that are embedded within the device. In the IoT, a "thing" refers to a device that is implanted in a natural, human-made, or machine-made object and has the functionality of communicating over a network.

Some of the key features of the IoT are connectivity, sensors, artificial intelligence, small devices, and active engagement.

---

## 2. How the IoT Works

IoT technology includes four primary systems: IoT devices, gateway systems, data storage systems using cloud technology, and remote control using mobile apps.

*   **Sensing Technology:** Sensors embedded in the devices sense a wide variety of information from their surroundings.
*   **IoT Gateways:** Gateways bridge the gap between an IoT device (internal network) and the end-user (external network).
*   **Cloud Server/Data Storage:** Collected data arrives at the cloud, where it is stored and undergoes data analysis.
*   **Remote Control using Mobile App:** The end-user uses remote controls (mobile phones, tablets) to monitor, control, retrieve data, and take specific actions.

---

## 3. IoT Architecture

*   **Edge Technology Layer:** Consists of all hardware components (sensors, RFID tags, readers) deployed in the field for data collection.
*   **Access Gateway Layer:** Bridges the gap between two endpoints (device and client), carrying out message routing, identification, and subscribing.
*   **Internet Layer:** Main component for communication between endpoints (device-to-device, device-to-cloud).
*   **Middleware Layer:** Operates in two-way mode, acting as an interface between the application and hardware layers (data management, analysis, access control).
*   **Application Layer:** Top of the stack, responsible for delivering services to relevant users.

## 5. IoT Technologies and Protocols

### Short-Range Wireless Communication
*   **Bluetooth Low Energy (BLE):** Wireless personal area network.
*   **Light-Fidelity (Li-Fi):** Visible Light Communications (VLC) system (up to 224 Gbps).
*   **Near-Field Communication (NFC):** Magnetic field induction for contactless communication.
*   **Radio-Frequency Identification (RFID):** Electromagnetic fields to read tags.
*   **Thread:** IPv6-based networking protocol for home automation.
*   **Wi-Fi / Wi-Fi Direct:** LAN technology / Peer-to-peer communication.
*   **Z-Wave:** Low-power, short-range for home automation.
*   **Zig-Bee:** Short-range communication protocol (IEEE 203.15.4).
*   **ANT:** Multicast wireless sensor network technology.

### Medium-Range Wireless Communication
*   **HaLow:** Wi-Fi variant for extended range.
*   **LTE-Advanced:** Enhancement to LTE.
*   **6LoWPAN:** IPv6 over Low-Power Wireless Personal Area Networks.
*   **QUIC:** Multiplexed connections over UDP.

### Long-Range Wireless Communication
*   **LPWAN (LoRaWAN, Sigfox, Neul):** Low Power Wide Area Networking.
*   **VSAT:** Very Small Aperture Terminal using dish antennas.
*   **Cellular:** High-quality data over long distances.
*   **MQTT:** Message Queuing Telemetry Transport.
*   **NB-IoT:** Narrowband IoT.

### Wired Communication
*   **Ethernet:** LAN wired connection.
*   **MoCA:** Multimedia over Coax Alliance.
*   **PLC:** Power-Line Communication using electrical wires.

*   **XMPP:** Real-time communication.
*   **Mihini/M3DA:** Communication between an M2M server and embedded gateway apps.

## 8. IoT Communication Models

*   **Device-to-Device Communication Model:** Devices interact through the Internet using protocols like ZigBee, Z-Wave, or Bluetooth.
*   **Device-to-Cloud Communication Model:** Devices communicate with the cloud directly (Wi-Fi, Ethernet, Cellular).
*   **Device-to-Gateway Communication Model:** IoT device communicates with an intermediate gateway (smartphone or hub), which connects to the cloud.
*   **Back-End Data-Sharing Communication Model:** Extends device-to-cloud; data can be accessed by authorized third parties.

## 11. IoT Security Problems

*   **Application:** Validation of the inputted string, AuthN, AuthZ, no automatic security updates, default passwords.
*   **Network:** Firewall, improper communications encryption, services, lack of automatic updates.
*   **Mobile:** Insecure API, lack of communication channels encryption, authentication, lack of storage security.
*   **Cloud:** Improper authentication, no encryption for storage and communications, insecure web interface.

## 12. OWASP Top 10 IoT Threats and Vulnerabilities

### OWASP Top 10 IoT Threats:
1.  **Weak, Guessable, or Hardcoded Passwords:** Using weak, guessable, or hardcoded passwords allows publicly available or unchangeable credentials to be determined via brute forcing. This includes backdoors in firmware or client software.
2.  **Insecure Network Services:** Insecure network services are prone to attacks like buffer overflow, leading to denial-of-service or unauthorized access. Attackers use port scanners and fuzzers to detect open ports.
3.  **Insecure Ecosystem Interfaces:** Interfaces such as web, backend API, mobile, and cloud interfaces outside the device lack authentication/authorization, encryption, or input/output filtering.
4.  **Lack of Secure Update Mechanisms:** Lack of firmware validation, secure delivery, anti-rollback mechanisms, or notifications of security changes.
5.  **Use of Insecure or Outdated Components:** Use of outdated software components or libraries from a compromised supply chain.
6.  **Insufficient Privacy Protection:** Insufficient protection of users' personal information stored on the devices or ecosystem.
7.  **Insecure Data Transfer and Storage:** Lack of encryption and access control for data in transit or at rest.
8.  **Lack of Device Management:** Lack of security support on devices deployed in production (e.g., asset management, update management, secure decommissioning).
9.  **Insecure Default Settings:** Devices come with insecure settings that restrict operators from making them more secure.
10. **Lack of Physical Hardening:** Lack of physical hardening measures allows attackers to acquire sensitive information for remote attacks or local control.

### OWASP IoT Attack Surface Areas:
The attack surfaces are the points where an attacker can try to enter data to or extract data from an environment. Key areas include:
*   **Ecosystem (General):** Interoperability standards, data governance, system-wide failures.
*   **Device Memory:** Cleartext usernames/passwords, encryption keys.
*   **Device Physical Interfaces:** Firmware extraction, privilege escalation, debug ports (UART, JTAG/SWD).
*   **Device Web Interface / Administrative Interface / Cloud Web Interface:** Vulnerable to OWASP Web Top 10 (SQLi, XSS), credential management issues (weak passwords, account lockout).
*   **Device Firmware:** Hardcoded credentials, sensitive data exposure, firmware downgrade.
*   **Device Network Services:** Unencrypted services, buffer overflows, vulnerable UDP services, replay attacks.
*   **Local Data Storage:** Unencrypted data, lack of data integrity checks.
*   **Update Mechanism:** Updates sent without encryption, unsigned updates, malicious updates.

### Key IoT Vulnerabilities:

| Vulnerability | Description |
| :--- | :--- |
| **Username Enumeration** | Ability to collect valid usernames by interacting with the authentication mechanism. |
| **Weak Passwords** | Ability to set weak passwords (e.g., "1234") or use pre-programmed default passwords. |
| **Account Lockout** | Ability to continue sending authentication attempts after 3-5 failed logins. |
| **Unencrypted Services** | Network services are not properly encrypted to prevent eavesdropping. |
| **Two-factor Authentication** | Lack of 2FA mechanisms like security tokens or fingerprint scanners. |
| **Poorly Implemented Encryption** | Encryption is used but improperly configured (e.g., using SSL v2). |
| **Firmware and Storage Extraction** | Attackers use JTAG/SWD, In-Situ Dumping, eMMC Tapping, or OTA interception to extract source code and binaries. |
| **Manipulating Code Execution** | Using JTAG/SWD or Side-Channel Attacks (Glitching) to modify firmware execution and bypass security controls. |
| **Obtaining Console Access** | Connecting to serial interfaces (SPI/UART) to gain full console access. |
| **Insecure Third-Party Components** | Out-of-date versions of BusyBox, OpenSSL, SSH, web servers. |

## 13. IoT Threats & Attacks

*   **DDoS Attack:** An attacker converts vulnerable devices into a botnet army to bombard a specific server, causing denial of service. **Steps:** Gain remote access -> Inject malware -> Use C&C center to instruct botnets -> Target server goes offline.
*   **Exploit HVAC:** Attackers exploit heating, ventilation, and air conditioning systems. **Steps:** Search Shodan for vulnerable ICS -> Search defpass.com for default credentials -> Access the ICS -> Gain remote access to the corporate network via the HVAC system.
*   **Rolling Code Attack:** Attackers jam and sniff the RF signal used by modern key fobs to lock/unlock vehicles or garages. **Tools:** HackRF One, RFCrack.
*   **BlueBorne Attack:** Exploits Bluetooth protocol vulnerabilities to gain access to devices without pairing or user interaction. Can lead to remote code execution and MITM attacks.
*   **Jamming Attack:** Attackers transmit radio signals randomly at the target device's communicating frequency to withhold transmissions (creates noise), causing a DoS.
*   **Hacking Smart Grid/Industrial Devices:** Attackers use spear-phishing to install a backdoor, gaining access to the SCADA network. They can replace legitimate firmware with malicious firmware to disable power supplies.
*   **SDR-Based Attacks:**
    *   **Replay Attack:** Capturing the command sequence from connected devices and using it for later retransmission (e.g., using URH).
    *   **Cryptanalysis Attack:** Reverse-engineering the protocol to obtain the original signal.
    *   **Reconnaissance Attack:** Using multimeters to investigate chipsets and discover product IDs.
*   **Identifying/Accessing Local IoT Devices:** Attackers use **DNS Rebinding** (via tools like Singularity of Origin) to gain access to a victim's router using malicious JavaScript.
*   **Fault Injection (Perturbation) Attacks:**
    *   **Optical/Electromagnetic Fault Injection (EMFI) / Body Bias Injection (BBI):** Projecting lasers or electromagnetic pulses to inject faults.
    *   **Power/Clock/Reset Glitching:** Injecting faults into the power supply or clock network to skip key instructions.
    *   **Frequency/Voltage Tampering / Temperature Attacks:** Altering operating conditions to introduce fault behavior.
*   **Other IoT Attacks:**
    *   **Sybil Attack:** Creating a strong illusion of traffic congestion using multiple forged identities (common in VANETs).
    *   **Exploit Kits:** Malicious scripts targeting poorly patched vulnerabilities.
    *   **Man-in-the-Middle Attack:** Intercepting communication between a sender and receiver.
    *   **Side-Channel Attack:** Extracting encryption keys by observing power consumption or electromagnetic emanations (e.g., Timing Analysis, Power Analysis).
    *   **Ransomware Attack:** Encrypting files or locking screens for a ransom.

### IoT Attacks in Different Sectors
*   **Buildings:** Access Control, MITM, DoS, Eavesdropping, Control Hijacking, Reverse Engineering, Rube Goldberg Attack (chained exploit).
*   **Energy / Industrial:** Access Control, Reconnaissance, DoS, Spear Phishing, Bluebugging.
*   **Consumer and Home:** DoS, MITM, Skill Squatting Attack (exploiting voice commands in Alexa/Google Home), Formjacking Attack.
*   **Healthcare and Life Science:** Signal-Jamming, Sinkhole Attack, Sybil Attack, Bluesnarfing, ZED (ZigBee End-Device) Sabotage Attack.
*   **Transportation:** Impersonation, Sybil, GPS Spoofing, Wormhole Attack, Black Hole Attack.

## 14. IoT Malware

*   **KmsdBot:** Targets IoT devices (Kmsdx variant includes Telnet/SSH scanning using default credential lists).
*   **IZ1H9 (Mirai-based):** Spreads via HTTP, SSH, Telnet. Uses XOR decryption for config strings and shell scripts (e.g., tenda.sh, netlog.sh) to establish persistent C2 connections.
*   **Other Malware:** WailingCrab, P2PInfect, NKAbuse, IoTroop, XorDdos.
