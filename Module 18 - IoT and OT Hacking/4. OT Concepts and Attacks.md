## 1. What is OT?

Operational Technology (OT) is a combination of software and hardware designed to detect or cause changes in industrial operations through direct monitoring and/or controlling of industrial physical devices. It includes Industrial Control Systems (ICSs) such as SCADA, RTU, PLC, and DCS.

### Essential Terminology:
*   **Assets:** Physical (sensors, servers, PLCs) and logical (firmware, firewall rules) components.
*   **Zones and Conduits:** Network segregation technique for isolation and access control.
*   **Industrial Protocols:** Proprietary (S7, CDA, SRTP) and non-proprietary (Modbus, OPC, DNP3, CIP).

---

## 2. Components of an ICS

*   **Distributed Control System (DCS):** Controls production systems spread within the same geographical location (chemical/nuclear plants). Uses centralized supervisory control loops (SCADA/MTU) and offers high redundancy and adaptability.
*   **Supervisory Control and Data Acquisition (SCADA):** Centralized system for controlling/monitoring wide geographical areas (pipelines, power grids). Integrates data acquisition, transmission, and HMI. Includes Control Server (SCADA-MTU), PLCs, RTUs, and IEDs.
*   **Programmable Logic Controller (PLC):** Solid-state control computer for logic, timing, and counting. Consists of CPU Module, Power Supply Module, and I/O Modules (Digital, Analog, Communication).
*   **Basic Process Control System (BPCS):** Responds to input signals to generate outputs based on a design control strategy (temperature, batch, pressure loops). First layer of protection.
*   **Safety Instrumented Systems (SIS):** Automated control system to safeguard against hazardous incidents. Shuts down systems to a safe state. Consists of field sensors, logic solvers, and final control elements.

## 3. IT/OT Convergence (IIOT)

Integration of IT computing systems and OT operation monitoring systems to improve business efficiency. Also referred to as Industry 4.0 or Industrial Internet of Things (IIoT).
**Benefits:** Enhancing automation, expediting output, minimizing expenses, mitigating risks, predictive maintenance, better quality control, simplified compliance.

---

## 4. The Purdue Model

Derived from the Purdue Enterprise Reference Architecture (PERA), it defines internal connections in ICS networks.
*   **Enterprise Zone (IT Systems):**
    *   **Level 5 (Enterprise Network):** B2B and B2C services, Internet connectivity.
    *   **Level 4 (Business Logistics Systems):** Scheduling, planning, DB servers, email.
*   **Industrial Demilitarized Zone (IDMZ):** Level 3.5 - Barrier between IT and OT.
*   **Manufacturing Zone (OT Systems):**
    *   **Level 3 (Operations Systems/Site Operations):** Production management, MES/MOMS, data historians.
    *   **Level 2 (Control Systems/Area Supervisory Controls):** DCS, SCADA software, HMIs.
    *   **Level 1 (Basic Controls/Intelligent Devices):** IEDs, PLCs, RTUs, PIDs, VFDs.
    *   **Level 0 (Physical Process):** Sensors, actuators, equipment under control (EUC).

## 5. OT Technologies and Protocols

*   **Level 4, 5:** DCOM, FTP/SFTP, GE-SRTP, IPv4/IPv6, OPC UA, TCP/IP, SMTP, HTTP/HTTPS, Wi-Fi.
*   **Level 3:** CC-Link, HSCP, ICCP (IEC 60870-6), IEC 61850, IEC 60870-5-104, ISA/IEC 62443, Modbus, NTP, Profinet, SuiteLink, Tase-2, ControlNet, Profibus PA/DP.
*   **Level 2:** 6LoWPAN, DNP3, DNS/DNSSEC, FTE, HART-IP, SOAP, DeviceNet, AS-Interface (AS-i).
*   **Level 0, 1:** BACnet, EtherCAT, CANopen, Crimson, Zigbee, ISA SP100, MELSEC-Q, Niagara Fox, Omron Fins, PCWorx, Sercos II, S7 Communication.

## 6. Challenges of OT

Lack of visibility, plain-text passwords, network complexity, legacy technology, lack of antivirus protection, lack of skilled professionals, outdated firmware, haphazard modernization, insecure Wi-Fi, convergence with IT, vulnerable protocols, poor segmentation.

---

## 7. OT Vulnerabilities

| Vulnerability | Description |
| :--- | :--- |
| **1. Publicly Accessible OT Systems** | OT systems are directly connected to the Internet so third-party vendors can perform remote maintenance. They are not protected using modern controls, allowing password brute-forcing or probing to disable functions. |
| **2. Insecure Remote Connections** | Corporate networks use jump boxes to establish remote connectivity with the OT network. Attackers can exploit vulnerabilities in jump boxes to gain remote access to the OT systems. |
| **3. Missing Security Updates** | Outdated software versions lead to increased risks and pave the way for attackers to compromise the OT systems. |
| **4. Weak Passwords** | Operators and administrators use default usernames and passwords for OT systems, which are easily guessable. |
| **5. Insecure Firewall Configuration** | Misconfigured access rules allow unnecessary access between corporate IT and OT networks. Support teams may allow excessive access permissions on firewalls. |
| **6. OT Systems Placed within Corporate IT** | Corporate systems are interconnected with the OT network for accessing operational data. OT systems (like control stations) placed within the IT network allow attackers to use compromised IT systems to gain access to the OT network. |
| **7. Insufficient Security for IT from OT** | Attacks also originate from OT systems, as they use outdated legacy software and are accessed from remote locations. |
| **8. Lack of Segmentation within OT** | Several OT networks have a flat and unsegmented configuration. Compromise of a single device may expose the entire OT network. |
| **9. Lack of Wireless Encryption/Auth** | Wireless equipment in OT networks uses insecure and outdated security protocols, allowing sniffing and authentication bypass attacks. |
| **10. Unrestricted Outbound Internet Access** | Direct outbound Internet connectivity to insecure and unpatched OT devices increases the risk of malware attacks and command-and-control communication. |

## 8. MITRE ATT&CK for ICS

*   **Initial Access:** Techniques to establish initial access within the targeted ICS environment. Includes: Drive-by compromise, Exploiting public-facing software applications, Exploiting remote services, Replication through removable media, Rogue master, Spear-phishing attachment, Supply-chain compromise, Transient cyber assets, Wireless compromise.
*   **Execution:** Executing malicious code or manipulating data. Includes: Changing the operating mode, Command-line interface (CLI), Execution through APIs, Graphical user interface (GUI), Hooking, Modify controller tasking, Native API, Scripting, User execution.
*   **Persistence:** Retaining access even if the device is restarted. Includes: Modifying a program, Module firmware, Project file infection, System firmware, Valid accounts.
*   **Privilege Escalation:** Achieving higher-level access and authorizations. Includes: Exploiting software, Hooking.
*   **Evasion:** Evading conventional defense mechanisms. Includes: Removing the indicators, Rootkits, Changing the operator mode, Exploitation of software vulnerabilities, Masquerading, Spoofed reporting messages.
*   **Discovery:** Gaining information about an ICS environment to assess and identify target assets. Includes: Enumerating the network connection, Network sniffing, Identifying remote systems.
*   **Lateral Movement:** Making additional movements across the target environment. Includes: Default credentials, Program download, Remote services, Lateral tool transfer, Valid accounts.
*   **Collection:** Gathering information and gaining knowledge regarding data and domains. Includes: Automated collection, Information repositories, I/O image, Detecting the operating mode, Man-in-the-middle attack, Monitoring the process state, Point and tag identification, Program upload, Screen capture, Wireless sniffing.
*   **Command and Control:** Deactivating, controlling, or exploiting physical control processes. Includes: Frequently used ports, Connection proxy, Standard application-layer protocols (HTTPS, Telnet, RDP).
*   **Inhibit Response Function:** Thwarting reactions against security events (hazards or failures). Includes: Activate firmware update mode, Block command messages, Block reporting messages, Alarm suppression, Blocking serial COM, Data destruction, DoS, Device restart/shutdown, Control I/O image, Rootkit, Service stop.
*   **Impair Process Control:** Disabling, exploiting, or controlling physical control processes. Includes: I/O brute-forcing, Altering parameters, Module firmware, Spoofed reporting messages, Unauthorized command messages.
*   **Impact:** Damaging, disrupting, or gaining control of data and systems. Includes: Damage to property, Loss of availability, Denial of control, Denial of view, Loss of productivity and revenue, Loss of protection/safety, Manipulation of control/view, Theft of operational information.

## 9. OT Threats

*   **Maintenance and Administrative Threat:** Exploiting zero-days to inject malware into SCADA/PLC.
*   **Data Leakage:** Stealing configuration files.
*   **Protocol Abuse:** Abusing E-stop mechanisms for single-packet attacks.
*   **HMI-Based Attacks:** Memory corruption (buffer overflow), Credential management issues, Code Injection (Gamma language EvalExpression), Path Traversal.
*   **Side-Channel Attacks:** Timing Analysis, Power Analysis (using oscilloscopes).
*   **Hacking PLCs:** PLC Rootkit Attack (ghost attack via I/O initialization manipulation), Evil PLC Attack (modifying logic via download procedures).
*   **RF Remote Controllers:** Replay attacks, Command Injection, Abusing E-stop, Malicious Re-pairing, Malicious Reprogramming.
*   **OT Supply Chain Attacks:** Third-Party Software Compromise, Hardware Manipulation, Service Provider Breach.
*   **OT Malware:** Fuxnet (rewrites NAND chip, exploits gateways), COSMICENERGY (targets IEC-104 devices, uses PIEHOP and LIGHTWORK to actuate power-line switches), Kapeka, INDUSTROYER.V2.
