## 1. How to Defend Against IoT Hacking

*   Disable "guest" and "demo" accounts. Use "Lock Out" features.
*   Implement strong authentication, IPS/IDS, end-to-end encryption, PKI, and VPNs.
*   Isolate control networks behind firewalls; use Protected Networks.
*   Allow only trusted IPs, disable Telnet (port 23), disable UPnP.
*   Implement secure boot (code signing, OEM verification).
*   Use two-way authentication (SHA with HMAC, ECDSA).
*   Implement active masking or shielding (protects against side-channel attacks).
*   Secure keys in SAM, TPM, or HSM.
*   Filter private IPs from DNS replies to prevent DNS rebinding.

### Prevent SDR-Based Attacks:
*   Secure the signal using standard encryption.
*   Avoid Command Repetition using a Rolling Technique.
*   Adopt Synchronization and Preamble Nibbles.
*   Use Anti-jamming Techniques & Frequency Hopping (FHSS).
*   Secure Key Management (HSMs) & Secure OTA Updates.

## 2. IoT Security Problems & Solutions

Based on the OWASP Top 10 IoT Vulnerabilities:

| Vulnerability | Solutions |
| :--- | :--- |
| **1. Weak/Hardcoded Passwords** | Use APM, strong passwords, avoid hardcoded ones. |
| **2. Insecure Network Services** | Close open ports, disable UPnP, encrypt data (TLS). |
| **3. Insecure Ecosystem Interfaces** | Account lockout, periodic assessments, sanity checking. |
| **4. Lack of Secure Update Mechanism** | Verify source/integrity, encrypt communication, notify users. |
| **5. Insecure/Outdated Components** | Monitor components, remove unused dependencies. |
| **6. Insufficient Privacy Protection** | Minimize and anonymize collected data. |
| **7. Insecure Data Transfer/Storage** | Encrypt endpoints, maintain SSL/TLS. |
| **8. Lack of Device Management** | Blacklist malicious devices, secure decommissioning. |
| **9. Insecure Default Settings** | Change default credentials, custom modify privacy settings. |
| **10. Lack of Physical Hardening** | BIOS/firmware passwords, configure boot order, minimize USB ports. |

## 3. IoT Framework Security Considerations

*   **Edge:** Provide cross-platform components for physical conditions, ensure communications/storage encryption.
*   **Gateway:** Aggregate communications securely, strong encryption, multi-directional authentication.
*   **Cloud Platform:** Encrypted communications, strong authentication, secure web interface.
*   **Mobile:** Authentication mechanisms, account lockout, local storage security.

## 4. IoT Hardware Security Best Practices

Securing IoT hardware prevents attacks at the seed level. Countermeasures include:
*   **Limit the Entry Points:** Avoid deploying additional entry points (like USB ports) and lock least-used ports.
*   **Employ Hardware Tamper Protection:** Detect direct physical damage or intrusion (device lifting, lid removal, chip-level access) and install GPS to track misplaced units.
*   **Monitor Secure Booting:** Prevent boot-level glitching attacks and implement secure data storage using TPM (Trusted Platform Module) chips.
*   **Implement Security Patches:** Update firmware securely and timely.
*   **Maintain a Proper Interface Management System:** Integrate hardware with secure interfaces to avoid API and library snatching.
*   **Avoid Open Access to the Hardware Unit:** Implement proper physical protection and use dummies for open ports in harsh environments.
*   **Secure Authentication Keys:** Secure unique device IDs crafted by the cloud service.
*   **Maintain a Proper Event Logging Mechanism:** Conduct timely security audits.
*   **Maintain a Proper Anti-Malware Protection System:** Install trusted third-party antivirus at entry points.
*   **Enable a Default Entry-Level Logging Mechanism:** Monitor entry logs provided by OSes.
*   **Protect Device Access Credentials:** Use magic-number implementation, encryption, and 2FA.
*   **Isolate Devices from Regular Supply Units:** Secure devices from electrification/spike attacks (e.g., rowhammer attacks).
*   **Implement a Root-on-Trust Mechanism:** Ensure only trusted/authorized users gain root-level access.
*   **Secure Legacy Units / Wireless Communication / Debug Interfaces:** Disable unsecured debug ports (JTAG/UART) and harden wireless interfaces.
*   **Hardware-based Root of Trust:** Use Trusted Execution Environments (TEEs) or secure enclaves.

**TPM and Cryptographic Countermeasures:**
*   Use third-party authentication (like BitLocker) for external data.
*   Employ TPM tools (like Nuvoton) using I2C/SPI interfaces.
*   Bind data using a TPM bind key (RSA encryption standard).
*   Implement sealing/unsealing for major computational updates (firmware/patches).
*   Employ HMAC-key-based and symmetric-key-based (for low-data-transmission) secure communication.
*   Store keys in non-volatile random-access memory (NVRAM) within TPMs.
*   Enable perfect forward secrecy and use Authenticated Encryption with Associated Data (AEAD) algorithms (AES-GCM, AES-CCM).
*   Implement key rotation policies periodically.

## 5. Secure Development Practices for IoT Applications

*   **Ensure Secure Boot:** Devices only execute authenticated and validated code at boot time.
*   **Secure API Endpoints:** Protect APIs with authentication and data validation to prevent SQL injection, XSS, and CSRF.
*   **Implement Threat Modeling:** Identify potential security threats specific to the IoT ecosystem.
*   **Secure Coding Practices:** Adhere to standards to prevent buffer overflows, injection attacks, and XSS.
*   **Conduct Security Testing:** Include penetration testing, vulnerability scanning, and code reviews throughout the lifecycle.
*   **Secure Firmware or Software Updates:** Implement secure over-the-air (OTA) update mechanisms to deliver patches securely.
*   **Ensure Device Identity Management:** Implement unique identifiers and digital certificates.
*   **Implement Hardware Security:** Utilize TPMs or HSMs to securely store cryptographic keys.
*   **Allow Code Signing:** Digitally sign firmware updates and applications to verify authenticity.
*   **Implement Runtime Protection:** Employ code execution monitoring and stack overflow protection.
*   **Ensure Secure Cloud Integration & Secure Communication Protocols:** Use MQTT with TLS/SSL for device-to-cloud communication.
