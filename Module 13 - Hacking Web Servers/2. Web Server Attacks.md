## 1. DNS Attacks

### DNS Server Hijacking
An attacker compromises a DNS server and changes its mapping settings to redirect a legitimate URL to a rogue DNS server. The user’s request is redirected to the attacker's fake site instead of the legitimate website.

### DNS Amplification Attack
A DDoS attack exploiting **recursive DNS queries**.
1. Attacker instructs compromised hosts (bots) to send DNS queries.
2. Bots spoof the victim’s IP address and send requests to the primary DNS server.
3. If the mapping doesn't exist, the primary DNS forwards the request to the root server recursively (checking `.com` and TLD namespaces).
4. The primary DNS generates a cache for the IP address.
5. The primary DNS server sends the mapping response to the victim's IP address.
6. Copious DNS mapping responses from the bots flood the victim's DNS server, causing a DoS.

## 2. Routing & File Access Attacks

### Directory Traversal Attacks
Exploitation of HTTP where attackers access restricted directories and execute commands outside the web server's root directory by manipulating the URL.
* Uses the dot-dot-slash **(`../`)** sequence.
* **Example Payload:** 
  `http://server.com/scripts/..%5c../Windows/System32/cmd.exe?/c+dir+c:\`

### Website Defacement
Unauthorized changes made to the visual appearance of a website (injecting code, adding images, popups, or replacing the entire page).
* Often performed via MySQL injection.
* Used to spread propaganda or infect visitors with viruses.

## 3. Web Server Misconfigurations

Improperly configured web servers leave loopholes that attackers can exploit.

### Examples of Web Server Misconfigurations:
* **Verbose Error Messages:** `php.ini` configured with `display_error = On` and `log_errors = On`.
* **Server Status Page Exposed:** `httpd.conf` allows anyone to view `<Location "/server-status">`.
* **Directory Browsing Enabled:** `web.config` configured with `<directoryBrowse enabled="true"/>`.
* **Unrestricted File Uploads (IIS):** Server allows large, unvalidated uploads leading to RCE (web shells).
  `<requestLimits maxAllowedContentLength="30000000" />`
* **Missing Root Location Block (Nginx):** A configuration with `location / {}` but no root defined, potentially exposing directory listings.
* **Unsanitized Variables (Nginx):** Direct use of user input in variables, e.g., `proxy_pass http://backend/$variable;`

## 4. HTTP Protocol Attacks

### HTTP Response-Splitting Attack
A web-based attack where the attacker tricks the server by injecting new lines (Carriage Returns/Line Feeds - **CRLF**) along with arbitrary code into the HTTP response header.
* The server splits the response into two. The first response is sent to the attacker, and the **attacker-controlled second response** is sent to the victim.
* Can be leveraged to perform XSS, CSRF, and SQL injection.

### Web Cache Poisoning Attack
An attacker swaps cached content for a random URL with infected content. 
* The attacker forces the web server's cache to flush its actual content, then sends a specially crafted request to store malicious content.
* Users requesting the URL receive the poisoned cache. Often relies on HTTP response-splitting flaws.

### HTTP/2 Continuation Flood Attack
Exploits the handling mechanism of HTTP/2 `CONTINUATION` frames to exhaust the target Apache server's memory and CPU (DoS).
1. Attacker establishes a TCP connection.
2. Attacker sends a legitimate `HEADERS` frame but **does not** set the `END_HEADERS` flag.
3. Attacker sends continuous `CONTINUATION` frames, each indicating that additional header data is forthcoming.
4. The server allocates additional memory for each frame, anticipating the end, until it crashes.

## 5. Brute-Force & Password Cracking Attacks

### SSH Brute Force Attack
Attackers perform port scans on **TCP port 22** using bots, then perform brute-force attacks to obtain login credentials.
* **Tools:** `Nmap`, `Ncrack` (Linux).

### FTP Brute Force with AI
Attackers use AI (like ChatGPT) to effortlessly generate precise tool commands for cracking FTP.
* **Prompt:** *"Attempt FTP login on target IP 10.10.1.11 with hydra using usernames and passwords from wordlists"*
* **Generated Command:** 
  `hydra -L /usr/share/wordlists/ftp-usernames.txt -P /usr/share/wordlists/ftp-passwords.txt ftp://10.10.1.11`

### Web Server Password Cracking Techniques
* **Guessing:** Using predictable passwords (pets, dates, "QWERTY").
* **Dictionary Attack:** Using a predefined file of words. Faster than brute-force.
* **Brute-force Attack:** Testing all possible character combinations (A-Z, 0-9, special chars).
* **Hybrid Attack:** Combines dictionary words with numbers/symbols.
* **Tools:** `Hashcat`, `THC Hydra`, `Ncrack`, `Rainbow crack` ([project-rainbowcrack.com](https://project-rainbowcrack.com)), `Wfuzz`, `Wireshark`.

### Tool Highlight: THC Hydra
**Source:** [https://github.com](https://github.com)
A parallelized login cracker supporting numerous protocols:
* *AFP, Cisco (AAA, auth, enable), CVS, Firebird, FTP, HTTP(S)-FORM-GET, HTTP(S)-FORM-POST, HTTP(S)-GET, HTTP(S)-HEAD, ICQ, IMAP, IRC, LDAP, Memcached, MongoDB, MS SQL, MySQL, NCP, NNTP, Oracle, POP3, RDP, SMB, SMTP, SNMP, SOCKS5, SSH, TeamSpeak, Telnet, VNC, XMPP.*

## 6. Advanced Web Server Attacks

### Frontjacking Attack
Injects or manipulates front-end components (scripts/HTML) to hijack user interfaces. Targets poorly configured **Nginx reverse proxy servers** by combining CRLF injection, HTTP header injection, and XSS.
1. Exploits improper sanitization of `$uri` and `$document_uri`.
2. Attacker injects a malicious host header via CRLF.
3. The reverse proxy routes the request to an attacker-controlled server instead of the legitimate backend.

### Using Application Server as a Proxy
Exploiting a web server configured for HTTP proxy forwarding.
* Attackers use `GET` and `CONNECT` requests to connect to third-party systems on the internet or arbitrary hosts on the internal network.

### Path Traversal via Misconfigured NGINX Alias
Exploits improper usage of the `alias` directive **without a trailing slash**.
* **Misconfiguration:** 
  ```nginx
  location /i { 
      alias /data/w3/images/; 
  }
  ```
* Appending `../` allows attackers to traverse to restricted areas.
* **Tool:** `Kyubi` ([https://github.com](https://github.com)) - Python-based tool to exploit Nginx alias path-traversals.
  * *Command:* `kyubi -v <target_URL>`

## 8. Overview of Web Application Attacks

Even with secure web servers, poorly coded web applications expose the server to compromise. Types include:
* **Server-Side Request Forgery (SSRF):** Forcing the server to send crafted requests to internal/backend servers.
* **Parameter/Form Tampering:** Modifying application data (credentials, prices) exchanged between client and server.
* **Cookie Tampering:** Modifying persistent/non-persistent cookies.
* **Unvalidated Input / File Injection:** Supplying unvalidated input or injecting malicious files.
* **Session Hijacking:** Stealing/predicting valid session control mechanisms.
* **SQL Injection:** Injecting malicious SQL queries to exploit the database.
* **Directory Traversal:** Accessing restricted directories.
* **DoS/DDoS:** Flooding targets with fake requests (bandwidth, memory, CPU, disk space).
* **Cross-Site Scripting (XSS):** Injecting HTML/scripts into a target website.
* **Buffer Overflow:** Flooding the application with excess data until it crashes.
* **Cross-Site Request Forgery (CSRF):** Exploiting an authenticated user's trust to pass malicious commands.
* **Command Injection:** Altering web page content via HTML code on unconstrained form fields.
* **Source Code Disclosure:** Failure to restrict script read permissions, exposing passwords and secret keys.
