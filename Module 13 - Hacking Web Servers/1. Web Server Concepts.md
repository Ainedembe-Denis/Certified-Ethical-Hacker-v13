## 1. Web Server Operations & Components
A web server is a computer system that stores, processes, and delivers web pages to clients via the Hypertext Transfer Protocol (HTTP). When a client initiates an HTTP request, the web server collects the content from data storage or application servers and returns an HTTP response.

### Components of a Web Server:
1. **Document Root:** 
   The root file directory storing critical HTML files. 
   *(Example: URL `www.certifiedhacker.com/P-folio/index.html` where `certroot` is the root, maps to `/admin/web/certroot/P-folio/index.html`)*.
2. **Server Root:** 
   The top-level directory storing server configuration files, log files, and executables. Contains sub-directories:
   * **`conf`:** Configuration files.
   * **`logs`:** Access and error logs.
   * **`cgi-bin`:** Common Gateway Interface (CGI) scripts and server-side executables.
3. **Virtual Document Tree:** 
   Storage provided on a different machine or disk when the original disk becomes full. It is case-sensitive and offers object-level security.
4. **Virtual Hosting:** 
   Hosting multiple domains on the same server. Types include:
   * Name-based hosting
   * IP-based hosting
   * Port-based hosting
5. **Web Proxy:** 
   A server located between the client and web server. Passes requests through web proxies to prevent IP blocking and maintain anonymity.

## 2. Web Server Security Issues

### Common Goals behind Web Server Hacking
* Stealing credit-card details or credentials via phishing.
* Integrating the server into a botnet to perform DoS/DDoS.
* Compromising databases or obtaining closed-source applications.
* Hiding and redirecting traffic.
* Escalating privileges.
* Personal reasons (curiosity, self-set intellectual challenge).

### Dangerous Security Flaws (Oversights)
* Failing to update patches.
* Using the same administrator credentials everywhere.
* Allowing unrestricted internal/outbound traffic.
* Running unhardened applications/servers.
* Providing complete error messages with server version information.
* Using outdated SSL/TLS encryption algorithms.
* Using vulnerable third-party plugins.

### Impact of Web Server Attacks
* **Compromise of user accounts:** Attackers gain useful info for further attacks.
* **Website defacement:** Changing the visual appearance/displaying messages.
* **Secondary attacks:** Using the compromised server to launch attacks on client systems.
* **Root access:** Gaining the highest privilege level to perform any action.
* **Data tampering:** Altering/deleting data or replacing it with malware.
* **Data theft:** Stealing financial records, future plans, or source code.
* **Reputation damage:** Destroying customer faith.

### Why are Web Servers Compromised?
* **Webmaster’s perspective:** Exposed corporate intranet, bugs in CGI scripts, and the open architecture of web servers.
* **Network administrator’s perspective:** Poorly configured servers, improper file permissions, default accounts/passwords.
* **End user’s perspective:** Browsing seems safe, but advanced active content (JavaScript, WebAssembly) allows malicious code execution.

## 3. Apache Web Server Architecture
Apache is a highly robust, flexible open-source HTTP server that handles HTTP requests and serves static/dynamic content. 

### Core Components:
* **HTTP Client:** Browser or software initiating requests.
* **HTTP Server (Core):** Interfaces with core modules for additional functionality:
  * **`mod_auth`:** Manages user authentication.
  * **`mod_ssl`:** Provides SSL/TLS encryption.
  * **`mod_rewrite`:** Enables URL rewriting and customized redirection.
  * **`mod_proxy`:** Functions as a proxy/gateway for forwarding requests and load balancing.
* **BMMTM Extensible Agent:** Intercepts HTTP(S) requests and responses to gather detailed transaction data for monitoring and performance analysis.
* **Application Server:** Executes backend applications (PHP, Java, Python), processes data, and generates dynamic content.

### 3.1 Apache Vulnerabilities

| Vulnerability | Description |
| :--- | :--- |
| **HTTP response splitting** | Improperly validated input allows malicious header injection, leading to XSS, cache-poisoning, or sensitive info disclosure. |
| **HTTP/2 DoS (memory exhaustion)** | Sending endless continuation frames leads to excessive memory consumption and server crashing (DoS). |
| **mod_macro buffer over-read** | The module improperly handles macro expansion, reading beyond the buffer's end and revealing sensitive info from adjacent memory. |
| **DoS in HTTP/2 (window size 0)** | Setting initial window size to 0 blocks server data, causing the server to wait indefinitely for updates. |
| **HTTP/2 stream memory on RST** | Memory allocated for HTTP/2 stream is not freed upon receiving an RST frame. Streams created and reset lead to memory exhaustion. |
| **Insecure default configuration** | Insecure default admin credentials leading to Remote Code Execution (RCE). |
| **Improper authorization** | Faulty authorization checks in core components allowing unauthorized access or privilege escalation. |
| **DNS rebinding in import** | Inadequate input validation in the import functionality of **Apache Allura**. Allows manipulation of DNS responses. |
| **Environment variable injection** | Improper handling of variables like `ZEPPELIN_INTP_CLASSPATH_OVERRIDES` in **Apache Zeppelin** leading to arbitrary code execution. |
| **Code injection** | Arises when connecting to a MySQL database via the JDBC driver in **Apache Zeppelin**. |
| **Improper certificate validation** | Improper certificate validation in FTP_TLS connections of **Apache Airflow**, leading to MITM attacks. |
| **Cross-site scripting (XSS)** | Unfiltered use of `PATH_INFO` in `GeneralUtility::getIndpEnv()` of **TYPO3 CMS** framework. Allows HTML injection into task logs in **Apache Airflow**. |
| **Path-traversal vulnerability** | Improper path limitation in **Apache OFBiz** allows accessing restricted files using directory traversal. |
| **SQL injection** | Improper neutralization in SQL commands of **Apache Submarine Server Core**. |

## 4. IIS Web Server Architecture
Internet Information Services (IIS) is a Microsoft web server application supporting HTTP, HTTPS, FTP, FTPS, SMTP, and NNTP. Uses HTML for interfaces and compiled Visual Basic for processing. 

### IIS Components:
* **Protocol listeners:** (`HTTP.sys`)
* **World Wide Web Publishing Service:** (WWW service)
* **Windows Process Activation Service:** (WAS)

### How IIS Functions:
1. An HTTP request is sent and intercepted by **`HTTP.sys`**.
2. `HTTP.sys` communicates with **WAS** to collect data from **`ApplicationHost.config`** (the root config file).
3. WAS raises a request for configuration info (site, application pool) which is sent to the **WWW Service**.
4. The WWW Service uses the info to configure `HTTP.sys`.
5. WAS initiates a **worker process** for the application pool.
6. The worker process handles the request, and the response is returned to `HTTP.sys`, which sends it to the client.
*(IIS depends on DLLs working collectively with the main server process, `inetinfo.exe`).*

### 4.1 IIS Vulnerabilities

| Vulnerability | Description |
| :--- | :--- |
| **Trust boundary violation** | Inadequate separation of privilege boundaries in the **Telerik Report Server**, leading to unauthorized server manipulation. |
| **Authentication bypass** | Insecure endpoint allows unauthenticated access to restricted server functionality. |
| **CRLF cross-site scripting** | Misconfigurations in **SiteMinder Web Agent** for IIS allow arbitrary JavaScript execution (XSS). |
| **CCURE passwords exposed** | Improper handling/logging of sensitive info while hosting the **C•CURE 9000 Web Server**. Exposes Windows credentials via logs. |
| **Arbitrary file path access** | Default configuration of **Aquaforest TIFF Server** improperly restricts file paths, allowing enumeration/traversal. |
| **Windows IIS server elevation** | Improper handling of user requests allowing attackers to take control of the system. |
| **File/directory permissions** | Incorrect default permissions in **Hitachi JP1/Performance Management** software. |
| **MailEnable vulnerability** | Authenticated users can add unsanitized files into public folders leading to RCE. |
| **XSS in password manager** | Improper neutralization within the `/isapi/PasswordManager.dll` `ResultURL` parameter. |

## 5. Nginx Web Server Architecture
Nginx is a high-performance web server, reverse proxy, and load balancer. It operates on a **master-worker architecture** using a single-threaded, event-driven, asynchronous, and non-blocking model.

### Core Components:
* **Master Process:** Reads/validates configurations, creates/binds/closes sockets, and manages worker processes.
* **Worker Processes:** Accepts connections, reads/writes data, communicates with upstream servers. Handles >1000 connections simultaneously using non-blocking I/O.
* **Proxy Cache:** Reduces backend load by serving frequently accessed content.
  * **Cache Loader:** Loads metadata into memory at start-up.
  * **Cache Manager:** Periodically checks/removes expired entries.
* **Web Server:** Handles HTTP requests and serves static content.
* **Application Server:** Runs server-side scripts (PHP, Java, Python) and delivers dynamic content.
* **Memcache:** Caching layer storing data in memory for rapid retrieval.

### 5.1 Nginx Vulnerabilities

| Vulnerability | Description |
| :--- | :--- |
| **NULL pointer dereference (HTTP/3)** | Handling HTTP/3 requests in the QUIC module causes worker processes to terminate (DoS). |
| **SSRF vulnerability** | Arises in the upload link feature of **mintplex-labs/anything-llm**, enabling internal port scanning and arbitrary file inclusion. |
| **Remote code execution** | Exposed configuration settings in **Nginx-UI** leading to RCE and privilege escalation. |
| **Improper certificate validation** | Improper validation in the **Import Certificate** feature of Nginx-UI allows arbitrary file writes. |
| **SQL injection vulnerability** | Improper neutralization of special SQL elements allows unsanitized parameters. |
| **Unauthenticated private keys access** | Nginx does not support `.htaccess`, yet sometimes security relies on it. Attackers can read private keys in unprotected directories. |
| **Memory usage & CPU exhaustion** | Improper memory handling in HTTP/2. Flooding the server with HTTP/2 requests consumes resources (DoS). |
| **OS command injection** | Improper handling of file arguments in the upload feature of **nginxWebUI**. |
| **Default file permissions** | The **Nginx Management Suite** permits authenticated users to modify sensitive files (Nginx Instance/API Connectivity Manager). |
