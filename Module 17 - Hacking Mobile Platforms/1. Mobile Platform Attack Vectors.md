## 1. OWASP Top 10 Mobile Risks - 2024

Source: [https://owasp.org](https://owasp.org)

| Risk | Description |
| :--- | :--- |
| **M1 - Improper Credential Usage** | Insecure handling of credentials (passwords, tokens). Includes hardcoded credentials, unprotected storage, unencrypted transmission, and weak authentication methods. |
| **M2 - Inadequate Supply Chain Security** | Use of outdated or flawed third-party components and libraries. Includes insecure coding practices, insufficient testing, and weak app signing/distribution processes. Can introduce backdoors. |
| **M3 - Insecure Authentication/Authorization** | Misuse of auth mechanisms resulting from weak password policies, insecure token handling, or improper authorization checks. Attackers execute privileged functionality using low-privileged tokens. |
| **M4 - Insufficient Input/Output Validation** | Inadequate validation/sanitization leading to SQL injection, command injection, and XSS attacks. Causes unauthorized data access, code execution, and app crashes. |
| **M5 - Insecure Communication** | Use of insecure/deprecated protocols, improper configuration, or invalid SSL certificates allowing data interception. Leads to account takeover and PII leaks. |
| **M6 - Inadequate Privacy Controls** | Inadequate protection of PII (names, addresses, financial data). Results from poor data access control and noncompliance with privacy laws. |
| **M7 - Insufficient Binary Protections** | Lack of protection against code tampering and reverse engineering. Attackers bypass security, modify app code, or create counterfeit apps. |
| **M8 - Security Misconfiguration** | Incorrect/incomplete configurations including weak encryption, unprotected storage/permissions, enabled debugging features, and unchanged default credentials. |
| **M9 - Insecure Data Storage** | Storing sensitive data insecurely (plain text storage, unsecured databases, weak encryption). Exploited via physical or remote access to the file system. |
| **M10 - Insufficient Cryptography** | Use of weak/outdated encryption, poor key management, insecure hash functions, or flawed cryptographic protocol implementation. |

## 2. Anatomy of a Mobile Attack

Attackers target the device, network layer, data center, or a combination of these.

### 1. The Device
*   **Browser-based Attacks:** Phishing, Framing (using iFrame for clickjacking), Clickjacking, Man-in-the-Mobile (bypassing OTPs via malware), Buffer Overflow, Data Caching exploitation.
*   **Phone/SMS-based Attacks:** Baseband Attacks (exploiting GSM/3GPP baseband processors), SMiShing.
*   **Application-based Attacks:** Sensitive Data Storage exploitation, No/Weak Encryption, Improper SSL Validation, Configuration Manipulation, Dynamic Runtime Injection, Unintended Permissions, Escalated Privileges.
*   **OS-based / The System:** No/Weak Passcode, iOS Jailbreaking, Android Rooting, OS Data Caching, Carrier-loaded Software (bloatware vulnerabilities), User-initiated Code (tricking users to install malware).

### 2. The Network
*   **Wi-Fi:** Eavesdropping on weak or no encryption.
*   **Rogue Access Points:** Hijacking connections.
*   **Packet Sniffing:** Capturing credentials in clear text.
*   **Man-in-the-Middle (MITM) & SSLStrip:** Downgrading HTTPS to HTTP.
*   **Fake SSL Certificates & DNS Poisoning.**

### 3. The Data Center/CLOUD
*   **Web-server-based attacks:** Platform Vulnerabilities (OS, IIS), Server Misconfiguration, Cross-site Scripting (XSS), Cross-Site Request Forgery (CSRF), Weak Input Validation (Brute-Force).
*   **Database Attacks:** SQL injection, Privilege Escalation, Data Dumping, OS Command Execution.

## 3. Mobile Attack Vectors & Exploitation

Mobile devices are targeted because they access many traditional network resources but have unique attack vectors:
*   **Malware:** Virus and rootkit, Application modification, OS modification.
*   **Data Exfiltration:** Extracted from data streams and email, Print screen and screen scraping, Copy to USB key and loss of backup.
*   **Data Tampering:** Modification by another application, Undetected tamper attempts, Jailbroken device.
*   **Data Loss:** Application vulnerabilities, Unapproved physical access, Loss of device.

**What Hackers Exploit Post-Compromise:**
*   **Data Theft:** Account details, Personal health information, Contacts.
*   **Financial:** Making expensive calls, Extortion via ransomware.
*   **Botnet Activity:** Launching DDoS attacks, Cryptocurrency mining, Sending premium-rate SMS.
*   **Impersonation:** Posting to social media, Sending emails.

## 4. Security Issues Arising from App Stores & Sandboxing

### App Stores
Attackers download legitimate apps, repackage them with malware, and upload them to third-party app stores (e.g., Amazon Appstore, GetJar, APKMirror). These malicious apps steal sensitive data (call logs, photos) without user knowledge.

### App Sandboxing Issues
Sandboxing protects systems by isolating apps and limiting resources an app can access. 
*   **Secure Sandbox:** Restricts access to other users' data and system resources.
*   **Vulnerable Sandbox:** Malicious apps exploit vulnerabilities to bypass the sandbox perimeter and tamper with other apps or access restricted data.

## 5. Mobile Spam & SMS Phishing (SMiShing)

### Mobile Spam
Unsolicited messages sent in bulk (SMS, MMS, IM, email). Contains malicious links or premium-rate scams.

### SMiShing (Targeted Attack Scan)
An attacker sends bogus SMS messages with deceptive links or phone numbers to steal PII or financial info.
*   **Process:** Attacker buys prepaid SIM -> Sends SMS bait (lottery, urgency) -> User clicks link -> Redirected to phishing site -> User inputs PII.
*   **Why it's effective:** High open rates, high trust in SMS, limited space forces concise messages making it hard to spot tells, lack of anti-phishing features compared to email.
*   **Tools:** **AdvPhishing** (https://github.com/Ignitetch/AdvPhishing) - bypasses 2FA/OTP using NGrok tunneling. **mrphish** (https://github.com/noob-hackers/mrphish).

## 6. Open Bluetooth & Wi-Fi Connections Attacks

*   **Bluesnarfing:** Theft of information via Bluetooth. Attackers access the victim's contacts, emails, and photos on devices set to "discoverable".
*   **Bluebugging:** Gaining remote access and taking over a device via Bluetooth. Attackers perform a backdoor attack, sniff data, intercept calls/texts, and forward calls without user consent.

## 7. Specialized Network & Telecom Attacks

### Agent Smith Attack
Victims are lured into downloading malicious apps from third-party stores (like 9Apps). The core malicious code replaces legitimate apps (WhatsApp, SHAREit) with infected versions or acts as a Google product (Google Updater). It floods the device with ads and steals critical information via C&C commands.

### Exploiting SS7 Vulnerability
Signaling System 7 (SS7) allows mobile users to exchange communication across cellular networks (roaming). It operates on mutual trust between operators with weak authentication. 
*   **Impact:** Attackers perform MITM to impede texts/calls, bypassing 2FA/OTP end-to-end encryption.
*   **Risks:** Phone tapping, tracking geographic locations, exposing subscriber identity, DoS on telecom operators.

### Simjacker: SIM Card Attack
Exploits a vulnerability in the **S@T browser** (SIMalliance Toolbox Browser) pre-installed on SIM cards.
*   **Process:** Attacker sends spyware-like code via SMS -> S@T browser processes hidden instructions -> Injected code controls the SIM without user interaction.
*   **Impact:** Capturing location, monitoring calls, making fraudulent calls.

### Call Spoofing
Manipulating caller ID to disguise the attacker's number as a trusted source (bank, government).
*   **Tools:** SpoofCard (https://www.spoofcard.com), Fake Call, SpoofTel, Fake Caller ID, Phone Id - Fake Caller Buster.

### OTP Hijacking / 2FA Hijacking
Intercepting One-Time Passwords (OTPs).
*   **Via SMS:** Social engineering telecom providers to transfer SIM control (SIM Swapping) or using SIM jacking malware.
*   **Via Lock Screen:** Physically monitoring lock screen notifications.
*   **Tools:** **AdvPhishing** (bypasses 2FA via tunneling), **mrphish**.
