## 1. Sniffing Concepts & Vulnerable Protocols
**Packet Sniffing** is the process of monitoring and capturing all data packets traveling across a network using software or hardware. Sniffers operate entirely at the **Data Link Layer** (Layer 2 of the OSI Model), meaning upper layers remain completely unaware of the interception.

### Active vs. Passive Sniffing
*   **Passive Sniffing:** Working on a **Hub-based** network. Since hubs blindly broadcast all data to every connected machine, an attacker simply places their NIC (Network Interface Card) into *Promiscuous Mode* (forcing it to evaluate every packet, not just ones addressed to it) and silently captures the traffic. No extra packets are sent.
*   **Active Sniffing:** Working on a **Switch-based** network. Since switches intelligently route data *only* to the intended MAC address port, an attacker must actively inject false traffic (e.g., ARP spoofing, MAC flooding) to force the switch into sending them traffic that is not theirs.

> **💡 CEH Beginner Tip:** **Promiscuous Mode** is the core mechanic of sniffing. By default, your network card ignores any data not explicitly addressed to your MAC address. Promiscuous mode removes this filter, absorbing everything traveling across the physical wire!

### Protocols Highly Vulnerable to Sniffing (Cleartext)
Attackers sniff the network primarily to steal plaintext passwords. 
*   **Telnet (23) & Rlogin:** No encryption. Keystrokes are captured.
*   **HTTP (80):** Transfers user credentials and cookies in cleartext.
*   **SNMPv1 & SNMPv2:** Management info and community strings sent in cleartext.
*   **SMTP, POP, IMAP, NNTP:** Email and newsgroup protocols with weak or no encryption.
*   **FTP (21) & TFTP:** File Transfer Protocols send authentication in cleartext. TFTP relies on UDP and has zero authentication mechanisms.

## 2. Hardware Protocol Analyzers & Wiretapping
If an attacker or administrator connects directly to the physical medium, they can intercept all traffic perfectly.

### SPAN Port (Port Mirroring)
A Cisco switch feature known as **Switched Port Analyzer (SPAN)** mirrors network traffic from one or more ports to a single destination port intended for a network analyzer (like Wireshark).

### Hardware Protocol Analyzers
These devices plug directly into the physical wire. They do not drop packets during overloads and can capture low-level physical errors. 
*   **Xgig 1000 32/128G FC & 25/50/100G Ethernet Analyzer:** Platform for inline, nonintrusive capture and inline jamming. *(Source: https://www.viavisolutions.com)*
*   **SierraNet M1288:** A high-speed Ethernet/FC test platform capable of 256GB buffers. *(Source: https://www.teledynelecroy.com)*
*   **Others:** PTW60, P5551A PCIe 5.0 Protocol Exerciser, Voyager M4x, N2X N5540A Agilent Protocol Analyzer.

### Wiretapping & Lawful Interception
A physical tap into electrical communication lines (Active or Passive).
*   **Lawful Interception (LI):** Legally sanctioned access to private network data (like telephone/email) performed by Law Enforcement Agencies (LEAs).
*   **Telco/ISP Lawful Solutions:** Uses tap switches and Centralized Management Servers (CMS) like **E-Detective (ED)** to decode/reconstruct POP3, IMAP, SMTP, ftp intercepts.

## 3. MAC Attacks & Defense Configuration
A **MAC Address** is a 48-bit physical address. (e.g., `D4-BE-D9-14-C8-29`). `D4BED9` is the OUI (Organizationally Unique Identifier / Manufacturer) and `14C829` is the specific serial number.
A Switch uses a **CAM (Content Addressable Memory) Table** to dynamically track which MAC addresses are plugged into which physical ports. 

### A. MAC Flooding
The CAM table has a limited size. If an attacker rapidly bombards the switch with thousands of fake MAC addresses, the CAM table fills up. When full, the switch enters **fail-open mode**, acting just like a Hub—it broadcasts all incoming private traffic to every port, allowing the attacker to passively sniff everything.
*   **Attack Tool:** `macof` (Part of the UNIX/Linux `dsniff` suite). It floods the table at 131,000 requests per minute with randomized MAC/IPs. *(Source: https://monkey.org)*

### B. Switch Port Stealing
The attacker repeatedly sends gratuitous ARP packets spoofing the MAC address of the target. This creates a "race condition", forcing the switch’s CAM table to continuously toggle the target’s MAC address to the attacker’s physical port. Now, traffic meant for the target routes directly to the attacker.

### 🛡️ Defending Against MAC Attacks (Cisco Port Security)
**Port Security** hardcodes a set number of allowed MAC addresses onto a physical switch port, blocking `macof` completely.

**Configuration Commands for Cisco IOS Switches:**
```bash
configure terminal
interface gigabitethernet 3/1
switchport mode access
switchport port-security

# 1. Limit MAC addresses allowed on this port (Range: 1 to 3072)
switchport port-security maximum 1

# 2. Automatically map the first connected device's MAC dynamically (Sticky)
switchport port-security mac-address sticky

# 3. Choose the action upon violation (restrict drops traffic & sends SNMP trap; shutdown kills port entirely)
switchport port-security violation restrict

# 4. Control aging limits
switchport port-security aging time 2
switchport port-security aging type inactivity

# 5. Prevent excessive traps
snmp-server enable traps port-security trap-rate 5
end

# Verify configuration
show port-security address interface gigabitethernet 3/1
```

## 4. DHCP Attacks & Defense Configuration
**DHCP (Dynamic Host Configuration Protocol)** automatically leases out IP addresses, gateways, and DNS configs. 
*   IPv4 Packet Opcode: `1` = Client Request, `2` = Server Reply.
*   Message flow: DHCPDISCOVER -> DHCPOFFER -> DHCPREQUEST -> DHCPACK.

### A. DHCP Starvation Attack
An attacker broadcasts thousands of spoofed DHCP requests. The DHCP server runs out of available IP addresses to lease, creating a massive Denial of Service (DoS) for the real office users.
*   **Tools:** **Yersinia** *(https://sourceforge.net)*, `dhcpStarvation.py`, Hyenae, DHCPig, Gobbler. 

### B. Rogue DHCP Server Attack
Once the attacker performs a Starvation Attack (above), they introduce their own fake (Rogue) DHCP Server. When legitimate computers reboot and ask the network for an IP address, the attacker’s DHCP server responds first, assigning them IPs and forcing them to use the **attacker's IP as the Default Gateway**. This intercepts all outgoing traffic!
*   **Tools:** mitm6, Ettercap, Gobbler.

### 🛡️ Defending Against DHCP Attacks (DHCP Snooping & MAC Limiting)
**1. DHCP Snooping (Cisco):** 
Filters untrusted DHCP messages. You designate the exact port the real DHCP Server sits on as "Trusted". All other ports instantly drop unauthorized DHCP server replies!
```bash
configure terminal
ip dhcp snooping
ip dhcp snooping vlan 4,104
interface gigabitethernet 3/1     # The port pointing to the REAL server
ip dhcp snooping trust
ip dhcp snooping limit rate 50    # Prevents starvation DoS by limiting packets per second
```

**2. MAC Limiting (Juniper Switches):**
Limits the volume of MAC requests generated on untrusted access ports.
```bash
set interface ge-0/0/1 mac-limit 3 action drop
set interface ge-0/0/2 mac-limit 3 action drop
show ethernet-switching table     # Verify
```

**3. DHCP Filtering (Oracle Switches):**
```bash
interface 0/11
<IP address> dhcp filtering trust
show <IP address> dhcp filtering
```

## 5. ARP Poisoning & Defense Configuration
**ARP (Address Resolution Protocol)** dynamically translates an IP Address into a physical MAC Address (Layer 3 to Layer 2).
*   **The Flaw:** ARP is completely stateless and has zero authentication. If a computer receives an unsolicited ARP reply, it blindly trusts it and overwrites its internal ARP Cache.

### The ARP Spoofing Attack
The attacker sends forged ARP Replies to two targets (e.g., Alice and the Router). The attacker tells Alice "I am the Router," and tells the Router "I am Alice." Both flush their ARP caches and insert the attacker’s MAC address. Now, all traffic between Alice and the Router passes silently through the attacker (MITM / Session Hijacking / Sniffing).

**Attack Tools:** 
*   `arpspoof`: Redirects packets using forged replies.
    ```bash
    arpspoof -i eth0 -t 192.168.1.100 192.168.1.1
    ```
*   **Habu:** Toolkit for ARP poisoning, DHCP starvation, and sub-domain ID. *(Source: https://github.com)*
*   **Others:** bettercap, Ettercap, RITM, larp.

### 🛡️ Defending Against ARP Poisoning (Dynamic ARP Inspection)
**DAI (Dynamic ARP Inspection)** relies on the verified DHCP Snooping database. If a rogue device sends an ARP packet claiming an IP address that the switch knows (from DHCP Snooping) does NOT belong to its switch port, the switch maliciously drops the ARP packet.
```bash
# MUST enable DHCP snooping first!
configure terminal
ip arp inspection vlan 10,11,12,13
show ip arp inspection

# Invalid packets are dropped entirely and show up in the log:
# %SW_DAI-4-DHCP_SNOOPING_DENY: 1 Invalid ARPs (Res) on Fa0/5...
```

**Tools for Detecting ARP Attacks:**
*   **Capsa Portable Network Analyzer:** Instantly detects ARP Poisoning & ARP Flooding visually.
*   **Others:** Wireshark, OpUtils, netspionage, NetProbe, ARP-GUARD.

## 6. Spoofing Attacks (VLAN, STP, IRDP)

### A. MAC Spoofing (Bypassing Filters)
An attacker sniffs a legitimate device's MAC address and manually assigns it to their own NIC to bypass wireless/wired MAC filtering.
*   **Windows Registry Hack:** Edit `NetworkAddress` string in `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\...`
*   **Tools:** **MAC Address Changer** *(https://www.appsvoid.com)*, SMAC, TMAC, Mac Changer.

### B. IRDP Spoofing
Instead of attacking ARP, the attacker attacks the **ICMP Router Discovery Protocol (IRDP)**, sending false "Router Advertisement" messages, forcing the PC to use the attacker as the Default Route. *(Mitigation: Disable IRDP on end-hosts).*

### C. VLAN Hopping
Circumventing network boundaries so your terminal on the "Guest VLAN" can talk inside the "Server VLAN."
*   **Switch Spoofing:** Connect a laptop and negotiate standard Trunking (DTP) to trick the switch into forwarding ALL VLAN traffic to the laptop.
*   **Double Tagging:** Injecting two distinct 802.1Q tags in one packet. The first switch strips the outer Native VLAN tag, unintentionally forwarding the inner, malicious tag onward across the trunk to the target VLAN.

**🛡️ Defending VLAN Hopping:**
```bash
switchport mode access        # Force it to be an access port ONLY
switchport mode nonegotiate   # Disable dynamic trunking (DTP) negotiation
switchport trunk native vlan 999  # Place unused native VLAN on all trunks
```

### D. STP Attack (Spanning Tree Protocol)
Switches use STP (BPDUs) to map out networks and prevent infinite data loops. The switch with the lowest Bridge Priority (BID) becomes the "Root Bridge." An attacker introduces a rogue switch with an artificially low priority value. It becomes the Root Bridge and successfully pulls vast amounts of network traffic physically through the attacker's tap.

**🛡️ Defending Spanning Tree Attacks (BPDU/Root Guard):**
```bash
# Prevents a port from transmitting/receiving rogue switch BPDUs
interface gigabitethernet 1/1
spanning-tree portfast bpduguard

# Forces interfaces to remain designated, completely ignoring fake root BPDUs
spanning-tree guard root

# Also enable Loop Guard and UDLD for malfunctioned links
spanning-tree guard loop
udld aggressive
```

## 7. DNS Poisoning & Spoofing
**DNS Poisoning** replaces legitimate Domain-to-IP resolutions with malicious IP addresses, silently redirecting the victim's Web Browser entirely. (e.g., `www.bank.com -> Attacker_IP`).

### Categories of DNS Spoofing:
1.  **Intranet DNS Spoofing:** Uses ARP Poisoning internally to intercept standard port 53 traffic traveling to the local router.
2.  **Internet / Remote DNS Spoofing:** Attacker uses a Trojan to modify the victim OS's primary DNS settings remotely.
3.  **Proxy Server DNS Poisoning:** Using malware to alter the victim's Internet Explorer Proxy settings.
4.  **DNS Cache Poisoning:** Attacker attacks the corporate DNS resolver itself, populating the shared cache with fake entries. If successful, all employees trying to go to `bank.com` get directed to the hacker!
5.  **SAD DNS Attack:** A modern cache poisoning variant exploiting side-channels in OSes & UDP port flaws to inject harmful records.

**DNS Spoofing Tools:**
*   **DerpNSpoof:** Loads lists of fake DNS records and spoofs the queries.
*   **Others:** deserter, PolarDNS, Evilgrade, DNS Goisoner.

### 🛡️ Defending Against DNS Spoofing
*   Implement **DNSSEC** (DNS Security Extensions).
*   Use DNS-over-HTTPS (**DoH**) or DNS-over-TLS (**DoT**) to encrypt DNS traffic.
*   Force **DNS NXDOMAIN Rate Limiting** and deploy DNS RFC 7873 Cookies to mitigate SAD DNS attacks.
*   Randomize source and destination IP addresses, query IDs, and source ports.
*   Do not allow incoming external UDP port 53 as a default source port answering. Ensure DNS software (Bind) generates secure random transaction IDs.

## 8. Sniffing Tools (Wireshark) & Detection Methods

### Wireshark & Filters
**Wireshark** uses `WinPcap` to capture live network traffic and decode virtually every known protocol.
*   **Follow TCP Stream:** Right-click a target packet -> Follow -> TCP Stream. Evaluates the conversation sequentially, successfully pulling plaintext Passwords straight out of FTP/HTTP/Telnet.

> **💡 CEH Procedural Commands - Essential Wireshark Display Filters:**
> *   `tcp.port==23` -> Filter only Telnet traffic
> *   `ip.addr==192.168.1.100 && tcp.port==23` -> Look for telnet to/from this specific IP
> *   `ip.src==205.153.63.30 or ip.dst==205.153.63.30` -> Track an endpoint
> *   `tcp.flags.reset==1` -> Look for dropped/resets
> *   `!(arp or icmp or dns)` -> Filter out "noise" to focus on raw communication traffic
> *   `http.request` -> Show only web page requests (HTTP GET)

**Other Corporate Network Analyzers:**
*   **OmniPeek:** Provides a Google Maps plug-in displaying public IP locations across real-time captures.
*   **Others:** RITA, Observer Analyzer, PRTG Network Monitor, Xplico.

### Detecting Promiscuous Sniffers
Since passive sniffers do not "say" anything, you cannot detect them by regular network logs. You must force the suspect's NIC to respond when it normally shouldn't.

1.  **Ping Method:** Fire an ICMP Ping request to the target IP, but with a *purposely incorrect MAC address*. A normal computer ignores it, but a Promiscuous NIC automatically processes the payload and erroneously responds.
2.  **DNS Method / Reverse DNS Lookup:** Sniffers often try to resolve the IP addresses they collect into human-readable Hostnames. This triggers massive spikes in sudden Reverse DNS Lookup requests out to the domain server.
3.  **ARP Method:** Send a non-broadcast ARP to all nodes. A promiscuous machine caches the address anyway. Then send a ping with a valid IP but an entirely different MAC. Only the Promiscuous node, utilizing the wrongly cached ARP info, will improperly respond!

**Nmap Promiscuous Detection Script:**
```bash
nmap --script=sniffer-detect 192.168.1.0/24
```
**NetScanTools Pro:** Scanning tools that check for Promiscuous mode listening natively.
