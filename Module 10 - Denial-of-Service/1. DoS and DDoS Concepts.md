## 1. What is a DoS Attack?

*(Source: EC-Council CEH v13)*

A **Denial-of-Service (DoS)** attack is an attack on a computer or network that **reduces, restricts, or prevents access to system resources for legitimate users**. Attackers flood a victim's system with non-legitimate service requests or traffic to overload its resources and bring down the system.

> The goal of a DoS attack is to **keep legitimate users from using the system**, not to gain unauthorized access or corrupt data.

**Examples of DoS attack types:**
* Flooding the victim's system with more traffic than it can handle
* Flooding a service (e.g., IRC) with more events than it can handle
* Crashing a TCP/IP stack by sending corrupt packets
* Crashing a service by interacting with it in an unexpected manner
* Hanging a system by causing it to go into an **infinite loop**

**What DoS attacks cause:**
* Consumption of resources (bandwidth, disk space, CPU time, data structures)
* Actual physical destruction or alteration of network components
* Destruction of programming and files in a computer system
* Loss of goodwill, network outages, financial losses, and operational disruptions

**Two broad DoS target types:**
* **Bandwidth attacks:** Overflow the network with high-volume traffic using existing network resources, depriving legitimate users.
* **Connectivity attacks:** Overwhelm a system with a large number of connection requests, consuming all available OS resources.

> **💡 CEH Beginner Tip (EC-Council):** Think of it like a catering company's phone lines. If an attacker blocks all incoming phone lines, legitimate business becomes impossible — even though nothing was stolen or damaged.

## 2. What is a DDoS Attack?

*(Source: EC-Council CEH v13 / techtarget.com)*

A **Distributed Denial-of-Service (DDoS)** attack is a large-scale, coordinated attack launched indirectly through many **compromised computers (botnets)** on the Internet.

**World Wide Web Security FAQ definition:** *"A DDoS attack uses many computers to launch a coordinated DoS attack against one or more targets. The perpetrator is able to multiply the effectiveness significantly by harnessing the resources of multiple unwitting accomplice computers, which serve as attack platforms."*

**Key Terminology:**

| Term | Definition |
| :--- | :--- |
| **Primary Victim** | The target system whose services are being disrupted |
| **Secondary Victims** | The compromised systems used to launch the attack (zombies/bots) |
| **Botmaster / Attacker** | The threat actor behind the attack |

The primary objective is to first **gain administrative access on as many systems as possible**, then upload DDoS software on them at the chosen time to launch the attack.

**Comparison: DoS vs. DDoS vs. DRDoS**

| Type | Traffic Source | Key Characteristic | Difficulty to Block |
| :--- | :--- | :--- | :--- |
| **DoS** | Single attacker machine | One-to-One | Easy — block the one IP |
| **DDoS** | Botnet (thousands of machines) | Many-to-One | Difficult — thousands of IPs |
| **DRDoS** | Spoofed via reflector systems | Amplified Many-to-One | Very difficult — attacker never contacts victim directly |

## 3. How DDoS Attacks Work

*(Source: EC-Council CEH v13)*

1. Attacker sends a command to **zombie agents** (internet-connected computers compromised via malware) through a **C&C server**
2. Zombie agents send connection requests to **reflector systems** using the **victim's spoofed IP address**
3. Reflector systems believe the requests came from the victim and send responses back to the victim's IP
4. Victim is flooded with **unsolicited responses from multiple reflectors simultaneously** — causing performance degradation or complete shutdown

## 4. Botnets

*(Source: EC-Council CEH v13)*

A **bot** is a software application that runs automated tasks over the Internet. A **botnet** ("roBOT NETwork") is a group of computers infected by bots — a massive network of compromised systems.

> **💡 CEH Beginner Tip:** A relatively small botnet of **1,000 bots** has a combined bandwidth larger than the bandwidth of most corporate systems. Real-world botnets (like Mirai or Necurs) have contained millions of devices.

**IRC Bot Examples (EC-Council):** Cardinal, Sopel, Eggdrop, EnergyMech

### 4.1 Organized Cybercrime Hierarchy

*(Source: EC-Council CEH v13)*

Modern DDoS attacks are often launched by organized crime syndicates operating like corporations:

| Role | Responsibility |
| :--- | :--- |
| **Boss** | Business entrepreneur; does not commit crimes directly |
| **Underboss** | Sets up C&C server and crimeware toolkit database; provides Trojans |
| **Campaign Managers** | Implement attacks, manage affiliation networks, steal data |
| **Resellers** | Sell stolen data |

> A DDoS attack on a bank may be used to **divert the security team's attention** while other actors simultaneously steal credentials and drain bank accounts — the DDoS is the distraction, not the primary goal.

### 4.2 Botnet Capabilities

*(Source: EC-Council CEH v13)*

Botnets enable attackers to:
* **DDoS attacks** — consume bandwidth, overload hosts, destroy network connectivity
* **Spamming** — SOCKS proxy to harvest email addresses and send spam
* **Sniffing traffic** — capture credit card numbers, passwords from compromised hosts
* **Keylogging** — harvest account login credentials (PayPal, banking)
* **Spreading new malware** — propagate more bots to new victims
* **Installing advertisement add-ons** — "click fraud" (automating ad clicks)
* **Google AdSense abuse** — inflate ad click counts for illegal revenue
* **Attacking IRC networks** — clone attacks flood IRC networks
* **Manipulating online polls and games**
* **Mass identity theft** — spoofing trusted organisations (eBay etc.)
* **Credential stuffing** — automated login attacks using stolen credentials across websites
* **Cryptocurrency mining** — installing miners on compromised machines without consent

### 4.3 Scanning Methods to Find Vulnerable Machines

*(Source: EC-Council CEH v13)*

| Scanning Method | How It Works |
| :--- | :--- |
| **Random Scanning** | Infected machine probes random IP addresses in the target range, checks vulnerability, infects and installs malicious code. Generates significant traffic; propagation slows as new IPs become scarce. |
| **Hit-list Scanning** | Attacker builds a list of potentially vulnerable machines. On finding a vulnerable one, installs code and **splits the list in half** — each half scanned by a different machine. Compromised machines increase **exponentially**. |
| **Topological Scanning** | Uses information from an already-infected machine (URLs on its hard drive) to find new victims. Accurate results; performance similar to hit-list scanning. |
| **Local Subnet Scanning** | Infected machine searches for new victims on its **local network behind a firewall**. Combined with other scanning mechanisms. |
| **Permutation Scanning** | All bots share a **pseudorandom permutation list** of IP addresses (32-bit block cipher + preselected key). Scanning restarts from a random point if an already-infected machine is found. Avoids reinfection; high scanning speed. |

### 4.4 Malicious Code Propagation Techniques

*(Source: EC-Council CEH v13)*

| Method | Description |
| :--- | :--- |
| **Central Source Propagation** | Attack toolkit on a central source server is copied to each newly discovered vulnerable machine. The newly infected machine then repeats the search. Uses **HTTP, FTP, and RPC**. |
| **Back-chaining Propagation** | Toolkit resides on the attacker's own machine. Uses **TFTP** through simple port listeners or full web servers to transfer the toolkit to newly compromised systems. |
| **Autonomous Propagation** | The attacking host transfers the toolkit to a newly discovered vulnerable system **at the exact moment it breaks in** — no external file source. Fastest propagation method. |

## 5. DDoS Case Study: HTTP/2 Rapid Reset Attack on Google Cloud (2023)

*(Source: EC-Council CEH v13 / cloud.google.com)*

> **⚠️ CEH Exam Focus:** This is the primary case study explicitly covered in the CEH v13 curriculum.

### Attack Overview
* **Date:** September 2023
* **Scale:** **398 million requests per second (rps)** — 7.5x larger than the previous record (46M rps)
* **CVE:** **CVE-2023-44487** — CVSS Score: **7.5 / 10** (High Severity)
* **Method:** HTTP/2 "Rapid Reset" technique exploiting **stream multiplexing**

### How the Attack Worked
HTTP/2 supports multiplexing — managing **up to 100 live streams through a single TCP connection**. Attackers exploited this by:
1. Opening many streams on a single HTTP/2 connection
2. Immediately sending RST_STREAM frames to cancel each stream right after creation
3. Because the server processes requests before receiving the RST, it is overwhelmed with work despite the connections appearing to terminate normally
4. At scale, this generated **398M requests per second** of server-side load with minimal client-side bandwidth

### Timeline & Impact
* Lasted from late August through end of September 2023
* Peaked for **2-3 minutes** at a time with unexpected TCP RST flag packets
* Targeted Google services, Google Cloud infrastructure, and their customers

### Google's Response
* Countered the attack using **edge capacity** at the perimeter of Google's network
* Devised countermeasures and upgraded proxies and defense systems
* **Shared real-time threat intelligence** with other cloud providers and software maintainers
* Led industry-wide coordinated disclosure, resulting in patches for major open-source/commercial proxies, application servers, and load balancers
* **Google Cloud Application Load Balancer** and **Cloud Armor** provided same protection to cloud customers

> **💡 Supplementary Context:** The same campaign simultaneously hit Cloudflare (201M rps peak) and AWS (155M rps peak). Patches were released for nginx, Apache httpd, HAProxy, and all major HTTP/2 implementations.

## 6. Mobile Devices as Botnets

*(Source: EC-Council CEH v13)*

Android devices are passively vulnerable to Trojans, bots, and RATs frequently found in **third-party application stores** and as **drive-by downloads**.

**Attack Method:**
1. Attacker binds a malicious server to an **Android APK file**
2. Encrypts it and removes unwanted features/permissions
3. Distributes to third-party app stores or as drive-by downloads
4. Victim installs the app — device is integrated into the mobile botnet
5. Device performs DDoS attacks, web injections, and other malicious activities without the owner's knowledge

## 7. Attacker Motivations

*(EC-Council context: diversion attacks / organized crime syndicates; supplementary: additional categories)*

| Motivation | Description |
| :--- | :--- |
| **Extortion (RDDoS)** | Warning attack + ransom demand in cryptocurrency; pay or face sustained attack |
| **Hacktivism** | Politically/socially motivated; e.g., Anonymous targeting government or corporate websites |
| **Cyber Warfare** | Nation-states targeting critical infrastructure before or during kinetic conflict |
| **Competitive Advantage** | Hiring DDoS-for-hire (Booters/Stressers) to take competitors offline during peak sales |
| **Smokescreen/Distraction** | DDoS draws SOC attention while a separate, stealthy data exfiltration occurs |
| **Organized Crime Diversion (EC-Council)** | DDoS on a bank while attackers simultaneously clean out accounts with stolen credentials |
