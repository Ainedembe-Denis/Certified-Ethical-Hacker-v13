## 1. Detection Techniques

*(Source: EC-Council CEH v13)*

Early detection helps prevent DoS/DDoS attacks. All detection techniques define an attack as an **abnormal and noticeable deviation in network traffic statistics**. They involve statistical analysis of deviations to categorize malicious vs. genuine traffic.

### 1.1 Activity Profiling
Based on the **average packet rate for network flow** (consecutive packets with similar header info — source/destination IP, ports, transport protocols). An attack is indicated by:
* An increase in activity levels among network flow clusters
* An increase in the overall number of distinct clusters (DDoS attack indicator)

**Entropy method:** Measures randomness in activity levels. If a network is under attack, the entropy of network activity levels increases. DoS attacks generate a large number of very similar data packets — an increase in average packet rate or diversity indicates attack.

### 1.2 Sequential Change-Point Detection (CUSUM)
Network traffic is filtered by IP addresses, targeted port numbers, and protocols — traffic flow data is stored in a **graph showing traffic flow rate vs. time**. Change-point detection algorithms isolate changes caused by attacks.

**Algorithm:** Uses the **CUSUM (Cumulative Sum) algorithm** to identify and locate DoS attacks. It calculates deviations in **actual vs. expected local average** in the traffic time series. Also identifies typical scanning activities of network worms.

### 1.3 Wavelet-Based Signal Analysis
Analyzes network traffic in terms of **spectral components** — divides incoming signals into various frequencies and analyzes each separately. Analyzing each **spectral window's energy** reveals the presence of anomalies.

* Normal network traffic = **low-frequency** traffic
* During an attack, **high-frequency components increase**
* The wavelet technique filters out anomalous traffic signals from background noise

## 2. DoS/DDoS Countermeasure Strategies

*(Source: EC-Council CEH v13)*

Three high-level organizational response strategies:

| Strategy | Description | Limitation |
| :--- | :--- | :--- |
| **Absorbing the Attack** | Use additional capacity to absorb the attack. Requires preplanning and additional resources. | Ongoing cost even when no attacks are occurring |
| **Degrading Services** | If all services cannot be kept running, identify and keep **critical services** functional by cutting non-critical services | May be insufficient for major attacks |
| **Shutting Down Services** | Shut down all services until the attack subsides | Completes the attacker's goal, but may be the only option |

## 3. Protect Secondary Victims

*(Source: EC-Council CEH v13)*

Secondary victims (zombie machines) must prevent themselves from being recruited into botnets.

**Individual Users:**
* Monitor security regularly to remain protected from DDoS agent software
* Ensure the system does not install DDoS agent programs
* Install and regularly update **antivirus and anti-Trojan software** and software patches
* Disable unnecessary services, uninstall unused applications
* Scan all files received from external sources

**Network Service Providers:**
* Adopt **dynamic pricing for network usage** to charge potential secondary victims, encouraging them to become more active in preventing themselves from participating in DDoS attacks

## 4. Detect and Neutralize Handlers

*(Source: EC-Council CEH v13)*

Discovering and disabling C&C handlers is one of the most effective ways to stop DDoS attacks:

* **Network traffic analysis:** Analyzing communication protocols and traffic patterns between handlers and clients/agents reveals infected network nodes
* **Neutralizing botnet handlers:** Disabling handlers can render multiple agents useless — because **the number of handlers is much less than the number of agents**, neutralizing a few handlers disrupts many attack vectors simultaneously
* **Identifying spoofed source addresses:** DDoS packet spoofed source addresses will often not represent valid addresses of the definite sub-network. Thorough understanding of traffic patterns among handlers, clients, and agents helps identify these

## 5. Prevent Potential Attacks

*(Source: EC-Council CEH v13)*

### 5.1 Egress Filtering
Scans headers of **IP packets leaving a network**. If packets don't meet specifications (source address doesn't match the internal network's IP block), they are dropped.

* Ensures **unauthorized or malicious traffic never leaves** the internal network
* DDoS attacks generate spoofed IPs — requiring source addresses to match internal network blocks mitigates this
* Protects even against zero-day exploits by **preventing the server from establishing connections back to the attacker**

### 5.2 Ingress Filtering
A packet filtering technique used by **Internet Service Providers (ISPs)** to prevent **source address spoofing** of Internet traffic.

* Makes Internet traffic traceable to its true source
* Protects against flooding attacks that originate from valid prefixes
* Enables the originator to be traced to its true source

### 5.3 TCP Intercept (Cisco)
A traffic-filtering feature in Cisco routers to protect TCP servers from SYN-flooding attacks.

**How it works:**
* In **intercept mode:** Cisco IOS actively intercepts all inbound SYN requests and replies with SYN-ACK on behalf of the server, then waits for ACK from the client. Once ACK is received, the router makes a 3-way handshake with the real server. The two half-connections are then linked transparently.
* In **watch mode:** Connection requests pass through to the server, but if not established within **30 seconds**, the software sends a reset to the server to clear its state.

### 5.4 Rate Limiting (Throttling)
Controls the **rate of outbound or inbound traffic** of a network interface. Configured to limit request rates on **Layers 4 and 5 of the OSI model**.

## 6. Deflect Attacks (Honeypots)

*(Source: EC-Council CEH v13)*

**Honeypots** are systems set up with **intentionally limited security** to attract attackers, gather intelligence on attack techniques and tools, and prevent attacks on actual sensitive systems.

DDoS attackers attracted to a honeypot install handlers/agent code into the honeypot — **avoiding compromise of more sensitive systems**. The honeypot records all handler/agent activity.

**Two types:**
* **Low-interaction honeypots** — simulate limited services
* **High-interaction honeypots** — e.g., **Honeynets**: simulate the complete layout of a real network with real computers running real applications. All activity is controlled and tracked.

**Blumira Honeypot Software (EC-Council):**
Source: https://www.blumira.com
* Detects unauthorized access attempts and **lateral movement** after a breach
* Enhances security maturity and enables **early attack detection** with low maintenance
* Once a honeypot event is detected, **immediately blocks the source IP at the switch or firewall level**

**Additional Honeypot Tools (EC-Council):**
* KFSensor (https://www.kfsensor.net)
* Valhala Honeypot (https://sourceforge.net)
* Cowrie (https://github.com)
* HoneyHTTPD (https://github.com)
* StingBox (https://www.stingbox.com)

## 7. Mitigate Attacks

*(Source: EC-Council CEH v13)*

### 7.1 Load Balancing
Bandwidth providers can **increase bandwidth on critical connections** during a DDoS attack. Using a **replicated server model** provides additional failsafe protection — load balancing balances loads on each server in a multiple-server architecture, increasing normal performance and mitigating DDoS effects.

### 7.2 Throttling
Setting up routers with logic to **throttle incoming traffic levels** that are safe for the server. Uses "Min-max fair server-centric router" throttles (minimum and maximum throughput controls). Helps the router manage heavy incoming traffic so the server can handle it.

**Limitation:** May trigger false alarms — occasionally allowing malicious traffic while dropping legitimate traffic.

### 7.3 Drop Requests
When load increases, the router/server drops packets. Before dropping, the system can make the requester **solve a difficult puzzle** that requires significant memory or computing power — dissuading zombie system users who detect performance degradation.

## 8. Post-Attack Forensics

*(Source: EC-Council CEH v13)*

### 8.1 Traffic Pattern Analysis
Traffic pattern tools store **post-attack data** which is analyzed to identify characteristics unique to the attacking traffic. These data help:
* Update load balancing and throttling countermeasures
* Develop new filtering techniques
* Ensure an attacker cannot use your servers as a DDoS platform against other sites

### 8.2 Packet Traceback
Tracing attack traffic **backward to its source** (reverse engineering). Once the true source is identified:
* Steps can be taken to block further attacks
* Knowledge gained about attacker tools and techniques helps develop filtering techniques

### 8.3 Event Log Analysis
DDoS event logs assist in **forensic investigation and law enforcement**. Use honeypots, firewalls, packet sniffers, and server logs to store all events during attack setup and execution. Routers, firewalls, and IDS logs help identify the DoS traffic source.

## 9. Techniques to Defend Against Botnets

*(Source: EC-Council CEH v13)*

| Technique | Description |
| :--- | :--- |
| **RFC 3704 Filtering** | Basic ACL filter limiting DDoS impact by blocking traffic with spoofed addresses. Uses a **"bogon list"** of unused/reserved IP addresses that should never originate from the Internet. If a packet comes from a bogon IP, it's spoofed and dropped. |
| **Cisco IPS Source IP Reputation Filtering** | Uses **Cisco Global Correlation** (Cisco IPS 7.0) and the **Cisco SensorBase Network** — contains info on all known Internet threats (botnets, malware, dark nets). Filters DoS traffic before it damages critical assets. |
| **Black Hole Filtering (RTBH)** | Drops traffic at network nodes without informing the source. Uses **Remotely Triggered Black-Hole (RTBH)** filtering via **BGP host routes** to route victim-destined traffic to a "null0" next hop. Must be done in conjunction with the ISP. |
| **DDoS Prevention from ISP** | ISP scrubs/cleans traffic before allowing it to enter the user's Internet link. Because this runs **in the cloud**, DDoS attacks don't saturate Internet links. Can use **IP Source Guard (Cisco)** to filter traffic based on the DHCP snooping binding database. |

**Additional DoS/DDoS Countermeasures (EC-Council complete list):**
* Use strong encryption (WPA2/WPA3, AES-256) for broadband networks to defend against eavesdropping
* Keep software and protocols up-to-date; scan machines for anomalous behavior
* Update kernel to latest release; disable unused and insecure services
* Block all inbound packets from service ports to block reflection server traffic
* **Enable TCP SYN cookie protection**
* Prevent transmission of fraudulently addressed packets at ISP level
* Implement cognitive radios in the physical layer to handle jamming and scrambling attacks
* Configure firewall to **deny external ICMP traffic access**
* Perform thorough input validation
* Prevent use of unsafe functions such as `gets` and `strcpy`
* Use advanced network-level surveillance technologies to monitor the network perimeter
* Ensure semi-accessible connections have **assertive timeout functions**
* Implement distributed server model and colocation services as backup
* Use third-party protection services for enhanced security
* Use **multi-cloud deployment** models for major applications to ensure backup during DDoS
* Perform extensive simulations of DoS/DDoS attacks regularly
* **Share threat intelligence** with industry peers and leverage threat intelligence feeds
* Use **AI/ML and anomaly detection** systems to automatically identify traffic deviations
* Limit network broadcasting
* **Disable echo and chargen services**

## 10. Cisco TCP Intercept Configuration

*(Source: EC-Council CEH v13 / cisco.com)*

TCP intercept can be enabled using these commands in **global configuration mode**:

| Step | Command | Purpose |
| :--- | :--- | :--- |
| 1 | `access-list <number> {deny|permit} tcp any <destination> <wildcard>` | Defines an IP extended access list |
| 2 | `ip tcp intercept list <access-list-number>` | Enables TCP intercept |

**Set the TCP intercept mode:**
```
ip tcp intercept mode {intercept | watch}
```

An access list achieves three purposes:
1. Interception of all requests
2. Interception of only requests originating from specific networks
3. Interception of only requests destined for specific servers

**Default mode:** Intercept (active). Watch mode has a 30-second timeout.

**DoS Protection at ISP Level (EC-Council):**
ISPs offer **"clean pipes"** service-level agreements providing **assured bandwidth of genuine traffic** rather than all traffic. Vendors providing cloud DoS protection: **Imperva, VeriSign**. Administrators can request ISPs to **block the original affected IP and move the site to another IP** after DNS propagation.
