## 1. Legal and Safety Prerequisites

*(Supplementary — CEH general framework applies)*

DoS/DDoS penetration testing is the **most legally dangerous** category of testing. Executing even a small DDoS test incorrectly can take a production environment offline, causing real financial losses and legal liability.

> **💡 CEH Exam Tip:** Standard pen testing Rules of Engagement (ROE) **exclude DoS testing by default**. Unless the ROE explicitly states "Denial of Service testing is authorized," it is forbidden.

**Mandatory prerequisites:**
1. **Explicit Written Authorization** — ROE must explicitly include DoS testing authorization
2. **Third-Party Notification** — If the client uses AWS, Cloudflare, Azure, or shared hosting, the pen tester MUST notify those providers before testing. Attacking an AWS-hosted server without notifying AWS violates their Terms of Service
3. **Maintenance Windows** — Tests only during agreed scheduled maintenance windows (e.g., 2:00 AM on Sunday) to minimize impact on real users
4. **Emergency Stop Protocol** — Both parties agree on an emergency "kill word" or direct communication channel; the tester must be able to halt all traffic within seconds
5. **Scope Definition** — Clearly define which IP addresses, ports, and services are in-scope; DoS tests should be narrowly scoped to avoid collateral damage to shared infrastructure

## 2. DoS Pen Testing Methodology

*(Supplementary — aligned with CEH pen testing framework)*

A DoS pen test is fundamentally a **structured, controlled stress test** — we want to find the exact breaking point and verify that defenses engage correctly.

### Phase 1: Reconnaissance & Baseline Establishment
You cannot measure attack impact without knowing what normal looks like.
* **Identify critical systems:** Web servers, DNS servers, load balancers, backend databases, authentication services
* **Establish a traffic baseline:** Measure normal CPU, RAM, bandwidth, and connection counts during peak and off-peak hours using monitoring tools (Wireshark, SolarWinds, Nagios)
* **Map the defense landscape:** Identify CDN, WAF, rate-limiting, and DDoS scrubbing services in place

### Phase 2: Vulnerability Identification
Before launching any floods, identify specific vulnerabilities:
* Web forms vulnerable to RUDY/Slowloris (timeouts too high, no rate limiting)?
* Is the Apache server exposing Slowloris attack surface?
* Is the NTP server running an unpatched version with monlist enabled?
* Are any services running on UDP with potential amplification exposure?
* **Fuzzing:** Send malformed packets to see if unexpected input crashes the application (fuzzing-based DoS)

### Phase 3: Attack Execution (Graduated Stress Testing)
Attack phases must be **ramped up slowly** — never instantaneous. The order matters:

**Step 1 — Protocol Testing (Layer 3/4):**
* Launch a TCP SYN flood using hping3; slowly ramp up packets-per-second (pps)
* Monitor the firewall's state table — does SYN Cookie protection engage? At what pps does the server stop accepting legitimate connections?

**Step 2 — Volumetric Testing (Bandwidth):**
* Generate controlled UDP/ICMP floods
* Note: True Tbps volumetric testing requires a commercial stress-testing service or large distributed infrastructure — a single pen tester cannot simulate 100+ Gbps floods

**Step 3 — Application Testing (Layer 7):**
* Launch Slowloris or an HTTP GET flood against the target web application
* Monitor backend database CPU usage — at what rps does the database become the bottleneck?

### Phase 4: Post-Attack Analysis & Reporting
* **Measure MTTD (Mean Time to Detect):** How long before the SOC realized they were under attack?
* **Measure Mitigation Effectiveness:** Did the WAF block the Layer 7 attack? Did BGP Blackhole engage?
* **Identify Gaps:** What traffic volume was required to take the service offline? Which defenses failed?
* **Report with Actionable Recommendations:** e.g., "Implement Rate Limiting on the login portal," "Upgrade NTP server firmware to patch monlist"

## 3. Pen Testing Tools for DoS

*(Supplementary — professional-grade tools used by ethical hackers)*

| Tool | Purpose in DoS Pen Testing |
| :--- | :--- |
| **hping3** | Ultimate packet crafting tool. Custom SYN/FIN/ICMP/UDP floods with full control over all packet fields. `hping3 -S --flood --rand-source -p 80 <target>` generates a rapid SYN flood from spoofed random IPs. |
| **Metasploit Framework** | Contains auxiliary DoS modules: `auxiliary/dos/tcp/synflood`, `auxiliary/dos/http/slowloris`. Used in authorized engagements for controlled, repeatable tests. |
| **Boofuzz** | Network protocol fuzzing framework (successor to Sulley). Send massive amounts of random/malformed data to a specific port to identify fuzzing-based DoS vulnerabilities. |
| **GoldenEye / Torshammer** | Layer 7 HTTP stress testing tools; test web server thread exhaustion. |
| **Nmap** | Used in reconnaissance phase: `nmap -sU -pU:123 -Pn -n --script=ntp-monlist <target>` to check for NTP monlist vulnerability |
| **Wireshark** | Baseline capture and attack traffic analysis; verify that malicious packets are being correctly dropped by defenses |

## 4. Module 10 Master Summary

*(EC-Council module summary + supplementary consolidation for exam review)*

**The Three Attack Categories (EC-Council):**
| Category | Measures In | Key Attacks |
| :--- | :--- | :--- |
| **Volumetric** | bps | UDP Flood, ICMP Flood, Smurf, Pulse Wave, NTP Amplification |
| **Protocol** | pps / cps | SYN Flood, ACK Flood, Fragmentation, TCP SACK Panic, Spoofed Session |
| **Application** | rps | HTTP GET/POST Flood, Slowloris, UDP App Layer Flood, RDDoS/Extortion |

**The Botnet Engine (EC-Council):**
* Boss → Underboss → Campaign Managers → Resellers hierarchical structure
* Scanning: Random, Hit-list, Topological, Local Subnet, Permutation
* Propagation: Central Source, Back-chaining, Autonomous
* Mobile botnets via APK infection in third-party stores

**The Google Case Study (EC-Council — must know):**
* September 2023 — 398 million rps — HTTP/2 Rapid Reset
* CVE-2023-44487 — CVSS 7.5 (High)
* Exploited HTTP/2 stream multiplexing (up to 100 streams per TCP connection)

**Key Detection Methods (EC-Council):**
* Activity Profiling (entropy-based)
* Sequential Change-Point Detection (CUSUM algorithm)
* Wavelet-Based Signal Analysis (frequency spectrum analysis)

**Critical Defense Technologies (EC-Council):**
* RFC 3704 Filtering — bogon list
* Cisco IPS Source IP Reputation — SensorBase Network
* Black Hole Filtering (RTBH) via BGP null0 routing
* DDoS Prevention at ISP level — clean pipes
* TCP Intercept (Cisco IOS)

**Hardware Appliances (EC-Council):**
* FortiDDoS (Fortinet)
* Quantum DDoS Protector (Check Point)
* AntiDDoS1000 (Huawei)
* Thunder TPS (A10 Networks)

**Protection Services (EC-Council):**
* Cloudflare — 100 Tbps, 87 billion threats blocked daily, 3-second mitigation

* Imperva, Stormwall PRO, Nexusguard, BlockDoS
