## 1. Wireless Encryption Protocols Overview

Wireless encryption is the process of protecting a wireless network from attackers attempting to collect sensitive information by breaching RF traffic.

| Protocol / Standard | Description |
| :--- | :--- |
| **802.11i** | IEEE amendment specifying security mechanisms for 802.11 networks. |
| **WEP** | Encryption algorithm for 802.11. Old standard; easily cracked. |
| **EAP** | Extensible Authentication Protocol supports multiple authentication methods (token cards, Kerberos, certificates). |
| **LEAP** | Lightweight EAP — a proprietary version developed by Cisco. |
| **WPA** | Advanced wireless encryption protocol using TKIP and Message Integrity Check (MIC). Uses 48-bit IV, 32-bit CRC, and TKIP. |
| **TKIP** | Security protocol used in WPA as a replacement for WEP. |
| **WPA2** | Upgrade to WPA using AES and CCMP for data encryption. |
| **AES** | Symmetric-key encryption used in WPA2 as a replacement for TKIP. |
| **CCMP** | Counter Mode Cipher Block Chaining Message Authentication Code Protocol — encryption protocol used in WPA2 for strong encryption. |
| **WPA2 Enterprise** | Integrates EAP standards with WPA2 encryption. |
| **RADIUS** | Centralized authentication and authorization management system. |
| **PEAP** | Encapsulates EAP within an encrypted and authenticated TLS tunnel. |
| **WPA3** | Third-generation Wi-Fi security. Uses GCMP-256 for encryption and HMAC-SHA-384 for authentication. |

## 2. Wired Equivalent Privacy (WEP)

WEP was an early attempt to protect wireless networks, utilizing a symmetric **Rivest Cipher 4 (RC4)** encryption algorithm at the data link layer.

**Role:** Protects against eavesdropping, attempts to prevent unauthorized access, and depends on a shared secret key.

**Key Lengths:**
* 64-bit WEP uses a **40-bit key** (with 24-bit IV).
* 128-bit WEP uses a **104-bit key**.
* 256-bit WEP uses a **232-bit key**.

### How WEP Works (Operational Flow):
1. **CRC-32** checksum calculates a 32-bit Integrity Check Value (ICV) added to the data frame.
2. A **24-bit initialization vector (IV)** is added to the WEP key to form the **WEP seed**.
3. The WEP seed is input to the RC4 algorithm to generate a **keystream**.
4. The keystream is bit-wise XORed with the (Data + ICV) to produce the encrypted data.
5. The IV field (IV + PAD + KID) is prepended to the ciphertext to generate the MAC frame.

## 3. Wi-Fi Protected Access (WPA)

WPA replaces WEP static keys. It uses **Temporal Key Integrity Protocol (TKIP)** and a **Message Integrity Check (MIC)** to eliminate WEP weaknesses by including per-packet mixing functions, extended IVs, and re-keying.

* **TKIP:** Unicast encryption key that changes for every packet. Uses Michael Integrity Check algorithm. Mitigates WEP flaws by increasing IV size to 48 bits. Implements sequence counters to prevent replay attacks. Changes the Temporal Key (TK) every 10,000 packets.
* **TKs (Temporal Keys):** Derived from the Pairwise Master Key (PMK) during the 4-way handshake.

### How WPA Works (Operational Flow):
1. A TK, transmit address, and TKIP sequence counter (TSC) are input into the RC4 algorithm to generate a keystream.
2. The IV, MAC destination address, and TK are mixed to generate a 128-bit and 104-bit key.
3. The MAC service data unit (MSDU) and MIC are combined using the Michael algorithm.
4. The MSDU + MIC is fragmented to generate the MAC protocol data unit (MPDU).
5. A 32-bit ICV is calculated for the MPDU.
6. The combination is bitwise XORed with the keystream.
7. The IV is added to generate the MAC frame.

## 4. Wi-Fi Protected Access 2 (WPA2)

WPA2 replaced WPA in 2006. It supports the **802.11i standard** and uses the NIST FIPS 140-2-compliant **AES** encryption algorithm alongside **CCMP**.

### Modes of Operation:
* **WPA2-Personal:** Uses a Pre-Shared Key (PSK) — 256-bit key generated from a passphrase (8–63 ASCII characters). The router combines the passphrase, SSID, and TKIP to generate unique keys.
* **WPA2-Enterprise:** Uses EAP or RADIUS for centralized client authentication. Users have individual login credentials, preventing key sharing.

### How WPA2 Works:
1. Additional Authentication Data (AAD) is generated using the MAC header to protect non-encrypted portions from alteration.
2. A sequenced Packet Number (PN) generates a Nonce.
3. Plaintext data, temporal keys, AAD, and Nonce are input into AES and CCMP algorithms.
4. PN is included in the CCMP header to prevent replay attacks.
5. AES and CCMP produce encrypted text and an encrypted MIC value.
6. The assembled MAC header, CCMP header, encrypted data, and encrypted MIC form the WPA2 MAC frame.

## 5. Wi-Fi Protected Access 3 (WPA3)

WPA3 uses modern key establishment protocols and prevents outdated legacy protocols.

### Modes of Operation:
* **WPA3-Personal:** Uses **Simultaneous Authentication of Equals (SAE)**, also known as the **Dragonfly Key Exchange**, replacing the PSK concept. It provides resistance to offline dictionary attacks, allows natural password choices, and provides forward secrecy.
* **WPA3-Enterprise:** Based on WPA2 but offers superior security.
  * *Authenticated Encryption:* Uses 256-bit **GCMP-256**.
  * *Key Derivation:* Uses 384-bit **HMAC-SHA-384**.
  * *Key Establishment:* Uses **ECDH** and **ECDSA** on a 384-bit elliptic curve.
  * *Frame Protection:* Uses 256-bit **BIP-GMAC-256**.

### Enhancements over WPA2:
1. **Secured Handshake:** The SAE / Dragonfly handshake prevents offline decryption of data via dictionary/brute-force attacks.
2. **Wi-Fi Easy Connect:** Uses Device Provisioning Protocol (DPP) to allow IoT devices to securely connect via QR code or password.
3. **Unauthenticated Encryption:** Uses **Opportunistic Wireless Encryption (OWE)** to replace "open" Wi-Fi networks (public hotspots) with encrypted protection.
4. **Bigger Session Keys:** Supports 192-bit keys (or higher) in Enterprise mode.

## 6. Comparison of WEP, WPA, WPA2, and WPA3

| Encryption | Algorithm | IV Size | Key Length | Key Management | Integrity Check |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **WEP** | RC4 | 24-bits | 40/104-bits | None | CRC-32 |
| **WPA** | RC4, TKIP | 48-bits | 128-bits | 4-way handshake | Michael algorithm / CRC-32 |
| **WPA2** | AES-CCMP | 48-bits | 128-bits | 4-way handshake | CBC-MAC |
| **WPA3** | AES-GCMP 256 | Arbitrary (1 to 2⁶⁴) | 192-bits | ECDH and ECDSA | BIP-GMAC-256 |

### Quick Comparison

| Standard | Security Level | Main Weakness / Strength |
| :--- | :--- | :--- |
| **WEP** | Very Weak | Easily broken due to RC4 weaknesses and short IV. |
| **WPA** | Weak / Deprecated | Improved over WEP but vulnerable due to TKIP-related attacks. |
| **WPA2** | Strong | Widely used; AES-CCMP provides robust security. |
| **WPA3** | Very Strong | Latest standard; stronger encryption, SAE authentication prevents password attacks. |

## 7. Issues with WEP, WPA, WPA2, and WPA3

### Issues with WEP
* **CRC-32 is insufficient:** Attackers can capture two packets, flip a bit, modify the checksum, and the packet is accepted.
* **Small IV (24 bits):** Sent in cleartext; a busy AP exhausts the entire IV space in 5 hours, forcing IV reuse.
* **RC4 Design Flaws:** KSA (Key Scheduling Algorithm) creates predictable bytes.
* **Vulnerable to FMS Attacks:** The way the IV is appended allows Fluhrer-Mantin-Shamir attacks to crack the key.
* **No Forward Secrecy / Centralized Management:** Same key used by all users; rarely changed.
* **Vulnerable to Known Plaintext & Dictionary Attacks.**

### Issues with WPA
* **Weak Passwords:** WPA PSK is vulnerable to password cracking.
* **Lack of Forward Secrecy:** Capturing the PSK allows decryption of *all* previously transmitted packets.
* **Packet Spoofing & Decryption:** WPA-TKIP allows injection and decryption, enabling TCP session hijacking.
* **GTK Predictability:** Insecure Random Number Generators (RNG) allow attackers to discover the Group Temporal Key and inject traffic.
* **Guessing IP Addresses:** TKIP flaws allow subnet IP guessing.

### Issues with WPA2
* **Weak Passwords & Lack of Forward Secrecy** (similar to WPA).
* **KRACK Vulnerabilities:** The **Key Reinstallation Attack (KRACK)** exploits flaws in the 4-way handshake. Attackers force "Nonce reuse" by capturing and replaying the victim's ANonce key. Allows sniffing, hijacking, and malware injection. Works against WPA-TKIP, AES-CCMP, and GCMP.
* **Hole96 Vulnerability:** Allows attackers to exploit the GTK to perform MITM and DoS attacks.
* **Wireless DoS Attacks:** Attackers forge group-addressed data frames with large PNs to abuse replay attack detection.
* **Insecure WPS PIN Recovery:** WPS vulnerabilities allow attackers to brute-force the PIN and extract the WPA2 key.

### Issues with WPA3
* **Implementation & Adoption Challenges:** Older devices lack firmware updates to support WPA3; transition is slow.
* **Hardware Requirements:** Complex encryption demands high processing power, straining older devices.
* **Configuration Errors:** Poor network setup leaves networks vulnerable.
* **Timing Attacks & Side-Channel Attacks:** Certain implementations of the SAE handshake are vulnerable to timing attacks or cache-based access pattern extraction (e.g., Dragonblood vulnerabilities).
* **Transition Mode Weakness:** Allowing both WPA2 and WPA3 lets attackers force a downgrade to WPA2, re-enabling attacks like KRACK.
