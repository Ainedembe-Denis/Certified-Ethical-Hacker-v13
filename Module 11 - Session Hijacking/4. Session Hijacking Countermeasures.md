## 1. Session Hijacking Detection Methods

Session hijacking attacks often go unnoticed unless severe damage is caused. Two primary symptoms are:
1. **A sudden burst of network activity** decreasing system performance.
2. **Busy servers** resulting from requests sent by both the legitimate client and the hijacker.

### Manual Method (Packet Sniffing)
Security professionals use tools like **Wireshark** or **SteelCentral Packet Analyzer** to monitor traffic. The primary technique used is a **Forced ARP Entry**.
* **Forced ARP Entry:** Replaces the MAC address of a compromised machine in the ARP cache of the server with a different one to restrict network traffic to the compromised machine.
* A Forced ARP entry should be performed if you observe:
  * Repeated ARP updates.
  * Frames sent between the client and server with different MAC addresses.
  * **ACK Storms** (endless loops of acknowledgment packets).

### Automatic Method (IDS/IPS)
Using Intrusion Detection Systems (IDS) and Intrusion Prevention Systems (IPS) to monitor incoming network traffic against databases of known attack signatures.

## 2. Prevention: Web Developer Guidelines

Developers must secure the mechanisms used for session establishment.

* **Session Key Generation:** Use lengthy strings or completely random numbers (predictability = failure).
* **Regeneration:** Always **regenerate the session ID after a successful login** to prevent Session Fixation attacks.
* **Cache Directives:** Use restrictive directives through HTTP/HTTPS.
  * `Cache-Control: no-cache, no-store`
  * `Pragma: no-cache`
* **Cookie Security Attributes:**
  * **HTTPOnly:** Prohibits client-side user scripts (like JavaScript) from accessing the cached cookies, heavily mitigating XSS attacks.
  * **Secure Flag:** Ensures cookies are only sent across the network via HTTPS requests.
  * **SameSite:** Prevents the browser from sending cookies along with cross-site requests, mitigating CSRF attacks.
* **Continuous Verification:** Implement continuous device verification to ensure the user who established the session is still in control (e.g., using behavioral biometrics like typing rhythms or mouse movements).
* **Destruction:** Destroy sessions on the server-side itself when a user logs out; do not rely merely on session expiration.

---

## 3. Prevention: Web User Guidelines

* Use **HTTPS** exclusively for transmitting sensitive data.
* Ensure the browser history, offline content, and cookies are **cleared** after sensitive transactions.
* **Logout explicitly** by clicking the button rather than simply closing the browser tab (which often keeps the session alive).
* Avoid auto-connecting to open Wi-Fi networks and avoid conducting financial transactions on public Wi-Fi.
* Use encrypted messaging (e.g., VPNs, SSH).
* Do not save passwords natively in the browser; use a dedicated Password Manager.

## 4. Advanced Approaches to Prevent MITM

Because detecting Man-in-the-Middle (MITM) attacks is so difficult, prevention relies heavily on architecture.

| Technology | How it Prevents Hijacking |
| :--- | :--- |
| **HSTS (HTTP Strict Transport Security)** | Forces web browsers to interact with servers *only* using HTTPS. All insecure HTTP connections are automatically converted, preventing MITM downgrade attacks (like `sslstrip`). |
| **Token Binding** | The client creates a public/private key pair for every connection. It sends a signature using the private key along with its public key. If an attacker captures the session ID, they still cannot use it because they don't possess the private key to generate the required cryptographic signature. |
| **DNS over HTTPS (DoH)** | Web queries and traffic are sent through a secured HTTPS tunnel via **Port 443** (instead of standard Port 53). Prevents ISPs and attackers from peeking at DNS lookups. (Default in Mozilla since 2020). |
| **WPA3 Encryption** | Modern wireless protocol that prevents attempts by unwanted users to brute-force credentials and enter the target network to perform MITM attacks. |
| **Zero-Trust Principles** | "Trust but verify." Standardized user pre-verification requiring *all* users (inside or outside the perimeter) to authenticate before accessing any resource. |
| **PKI (Public Key Infrastructure)** | Manages, distributes, and validates digital certificates to ensure communicating entities are who they claim to be. Validated by Certificate Authorities (CAs). |

## 5. Deep Dive: IPsec (Internet Protocol Security)

IPsec is a critical suite of protocols developed by the IETF to support the secure exchange of packets at the **IP layer** (Network Layer). It supports data confidentiality, connectionless integrity, and **replay protection**.

### IPsec Components
1. **IPsec Driver:** Software that encrypts/decrypts packets.
2. **IKE (Internet Key Exchange):** Protocol that produces security keys.
3. **ISAKMP:** Allows two computers to communicate by encrypting exchanged data.
4. **Oakley:** Uses the Diffie-Hellman algorithm to create a master key specific to each session.
5. **IPsec Policy Agent:** Windows OS service that enforces IPsec policies.

### IPsec Architecture Protocols
* **AH (Authentication Header):** Provides connectionless integrity and data origin authentication, plus anti-replay protection. **Does NOT provide confidentiality (no encryption).**
* **ESP (Encapsulating Security Payload):** Offers all services of AH, **plus confidentiality (encryption).**
* **DOI (Domain of Interpretation):** Defines payload formats, exchange types, and naming conventions for cryptographic algorithms.

### Modes of IPsec

> **💡 CEH Beginner Tip:** The exam will heavily test the difference between Transport and Tunnel mode. Remember: **Transport = Payload only. Tunnel = Entire Packet.**

1. **Transport Mode:**
   * **Encrypts ONLY the payload** of the IP packet. The original IP header remains intact.
   * Used for end-to-end communications between two specific hosts.
   * Compatible with Network Address Translation (NAT).

2. **Tunnel Mode:**
   * Encapsulates and **encrypts the ENTIRE IP packet** (both payload and original IP header).
   * This encapsulated packet becomes the payload for a *new* IP packet with a *new* IP header.
   * Used to create VPNs over the internet for network-to-network communication (e.g., between two routers bridging site-to-site).
   * Highly secure, but heavier overhead.

## 6. Detection & Prevention Tools

**Detection Tools:**
* **USM Anywhere:** (AT&T Cybersecurity) SIEM tool for threat detection, incident response, asset discovery, and compliance.
* **Wireshark:** Captures live network traffic from Ethernet, IEEE 802.11, Token Ring, etc. Uses Winpcap.
* **IPS Tools:** Quantum IPS, SolarWinds Security Event Manager, IBM Security Network IPS, LogRhythm.

**Prevention / Auditing Tools:**
* **Checkmarx One (SAST):** Static Application Security Testing. Analyzes source code for technical and logical flaws before deployment to prevent MITM, XSS, and Fixation vulnerabilities.
* **Fiddler:** Web debugging proxy that logs all HTTP(S) traffic. Used by security pros to perform MITM decryption locally to test web applications and manipulate web sessions.
* **Vulnerability Scanners:** Nessus, Invicti, Wapiti.
