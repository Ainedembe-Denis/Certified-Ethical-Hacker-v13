## 1. Public Key Infrastructure (PKI)

PKI is a security architecture developed to manage public-key encryption and digital certificates, binding public keys to user identities.

### Components of PKI:
*   **Certificate Authority (CA):** Trusted entity that issues and verifies digital certificates. Examples: Comodo, IdenTrust, DigiCert.
*   **Registration Authority (RA):** Acts as the verifier for the CA. Validates the subject's identity before the CA issues the certificate.
*   **Validation Authority (VA):** Stores and validates the certificates with their public keys for clients making inquiries.
*   **Certificate Management System:** Generates, distributes, stores, and verifies certificates.
*   **Digital Certificates:** Digitally signed statements (X.509) containing the subject's name and public key.

### Trust Models:
*   **Signed Certificate:** Validated by a trusted third-party CA.
*   **Self-Signed Certificate:** Generated by the user via tools (Adobe Acrobat, Java keytool, Apple Keychain). The user signs the document using their own self-generated certificate.
*   **Web of Trust (WOT):** A decentralized model used by PGP/GnuPG. There is no central CA; instead, every user is a CA and intermediately validates each other's certificates using their signatures.

## 2. Digital Signatures

A digital signature uses asymmetric cryptography and hash functions to simulate the properties of a physical signature. 
1.  The sender creates a hash (message fingerprint) of the message.
2.  The sender encrypts this hash with their **private key** to create the digital signature.
3.  The receiver decrypts the signature using the sender's **public key** to retrieve the original hash.
4.  The receiver hashes the received message and compares it to the decrypted hash to verify **integrity** and **nonrepudiation**.

## 3. SSL and TLS

### Secure Sockets Layer (SSL)
Developed by Netscape, SSL encrypts data transferred over network connections (e.g., HTTP over SSL = HTTPS) using RSA asymmetric encryption. 

**SSL Handshake Protocol Flow:**
1.  Client sends a "Client Hello" (protocol version, session ID, cipher suite).
2.  Server sends a "Server Hello" and its digital certificate.
3.  Server sends a "Server Hello Done".
4.  Client responds with a certificate (if requested) and a "Client Key Exchange" message (contains the pre-master secret encrypted with the server's public key).
5.  Client sends a "Change Cipher Spec" message to switch to the negotiated symmetric algorithm, followed by a "Finished" message.
6.  Server responds with its own "Change Cipher Spec" and "Finished" message. Application data exchange begins securely.

### Transport Layer Security (TLS)
TLS is the modern, more secure replacement for SSL. It operates in two layers: the **TLS Record Protocol** (secures connection, fragments/compresses data, applies MAC) and the **TLS Handshake Protocol** (negotiates algorithms and keys).

## 4. Email Encryption (PGP & S/MIME)

### Pretty Good Privacy (PGP) & GNU Privacy Guard (GPG)
PGP is a hybrid cryptosystem combining symmetric and asymmetric encryption for email/file security. GPG is its free, open-source implementation (OpenPGP standard).
*   **Process:** 
    1. PGP compresses the plaintext data.
    2. It creates a one-time random session key to symmetrically encrypt the compressed data.
    3. The session key is encrypted using the recipient's **public key**.
    4. Both the encrypted data and encrypted session key are sent to the recipient.
*   **Tools:** **FlowCrypt** (a browser extension for end-to-end PGP encryption in Gmail).

### S/MIME Encryption
Secure/Multipurpose Internet Mail Extensions (S/MIME) is used natively in enterprise email clients like Microsoft Outlook.
*   **Outlook Setup:** Requires a signing certificate attached to the keychain. Configured via `File → Options → Trust Center → Trust Center Settings → Email Security`.
*   **Office 365 Message Encryption (OME):** Allows sending encrypted emails to any address (recipient uses a one-time passcode or Microsoft account). Configured via `Options → Encrypt → Encrypt-Only`.
*   **Other Tools:** RMail, Mailvelope, Virtru, Proofpoint.

## 5. Disk Encryption

Disk encryption scrambles all information on a disk, rendering it illegible without the correct password or keyfile.

### Hardware-Based Encryption
Hardware processors handle the cryptographic workload, keeping system resources free and preventing malicious software interference.
*   **TPM (Trusted Platform Module):** A crypto-processor chip on the motherboard that securely stores keys and provides full disk encryption.
*   **HSM (Hardware Security Module):** An external network device used for managing and securely storing high-performance cryptographic keys (e.g., Thales Luna).
*   **USB/Hard Drive Encryption:** Self-encrypting drives (SEDs) with onboard encryption (e.g., Kingston Ironkey).

### Software-Based Encryption Tools
*   **Windows:** 
    *   **BitLocker:** Uses the TPM chip to provide volume-level encryption for Windows.
    *   **VeraCrypt:** Creates on-the-fly encrypted volumes. Files are decrypted dynamically in RAM only when accessed.
    *   **Rohos Disk Encryption:** Creates hidden, AES-256 encrypted partitions on local drives or cloud storage.
*   **Linux:**
    *   **Cryptsetup:** Sets up disk encryption based on the DMCrypt kernel module (supports LUKS, loop-AES, TrueCrypt).
    *   *Others:* Cryptmount, Tomb.
*   **macOS:**
    *   **FileVault:** Uses XTS-AES-128 encryption tied to user logins to protect the startup disk.

## 6. Blockchain

A blockchain is a distributed ledger technology (DLT) that records transactions securely in blocks. Each block contains data, its own hash, and the hash of the previous block (genesis block is the first). Validating blocks is known as "proof of work" (crypto mining).

*   **Public Blockchain:** Decentralized, permission-less (Bitcoin, Ethereum).
*   **Private Blockchain:** Central authority dictates who can join (Hyperledger).
*   **Federated/Consortium Blockchain:** Partially decentralized, managed by a group of trusted organizations (banks, government).
*   **Hybrid Blockchain:** Combination of public and private (IBM Food Trust).
