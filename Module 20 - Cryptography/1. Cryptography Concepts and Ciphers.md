## 1. Introduction to Cryptography

"Cryptography" comes from the Greek words *kryptos* (concealed, hidden, veiled, secret) and *graphia* (writing). It is the practice of concealing information by converting plaintext (readable format) into ciphertext (unreadable format) using a key or encryption scheme. It secures data against interception during online transmissions (e.g., email, web transactions, e-commerce).

---

## 2. Objectives of Cryptography

*   **Confidentiality:** Assurance that the information is accessible only to authorized entities.
*   **Integrity:** Trustworthiness of data; preventing improper and unauthorized changes.
*   **Authentication:** Assurance that the communication, document, or data is genuine.
*   **Nonrepudiation:** Guarantee that the sender cannot later deny sending the message, and the recipient cannot deny receiving it.

---

## 3. Types of Cryptography

Cryptography is categorized into two main types based on the number of keys employed:

### Symmetric Encryption (Private-Key Cryptography)
Requires both the sender and the receiver to possess the **same** encryption key. 
*   **Strengths:** Faster and easier to implement; requires less processing power; can be implemented in ASICs; prevents widespread compromise as different keys are used for different parties.
*   **Weaknesses:** Lacks a secure channel to initially exchange the secret key; difficult to manage many shared keys; provides no assurance about the origin/authenticity of a message (no nonrepudiation); vulnerable to dictionary and brute-force attacks.

### Asymmetric Encryption (Public-Key Cryptography)
Uses a key pair: a **public key** (available to anyone) to encrypt, and a **private key** (held only by the owner) to decrypt. This solves the key management and exchange problem.
*   **Strengths:** Convenient (no need to distribute private keys); enhanced security; provides digital signatures that cannot be repudiated.
*   **Weaknesses:** Slow processing; requires high processing power; widespread message compromise is possible if the private key is lost or stolen; messages cannot be decrypted if the private key is lost; vulnerable to MITM attacks.

## 4. Government Access to Keys (GAK)

**Government Access to Keys (GAK)** refers to the statutory obligation of individuals and organizations to disclose their cryptographic keys to government agencies. Law enforcement uses these keys to monitor suspicious communications and collect digital evidence.

*   **Key Escrow:** Government agencies often use a key exchange arrangement where essential cryptographic keys are stored with a trusted third party in escrow. The third party can provide the keys to the government under a court warrant.
*   **Concerns:** Disclosing a single key might expose other, unrelated confidential data. Government agencies are rarely aware of the full scope of what the key protects, leaving the key owner liable for the consequences of a widespread data breach if the keys are mishandled.

## 5. Ciphers

A cipher is an algorithm (a series of well-defined steps) for performing encryption and decryption. 

### Classical Ciphers
The most basic ciphers, operating on letters of the alphabet (A–Z). Easily deciphered and generally unreliable.
*   **Substitution Cipher:** Replaces units of plaintext with ciphertext. The recipient performs inverse substitution. 
    *   *Examples:* Beale cipher, autokey cipher, Gronsfeld cipher, Hill cipher. (e.g., "HELLO" -> "PSTER").
*   **Transposition Cipher:** Letters in the plaintext are rearranged according to a regular system. 
    *   *Examples:* Rail fence cipher, route cipher, Myszkowski transposition. (e.g., "CRYPTOGRAPHY" -> "AOYCRGPTYRHP").

### Modern Ciphers
Designed to withstand a wide range of attacks using one-way mathematical functions capable of factoring large prime numbers.

**Based on Input Data:**
*   **Block Cipher:** Deterministic algorithms operating on a fixed-size block (group of bits) with an unvarying transformation specified by a symmetric key. Padding is used if the block size is smaller than required.
    *   *Examples:* DES, AES, IDEA.
*   **Stream Cipher:** Symmetric-key ciphers where plaintext digits are combined with a pseudorandom cipher digit stream (key stream). The key is applied to each bit, one at a time.
    *   *Examples:* RC4, SEAL.

### Cipher Modes of Operation (Block Ciphers)
*   **Electronic Code Book (ECB):** Straightforward. Plaintext is divided into fixed blocks. Each block is encrypted individually with the key. 
    *   *Flaw:* Identical plaintext blocks produce identical ciphertext blocks, allowing pattern prediction.
*   **Cipher Block Chaining (CBC):** Uses an Initialization Vector (IV). The first plaintext block is XORed with the IV before encryption. Subsequent plaintext blocks are XORed with the previous ciphertext block.
    *   *Flaw:* Errors in one ciphertext block propagate to subsequent blocks.
*   **Cipher Feedback (CFB):** The previous ciphertext is used as feedback to encrypt the next block. The IV is stored in a shift register. It makes cryptanalysis difficult due to data loss in shift registers.
*   **Counter Mode (CTR):** Uses a synchronized counter value instead of an IV. The counter value and key are encrypted, then XORed with the plaintext. Eliminates error propagation because it doesn't use previous ciphertext blocks.

### Authenticated Encryption (AE)
Combines ciphertext with a Message Authentication Code (MAC) to prevent Chosen Ciphertext Attacks.
*   **Encrypt-then-MAC (EtM):** Plaintext is encrypted -> MAC generated from ciphertext -> MAC attached to ciphertext. (Highest security).
*   **Encrypt-and-MAC (E&M):** MAC generated from plaintext -> Plaintext encrypted -> Both combined.
*   **MAC-then-encrypt (MtE):** MAC generated from plaintext -> MAC combined with plaintext -> Entire combination encrypted.
*   **AEAD (Authenticated Encryption with Associated Data):** Adds unencrypted routing/header data to the ciphertext to verify the source, while the payload remains encrypted.
