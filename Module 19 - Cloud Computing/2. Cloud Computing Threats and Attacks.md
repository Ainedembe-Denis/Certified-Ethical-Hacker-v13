## 1. OWASP Top 10 Security Risks

### OWASP Top 10 Cloud Security Risks
1.  **Accountability and Data Ownership:** Using public cloud can jeopardize data recoverability and control compared to traditional data centers.
2.  **User Identity Federation:** Using multiple cloud providers creates multiple user identities, complicating management and offboarding.
3.  **Regulatory Compliance:** Complex due to different regulatory laws across various countries.
4.  **Business Continuity and Resiliency:** Risk of monetary loss if the CSP handles business continuity improperly during disasters.
5.  **User Privacy and Secondary Usage of Data:** Social application providers mining user data for secondary usage.
6.  **Service and Data Integration:** Unsecured data in transit between the end-user and data center is susceptible to interception.
7.  **Multi Tenancy and Physical Security:** Inadequate logical segregation can lead to tenants interfering with each other’s security features.
8.  **Incidence Analysis and Forensic Support:** Distributed event logs across multiple hosts/countries make forensics difficult.
9.  **Infrastructure Security:** Misconfigurations allow network scanning for vulnerable applications and exposed ports.
10. **Non-Production Environment Exposure:** Using test environments internally increases the risk of unauthorized access and data disclosure.

### OWASP Top 10 Kubernetes Risks
1.  **Insecure Workload Configurations:** Running containers with root privileges or missing resource limits.
2.  **Supply Chain Vulnerabilities:** Flaws in third-party container images or CI/CD pipelines.
3.  **Overly Permissive RBAC Configurations:** Granting excessive permissions, allowing privilege escalation.
4.  **Lack of Centralized Policy Enforcement:** Inconsistent security policies across clusters (requires tools like OPA).
5.  **Inadequate Logging and Monitoring:** Lack of detailed logs makes incident response difficult.
6.  **Broken Authentication Mechanisms:** Weak passwords or failure to implement MFA.
7.  **Missing Network Segmentation Controls:** Lack of isolation between pods allows lateral movement.
8.  **Secrets Management Failures:** Hardcoding API keys in code or storing them unsecured.
9.  **Misconfigured Cluster Components:** Incorrect settings in API server, etcd, or kubelet.
10. **Outdated and Vulnerable Kubernetes Components:** Failing to update Kubernetes and its dependencies.

### OWASP Top 10 Serverless Security Risks
1.  **Injection:** SQL/NoSQL, OS command, and code injection originating from diverse event sources (S3, DynamoDB, SMS).
2.  **Broken Authentication:** Stateless functions triggered by events; spoofed emails can execute internal functionality without auth.
3.  **Sensitive Data Exposure:** Storing data in plaintext or writing to `/tmp` without removing it.
4.  **XML External Entities (XXE):** XML processors vulnerable to XXE, leading to leakage of `/tmp` files or environment variables.
5.  **Broken Access Control:** Over-privileged functions granting access to unnecessary resources.
6.  **Security Misconfiguration:** Long timeouts and low concurrency limits leading to DoS.
7.  **Cross-Site Scripting (XSS):** Arriving from non-traditional sources like emails, logs, and IoT.
8.  **Insecure Deserialization:** Flaws in Python/NodeJS JSON deserialization allowing arbitrary code execution.
9.  **Using Components with Known Vulnerabilities:** Vulnerable third-party libraries.
10. **Insufficient Logging and Monitoring:** Lack of timely auditing paves the way for deeper attacks.

## 2. General Cloud Computing Threats

*   **Data Breach/Loss:** Improperly designed multi-tenant environments leading to erased data or stolen encryption keys.
*   **Loss of Operational and Security Logs:** Storage under-provisioning resulting in lost audit trails.
*   **Malicious Insiders:** Disgruntled employees or contractors misusing access to compromise data.
*   **Illegal Access:** Weak authentication controls leading to unlawful access.
*   **Loss of Business Reputation:** Malicious activity of one co-tenant affecting another due to poor resource isolation.
*   **Theft of Computer Equipment:** Inadequate physical security at data centers.
*   **Improper Data Handling and Disposal:** Data not being truly wiped upon client request due to backups or shared hardware.
*   **Cloud Service Misuse:** Attackers utilizing cloud infrastructure for Botnet C&C, DDoS, or password cracking farms.
*   **Insecure Interfaces and APIs:** Unknown dependencies, reusable tokens, and lack of validation.
*   **Shared Technology Issues:** Vulnerabilities in hypervisors mediating access between guest OSs.
*   **Unsynchronized System Clocks:** Leading to timestamp inaccuracies that hinder forensic analysis and database backups.
*   **Economic Denial of Sustainability (EDoS):** Attackers consume CPU cycles to bankrupt the legitimate account holder ("No use, no bill" exploited).
*   **Container Vulnerabilities:** Impetuous image creation, insecure runtimes, embedded malware, hijacked registries, and mixing workload sensitivity levels on one host.

## 3. Cloud Attacks

*   **Service Hijacking via Social Engineering:** Attackers trick users into visiting fake cloud login pages to steal credentials.
*   **Service Hijacking via Network Sniffing:** Intercepting unencrypted credentials/cookies using Wireshark or Capsa.
*   **Side-Channel / Cross-guest VM Breaches:** Placing a malicious VM on the same physical host as the target to perform timing, power monitoring, or cache attacks.
*   **Wrapping Attack:** Duplicating the body of a SOAP message during TLS translation. The server verifies the duplicated signature but executes the attacker's malicious code.
*   **Man-in-the-Cloud (MITC) Attack:** Abusing cloud file synchronization services (Google Drive, Dropbox) by stealing the victim's synchronization token and syncing malicious files.
*   **Cloud Hopper Attack:** Targeting Managed Service Providers (MSPs) via spear-phishing, then moving laterally to compromise the MSP's global customers.
*   **Cloud Cryptojacking:** Injecting JavaScript-based crypto-miners (e.g., CoinHive) into cloud instances or exploiting random cloud resources for mining.
*   **Cloudborne Attack:** Implanting a persistent backdoor in the bare-metal server firmware (Baseboard Management Control - BMC). The backdoor survives server reallocation to new clients.
*   **Instance Metadata Service (IMDS) Attack:** Exploiting a reverse proxy or SSRF vulnerability to query the IMDS (e.g., `169.254.169.254/latest/meta-data/`) to steal cloud access keys.
*   **CPDoS / CDN Cache Poisoning:** Sending malformed HTTP requests so the origin server returns an error. The CDN caches the error page, denying legitimate access.
*   **Cloud Snooper Attack:** Bypassing AWS Security Groups by installing a rootkit that intercepts legitimate traffic on port 80/443 and redirects it to a backdoor Trojan on internal ports.
*   **Golden SAML Attack:** Compromising the ADFS server (identity provider) to steal token signing certificates, allowing the attacker to forge SAML assertions and access federated services.
*   **Living Off the Cloud Attack (LotC):** Using legitimate cloud tools (CMD, PowerShell) and services (Dropbox, Ngrok) for malware delivery and C2, blending in with normal traffic.
*   **Session Hijacking using Session Riding:** Using Cross-Site Request Forgery (CSRF) to execute commands via a victim's active session.
*   **DNS Attacks:** DNS Poisoning, Cybersquatting, Domain Hijacking.

## 4. Cloud Malware

*   **Cuttlefish Zero-Click Malware:** A packet-sniffing malware targeting SOHO routers. It deploys a bash script to collect host data and hijack DNS/HTTP traffic directed to private IPs, sending it to a cloud C2 server.
*   **Other Examples:** Denonia, LemonDuck, RansomCloud, DBatLoader, Goldbackdoor.
