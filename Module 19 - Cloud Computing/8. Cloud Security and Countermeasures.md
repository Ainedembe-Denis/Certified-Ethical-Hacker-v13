## 1. Cloud Security Control Layers

Security in the cloud is a shared responsibility between the Cloud Service Provider (CSP) and the Cloud Consumer. Security controls are mapped to the following layers:
*   **Application Layer:** Policies matching industry standards (OWASP), WAFs, and secure SDLC.
*   **Information Layer:** Data Loss Prevention (DLP), encryption, database activity monitoring.
*   **Management Layer:** Governance-Risk-Compliance (GRC), IAM, patch management, VM monitoring.
*   **Network Layer:** Intrusion Prevention Systems (IPS), deep packet inspection, anti-DDoS, DNSSEC.
*   **Trusted Computing:** Hardware/Software Root of Trust (RoT) and APIs for internal control.
*   **Computation and Storage:** Host-based firewalls, encryption, and data retention policies.

### Security Assertion Markup Language (SAML)
SAML is an open-standard protocol for Single Sign-On (SSO). It consists of three entities: Client, Service Provider (SP), and Identity Provider (IdP). The IdP validates the user and sends an XML-based authentication assertion to the SP, preventing password sharing across services.

## 2. Cloud Network Security

*   **Virtual Private Cloud (VPC):** A secure, independent environment residing within a public cloud. It isolates network traffic between different tenants using subnets, ACLs, and routing tables.
*   **Public and Private Subnets:** Public subnets route traffic to the internet via an Internet Gateway (IGW). Private subnets route outbound traffic via a NAT gateway, keeping inbound traffic completely blocked.
*   **Transit Gateways:** A centralized network routing solution connecting on-premise networks with multiple VPCs, simplifying topology.
*   **VPC Endpoints:** Establishes a private connection between a VPC and a cloud service (e.g., S3) without using the public internet. Includes *Interface Endpoints* (ENIs) and *Gateway Load Balancer Endpoints*.

## 3. Zero Trust Networks

The Zero Trust model assumes that *every* user or device trying to access the network is untrusted by default. It follows the principle: **"Trust no one and validate before providing access."**
*   **Control Plane:** Manages and verifies requests based on role, time, and device type.
*   **Data Plane:** Configured dynamically to accept traffic only after the control plane approves it.
*   **Micro-segmentation:** Breaks the network into smaller zones to limit lateral movement if a perimeter breach occurs.

## 4. Best Practices for Cloud Security

### General Practices
*   Enforce SLAs for patching, vulnerability remediation, and business continuity.
*   Use Strong Key Generation (HSM) and rotate keys frequently.
*   Implement end-to-end encryption and Transport Data Encryption (TDE).
*   Conduct continuous monitoring and deploy Cloud Access Security Brokers (CASB).

### AWS Security Best Practices
*   Apply the Principle of Least Privilege via IAM policies and rotate access keys regularly.
*   Utilize **AWS Trusted Advisor** to prevent misconfigurations.
*   Use **AWS VPC Flow Logs**, **CloudTrail**, and **Amazon Inspector** for monitoring and threat detection.
*   Store backups on immutable storage.

### Azure Security Best Practices
*   Ensure identity is the main security perimeter (Azure AD).
*   Implement JIT (Just-In-Time) VM access to provide temporary elevated permissions.
*   Use **Azure Bastion** for RDP and SSH connections rather than exposing ports to the internet.
*   Leverage **Microsoft Sentinel** for SIEM threat detection.

### GCP Security Best Practices
*   Implement STRIDE as a threat model.
*   Deactivate interactive serial console support in Google VMs.
*   Use Shielded VMs to protect against rootkits and remote attacks.
*   Use **Google Security Command Center** for aggregating security findings.

## 5. Container & Serverless Security

### Container / Kubernetes Security
*   **Immutable Containers:** Disallow modifications after deployment. Run applications as non-root users.
*   **Namespace Isolation:** Use Docker's PID and IPC namespaces to isolate containers.
*   **Resource Quotas:** Set memory/CPU constraints (`--memory`) to prevent resource exhaustion (DoS).
*   **Kubernetes Specifics:**
    *   Implement copy-then-rename for atomic log rotation.
    *   Use secondary logging for strict non-repudiation.
    *   Avoid using legacy SSH tunnels; use secure TLS by default.
    *   Use Open Policy Agent (OPA) or Kyverno for centralized policy management.

### Serverless Security
*   Do not trust input from any source; sanitize all event inputs (S3, DynamoDB, API Gateway).
*   Set minimum timeouts for functions to limit the window of execution for attackers.
*   Employ API Gateway throttling and rate-limiting to mitigate DDoS.
*   Use ephemeral secret storage and rotate keys during runtime.

## 6. Cloud Security Tools

### Shadow Cloud Asset Discovery
*   **Securiti:** AI-powered tool to discover and monitor untracked/shadow data assets across multi-cloud.
*   **Other Tools:** CloudEagle, FireCompass, BetterCloud, Microsoft Defender for Cloud Apps.

### Cloud Access Security Broker (CASB)
Gatekeepers placed between on-premise infrastructure and cloud providers. They enforce DLP, tokenization, malware filtering, and encryption.
*   **Tools:** Forcepoint ONE CASB, Cisco Cloudlock, Zscaler CASB, FortiCASB.

### Next-Generation Secure Web Gateway (NG SWG)
Protects against cloud-based threats and online data theft using URL filtering, TLS decryption, and machine learning anomaly detection.
*   **Tools:** Netskope Next Gen SWG, Cloudflare Gateway, Skyhigh SWG.

### Security Auditing & Container Security Tools
*   **Scout Suite:** Multi-cloud security-auditing tool leveraging APIs to highlight misconfigurations.
*   **Qualys Cloud Platform:** End-to-end continuous compliance posture assessment.
*   **Container Security:** Aqua, Sysdig Falco, Anchore, Snyk Container, Lacework.
*   **Kubernetes Security:** Advanced Cluster Security (ACS) for Kubernetes, Kyverno, Kubeaudit.
*   **Serverless Security:** Dashbird, CloudGuard, Datadog Serverless Monitoring.
