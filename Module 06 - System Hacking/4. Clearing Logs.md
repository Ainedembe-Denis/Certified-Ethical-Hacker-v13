## 1. Introduction to Covering Tracks
Covering tracks is a mandatory phase for attackers who wish to remain unobserved and retain long-term access. System administrators typically monitor event logs and audit records; therefore, manipulating or destroying these logs is a priority.

### Key Objectives
* Evade detection and traceback.
* Prevent legal action and forensic investigations.
* Maintain prolonged access (backdoors) without suspicion.

### Target Windows Log Types
| Log Type | Filename | Contains |
| :--- | :--- | :--- |
| **Security** | `SECEVENT.EVT` | Failed logins, file accesses without privileges, security policies. |
| **System** | `SYSEVENT.EVT` | Driver failures, hardware/system component events. |
| **Application** | `APPEVENT.EVT` | Application-specific warnings and errors. |

### Main Techniques Used
1. **Disabling Auditing:** Turning off log generation altogether.
2. **Clearing Logs:** Deleting existing corresponding entries.
3. **Manipulating Logs:** Modifying select entries to avoid total deletion (which requires admin privileges and causes suspicion).
4. **Covering Tracks on the Network:** Utilizing reverse HTTP/ICMP tunnels and DNS tunneling.
5. **Covering Tracks on the OS:** Utilizing NTFS streams, modifying timestamps.
6. **Deleting Files:** Utilizing tools like Cipher.exe to prevent data recovery.
7. **Disabling Windows Functionality:** Disabling last access timestamp, hibernation, virtual memory, system restore points, etc.
8. **Hiding Artifacts:** Hiding malicious artifacts within the OS artifacts to evade detection.

## 2. Disabling Auditing
If an attacker gains command-line access, they will often disable the auditing status before proceeding using `Auditpol.exe`, a command-line utility tool to change audit security settings at the category and subcategory levels.

| Action | Command |
| :--- | :--- |
| **View Audit Settings** | `auditpol /get /category:*` |
| **Enable Auditing** | `auditpol /set /category:"system","account logon" /success:enable /failure:enable` |
| **Disable Auditing** | `auditpol /set /category:"system","account logon" /success:disable /failure:disable` |

## 3. Clearing and Manipulating Logs

### 3.1 Automated Methods (Windows)

#### `Clear_Event_Viewer_Logs.bat`
A utility (downloaded from tenforums.com) used to wipe out logs using a BAT file. It can be run as an administrator. It opens a command prompt to clear the event logs and automatically closes when finished.

#### Meterpreter Shell (Metasploit)
Wipes out all logs on a compromised Windows system instantly:
```bash
meterpreter > clearev
```

#### PowerShell (`Clear-EventLog`)
Requires Administrator privileges to clear PowerShell or system logs:

| Purpose | Command |
| :--- | :--- |
| Clear PS Logs | `Clear-EventLog "Windows PowerShell"` |
| Clear specific logs | `Clear-EventLog -LogName ODiag, OSession localhost, Server02` |
| Clear multiple and confirm | `Clear-EventLog -LogName application, system -confirm` |

> *Note Parameters:* `-ComputerName` specifies a remote computer; `-Confirm` prompts for confirmation; `-LogName` specifies event logs; `-WhatIf` shows what will happen without executing.

#### using `wevtutil`
A native Windows utility to manage event logs:
```bat
:: Display list of event logs
wevtutil el

:: Clear specific log (e.g., system)
wevtutil cl system
:: Syntax: wevtutil cl <log_name>
```

### 3.2 Manual Methods (Windows & Linux)

**For Windows:**
1. Navigate to `Control Panel` → `System and Security` → `Windows Tools` → `Event Viewer`.
2. Delete all the log entries logged while compromising the system.

**For Linux (`/var/log/`):**
Linux logs are plainly stored text files under `/var/log`. An attacker uses a standard text editor to modify or delete logs, like `/var/log/<filename.log>`.

## 4. Clearing Online & Shell Tracks

### Ways to Clear Online Tracks
Attackers clear online tracks (web history, logs, cookies, cache, etc.) using multiple approaches:
* Use private browsing
* Delete history in the address field
* Disable stored history
* Delete private data
* Clear cookies and cache on exit
* Delete downloads
* Disable password manager & clear data in it
* Delete saved sessions & user JavaScript
* Set up multiple users
* Remove Most Recently Used (MRU)
* Clear toolbar data from browsers
* Turn off AutoComplete

### Clearing Windows 11 Tracks (Privacy Settings & Registry)
* **Windows 11 Privacy Settings:** Right-click Start -> Settings -> Personalization -> Start. Turn off “Show most used apps” and "Show recently opened items in Start, Jump Lists, and File Explorer".
* **Windows Registry:** Open Registry Editor, navigate to `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\RecentDocs`. Delete all keys/values except `(Default)`.
* **Windows Activity History:** Open Settings (Win + I) -> Privacy & security -> Activity history -> Click **Clear** under "Clear activity history".
* **Windows Incognito / DNS History:** Run `ipconfig /displaydns` to view, and `ipconfig /flushdns` to clear traces of browsing history from memory.
* **macOS Incognito / DNS History:** Open Terminal and run `sudo killall -INFO mDNSResponder`.

### Covering BASH Shell Tracks (Linux)
Bash stores commands in `.bash_history` (viewed using `more ~/.bash_history`).

| Technique | Command | Description |
| :--- | :--- | :--- |
| **Disable History** | `export HISTSIZE=0` | Sets retained commands to zero limit. |
| **Clear History** | `history -c` | Clears stored history, an alternative to disabling it entirely. |
| **Clear Current Shell** | `history -w` | Only deletes the history of the current shell. |
| **Delete Complete History** | `cat /dev/null > ~/.bash_history && history -c && exit` | Purges all history logs completely and exits. |
| **Shred History** | `shred ~/.bash_history` | Renders the history file permanently unreadable. |
| **Shred, Delete, & Clear** | `shred ~/.bash_history && cat /dev/null > ~/.bash_history && history -c && exit` | Shreds, zeroes out, clears cache, and exits. |

## 5. Covering Tracks on a Network
To evade Network IDS and Firewalls, attackers obfuscate their communication channels.

* **Reverse HTTP Shells:** Malicious reverse shell contacts an external master system. Traffic to the attacker behaves like normal HTTP `GET` web requests, blending into standard internet traffic.
* **Reverse ICMP Tunnels:** Encapsulating TCP payloads inside ICMP Echo/Reply packets. Bypasses firewalls that only check incoming ICMP packets but not outgoing ones.
* **DNS Tunneling:** Encoding malicious payloads or commands inside standard DNS queries and replies to exfiltrate data (creating a backchannel using internal compromised systems).
* **TCP Parameters:** Hiding data inside TCP packet parameters:
  * **IP Identification Field:** Encapsulating one character per packet.
  * **TCP Acknowledgement Number:** Using a bounce server to relay hidden characters.
  * **TCP Initial Sequence Number:** Encapsulating hidden characters per SYN request and reset packet (requires no established session).

## 6. Covering Tracks on an OS (Hiding Artifacts)
Attackers manipulate OS features, timestamps, and files to prevent forensic discovery.

### 6.1 Windows
* **NTFS Alternate Data Streams (ADS):**
  Hide a secret file behind a legitimate one:
  ```bat
  type C:\SecretFile.txt > C:\LegitFile.txt:SecretFile.txt
  more < C:\LegitFile.txt:SecretFile.txt
  ```
* **Hiding Files & Folders:** `attrib +h +s +r <FolderName>`
* **Hiding Active User Accounts via CLI:**
  ```bat
  net user <UserName> /add
  net user <UserName> /active:yes
  net user <UserName> /active:no
  ```
* **Hiding User Accounts via Registry:**
  Navigate to `HKEY_LOCAL_MACHINE\Software\Microsoft\WindowsNT\CurrentVersion\Winlogon`. Right-click on Winlogon -> New -> Key (rename to `<Account1>`). Within `<Account1>`, create a New -> Key (rename to `<Account2>`). Finally, create a NEW -> DWORD value and rename to `<UserName>`.
* **Modifying Timestamps:**
  ```bat
  timestomp file_name.doc -z "<Date> <time>"
  ```
  ```powershell
  powershell -Command "(Get-Item $File_name).LastWriteTime = $(Get-Date).AddHours(-10)"
  ```
* **Secure File Deletion (`Cipher.exe`):**
  Overwrites deleted data (with zeros (0x00), then 255s (0xFF), then random data) to guarantee files are irrecoverable.
  ```bat
  cipher /w:<drive letter>:\<folder name>
  cipher /w:<drive letter>
  ```

### 6.2 Linux/macOS
* **Linux (dot prefix):** Prefixing a filename with a `.` makes it hidden (`mv MaliciousFile.txt .MaliciousFile.txt`). Usually stored in `/dev`, `/tmp`, or `/etc`. To create hidden folders and files: `mkdir .HiddenMaliciousFiles`, `touch .MaliciousFile.txt`. View hidden files using `ls -a` or `ls -al`.
* **Linux Modifying Timestamps (`touch`):**
  ```bash
  touch -a -d '<date> <time>' $File_name  # Changes access time
  touch -m -d '<date> <time>' $File_name  # Changes modification time
  ```
* **macOS Hiding Files & Folders:**
  ```bash
  defaults write com.apple.finder AppleShowAllFiles FALSE
  killall Finder
  ```
  Hide a specific file:
  ```bash
  chflags hidden <filename> 
  ```

## 7. Disabling Windows Functionality
Windows services specifically track user actions and state. Disabling them is required to remain undetected.

1. **Last Access Timestamp**
   Updates timestamp when file accessed. Disabling prevents tracking:
   ```bat
   fsutil behavior set disablelastaccess 1
   ```
2. **Windows Hibernation (`Hiberfil.sys`)**
   The hibernation file stores a snapshot of RAM. Attackers disable hibernation to prevent forensic RAM dumps.
   * **Registry:** `Computer\HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Power` -> Set `HibernateEnabledDefault` to `0`.
   * **CLI:** `powercfg.exe /hibernate off`
3. **Virtual Memory (Paging File - `pagefile.sys`)**
   Paging holds chunks of RAM on disk (e.g., decrypted passwords).
   * **Steps:** Control Panel -> System and Security -> System -> Advanced system settings -> Performance (Settings...) -> Advanced tab -> Virtual Memory (Change...) -> Uncheck "Automatically manage paging file size", select "No paging file", and click Set.
4. **System Restore Points**
   Deleted artifacts can be recovered here.
   * **Steps:** Control Panel -> System and Security -> System -> System protection -> Configure -> Disable system protection, click Delete, and repeat for all partitions.
5. **Windows Thumbnail Cache (`thumbs.db`)**
   Stores remnants of viewed/deleted graphic files.
   * **Steps:** Run `gpedit.msc` -> User Configuration -> Administrative Templates -> Windows Components -> File Explorer -> Enable "Turn off the caching of thumbnails in hidden thumbs.db files".
6. **Windows Prefetch**
   Accelerates app launches but logs app execution history.
   * **Steps:** Run `services.msc` -> search and double-click `SysMain (Superfetch)` -> set Startup type to `Disabled`.

## 8. Anti-Forensics Techniques
Attackers use advanced techniques and tools to thwart computer forensics:

* **Data/File Deletion:** Circumventing the recycle bin to remove pointers; hiding/deleting metadata from the Recycle Bin.
* **Password Protection/Encryption:** Thwarting extraction attempts by securing malicious toolkits against reverse engineering.
* **Steganography:** Hiding configurations, lists of compromised servers, tools, or botnet IPs inside encrypted formats or images.
* **Data Hiding in Structures:** Misusing `$BadClus` (sparse file allocations), HPAs (Host-protected areas), DPAs, and slack spaces on disks.
* **Trail Obfuscation:** Deleting evidence against defensive systems. Techniques include log tampering, false email header generation, timestamp modifications (`Timestomp`, `Transmogrify`), using log cleaners, zombie accounts, spoofing, trojan commands, and misinformation.
* **Overwriting data/metadata:** Utilizing data shredding and wiping to overwrite storage media with random bits.
* **Program Packers:** Compressing and obfuscating malware code (e.g., UPX, PECompact, BurnEye, Exe Stealth Packer, Smart Packer Pro) to confuse reverse-engineering tools.
* **Minimizing Footprints:** Using stolen identities, VMs, Live USB/External HDDs, Tor, untraceable cryptocurrencies, and Cloud infrastructure to reduce residual evidence.
* **Access Anonymization:** Using proxy servers, Tor networks, anonymization services, traffic padding, and anonymous communication channels.

## 10. Defending Against Covering Tracks
To ensure incident response capabilities aren't blinded by attackers, organizations should:

* **Activate Logging:** Enable it on all critical systems.
* **Periodic Audits:** Review access policies ensure `logging` settings follow security policy.
* **Log Rotation Constraints:** Ensure new events do not overwrite old entries when storage limits hit.
* **Strict Permissions:** Configure minimal correct permissions for reading/writing logs.
* **Centralize Logs (DMZ):** Forward all logs off-site to a highly secure separate logging server in the DMZ.
* **Update / Patch:** Regularly update OS, software, and firmware.
* **Close Open Ports:** Close unused services.
* **Immutable Logs / Encryption:** Encrypt log files to prevent decryption/modification without a key.
* **Append-Only Logs:** Ensure configurations prevent standard users or malicious admins from modifying/deleting.
* **Unalterable Backups:** Periodically backup logs to unalterable media.
* **Restricted ACLs:** Use Access Control Lists to lock down log files.
* **Implement SIEM:** Use Security Information and Event Management (SIEM) tools for real-time analysis of suspicious log modifications.
* **Deploy FIM:** Set up File Integrity Monitoring to catch unauthorized changes to system architectures.
* **Utilize IDS/IPS:** Monitor network activities for policy violations.
* **Utilize UEBA:** Implement User and Entity Behavior Analytics to catch anomalies pointing to covered tracks.
