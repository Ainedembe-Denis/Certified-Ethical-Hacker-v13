## 1. What is Privilege Escalation?

**Privileges** are security roles assigned to users for using specific programs, features, OS functions, or files — they limit access by user type. A **privilege escalation attack** is the process of gaining more privileges than were initially acquired.

Attackers first gain access using a **non-admin user account**, then try to gain administrative privileges by exploiting design flaws, programming errors, bugs, and configuration oversights in the OS and applications.

> 💡 Once an attacker gains admin access, they can: view sensitive information, delete files, or install malicious programs (viruses, Trojans, worms).

### Types of Privilege Escalation

| Type | Description | Example |
| :--- | :--- | :--- |
| **Horizontal** | Unauthorized user accesses resources of another user with *similar* access permissions. | Online banking user A accessing user B's bank account. |
| **Vertical** | Unauthorized user gains access to resources of a user with *higher* privileges (admin). | Normal banking user accessing administrative site functions. |

## 2. Privilege Escalation Using DLL Hijacking

Most Windows applications do not use a fully qualified path when loading an external DLL library — they first search the directory from which they were launched. Attackers exploit this by placing a **malicious DLL** in the application directory, so the application executes it in place of the real one.

> **Example:** If `app.exe` needs `library.dll` (normally in `C:\Windows\System32`) but the path is not specified, Windows searches the launch directory first. If the attacker has placed a malicious `library.dll` there, it loads instead.

## 3. Privilege Escalation by Exploiting Vulnerabilities

Attackers exploit **software vulnerabilities** — programming flaws in programs, services, or kernel — to execute malicious code with elevated privileges. This can allow them to:
- Execute commands or binaries with higher privileges than existing ones.
- Bypass security mechanisms.
- Access privileged user accounts and credentials.

Attackers search for exploits based on the target OS and installed applications using:
- 🔗 **Exploit Database** (https://www.exploit-db.com)
- 🔗 **VulDB** (https://vuldb.com)

## 4. Privilege Escalation Using Dylib Hijacking (macOS)

Similar to Windows DLL hijacking, macOS is vulnerable to **dynamic library (dylib) hijacking**. macOS provides legitimate methods (e.g., setting the `DYLD_INSERT_LIBRARIES` environment variable) that force the loader to load malicious libraries into a target running process.

macOS allows the loading of **weak dylibs dynamically**, which allows an attacker to:
- Place a malicious dylib in a specified location.
- Inject it into primary directories and load it at runtime.

**Malicious activities enabled:**
- Stealthy persistence
- Runtime process injection
- Bypassing security software
- Bypassing macOS Gatekeeper

> 🔗 **Dylib Hijack Scanner** (https://objective-see.com): Scans for applications susceptible to or already hijacked via dylib attacks.

## 5. Privilege Escalation Using Spectre and Meltdown

**Spectre** and **Meltdown** are CPU-level vulnerabilities found in the design of modern processors — AMD, ARM, Intel, Apple, Samsung, and Qualcomm — caused by performance optimization features (speculative execution, branch prediction, caching).

Attackers exploit these to steal critical system information such as login credentials, secret keys, keystrokes, and encryption keys stored in application memory.

### Spectre Vulnerability
- Tricks a processor into performing **speculative execution** to read restricted data.
- The processor is forced to execute a speculative read **before** bound checking is performed → attacker can read out-of-bounds memory.
- Can be used to read adjacent process memory and extract confidential info (e.g., credentials stored in a browser).
- In certain cases, can read **kernel memory** or perform **JavaScript-based web attacks**.

### Meltdown Vulnerability
- Found specifically in **Intel** and **ARM (Apple)** processors.
- Tricks a process into accessing out-of-bounds memory using CPU speculative execution.
- **How it works:** Attacker requests an illegal memory location + a valid conditional read. Speculative execution evaluates both before privilege checking. The results remain in **cache memory**, even after the processor rejects them. Attacker then sends multiple valid requests to access those out-of-bounds locations.
- Allows an unprivileged process to read kernel memory and physical memory → reveals credentials, private keys, etc.

**Detection Tools:**

| Tool | URL | Description |
| :--- | :--- | :--- |
| **InSpectre** | https://www.grc.com | Examines and discloses any Windows system's hardware and software capability to prevent Meltdown and Spectre attacks. |
| **Spectre & Meltdown Checker** | https://github.com | Shell script to determine whether a Linux system is vulnerable against various "speculative execution" CVEs. Detects backported mitigations. |
| **INTEL-SA-00075 Detection Tool** | (Intel) | Detects specific Intel ME vulnerabilities related to Spectre/Meltdown. |

## 6. Privilege Escalation Using Named Pipe Impersonation

In Windows, **named pipes** are used for legitimate inter-process communication (IPC) via files. The process that creates a pipe acts as the **pipe server**; any other process that connects to it becomes a **pipe client**.

> **The exploit:** When a client connects to a pipe, the server can utilize the **access privileges and security context of the pipe client**. Attackers create a pipe server with fewer privileges and trick a high-privilege client into connecting — then impersonate the client's elevated privileges.

**Metasploit commands used:**
```console
# After obtaining an active Meterpreter session:
meterpreter > getsystem          # Attempts to elevate to SYSTEM via named pipe impersonation
meterpreter > getuid             # Verifies current privileges
meterpreter > hashdump           # Dumps password hashes of admin/user accounts
```

## 7. Privilege Escalation by Exploiting Misconfigured Services

If attackers cannot find zero-day exploits, they abuse **misconfigured system services** to elevate privileges. Tools used: **Metasploit** (for session) + **PowerSploit** (to detect misconfigurations).

### Unquoted Service Paths
Windows searches for a service executable by checking folders in the path sequentially if the path is not enclosed in quotes. Attackers exploit services with **unquoted paths running under SYSTEM privileges** to place a malicious binary in a searched directory.

```powershell
# Detect unquoted service paths using PowerSploit:
Get-ServiceUnquoted
```

### Service Object Permissions
A misconfigured service permission may allow an attacker to **modify or reconfigure the service**, change the binary path to a malicious executable, or even add new users to the local administrator group.

```powershell
# Detect misconfigured service permissions:
Get-ModifiableServiceFile
Get-ModifiableService
```

### Unattended Installs
Unattended Windows installs store configuration settings in **`Unattend.xml`**, which may contain **credentials in decoded/plaintext form**. If an attacker gains access to this file, they can obtain credential information.

**Locations of `Unattend.xml`:**
```
C:\Windows\Panther\
C:\Windows\Panther\UnattendGC\
C:\Windows\System32\
C:\Windows\System32\sysprep\
```

```powershell
# Detect unattended install files:
Get-UnattendedInstallFile
```

## 8. Pivoting and Relaying to Hack External Machines

After compromising a system, attackers use **pivoting** and **relaying** to expand their reach into the rest of the target network.

| Technique | What it does |
| :--- | :--- |
| **Pivoting** | Opens a remote shell on a target *tunneled through* the initially compromised system. Only exploits systems accessible through the compromised system. |
| **Relaying** | Accesses *resources* on other systems through a tunneled shell session on the compromised system. |

### Pivoting Steps (with Metasploit)

**Step 1: Discover live hosts**
```console
meterpreter > run post/windows/gather/arp_scanner RHOSTS <target subnet range>
```

**Step 2: Set up routing rules**
```console
meterpreter > background
msf > route add <IP address> <subnet mask> <session number>
# Example: route all traffic to 10.10.10.0/24 through Meterpreter session 1
```

**Step 3: Port scan live systems**
```console
msf > use auxiliary/scanner/portscan/tcp
msf > set RHOSTS <IP addresses>
msf > set PORTS 1-1000
msf > run
```

**Step 4: Exploit vulnerable services**
```console
# Example: Bypass UAC on a found target
msf > use exploit/windows/local/bypassuac
```
> A successful session is established to the vulnerable system **pivoting through the compromised host** — the target cannot determine the actual origin of the exploitation.

### Relaying Steps (Port Forwarding via Meterpreter)

**Step 1: Set up port forwarding rules**
```console
meterpreter > portfwd add -l 10080 -p 80 -r <Target IP>
meterpreter > portfwd add -l 10022 -p 22 -r <Target IP>
meterpreter > portfwd add -l 10445 -p 445 -r <Target IP>
```

**Step 2: Access the system resources**
```bash
# Browse HTTP server on the target
http://localhost:10080

# Access SSH server on the target
ssh myadmin@localhost -p 10022
```

## 9. Privilege Escalation Using Misconfigured NFS

NFS (Network File System) is a protocol for sharing files over a network using **port 2049** via RPC. A **misconfigured NFS** allows attackers to gain root-level access through a regular/low-privilege user account.

### Steps to Gain Root Access via Misconfigured NFS

```bash
# Step 1: Check if NFS service is running on the target
nmap -sV <Target IP Address>

# Step 2: Install NFS client utilities
sudo apt-get install nfs-common

# Step 3: List available NFS shares on the target
showmount -e <Target IP Address>

# Step 4: Create a local mount directory
mkdir /tmp/nfs

# Step 5: Mount the target NFS share locally
sudo mount -t nfs <Target IP Address>:/<Share Directory> /tmp/nfs

# Step 6: View mounted directory and check permissions
cd /tmp/nfs
sudo cp /bin/bash .
ls -la

# Step 7: Establish SSH connection to the target
ssh -l <Target Login Name> <Target IP Address>
```

## 10. Privilege Escalation by Bypassing UAC

When attackers fail to escalate privileges using a simple payload, they attempt to evade Windows **User Account Control (UAC)** to gain SYSTEM-level access. Even if UAC protection level is set to any option, some Windows applications can be abused to escalate privileges **without triggering a UAC notification**.

### UAC Bypass Techniques via Metasploit

| Metasploit Module | Technique | Description |
| :--- | :--- | :--- |
| `exploit/windows/local/bypassuac` | Process Injection | Bypasses UAC through process injection; generates another session without a UAC flag. |
| `exploit/windows/local/bypassuac_injection` | Reflective DLL Memory Injection | Uses reflective DLL mechanisms to inject DLL payload binaries only → obtains `AUTHORITY\SYSTEM`. |
| `exploit/windows/local/bypassuac_fodhelper` | FodHelper Registry Key | Hijacks a special key from `HKCU` registry hive and attaches it to `fodhelper.exe`. |
| `exploit/windows/local/bypassuac_eventvwr` | Eventvwr Registry Key | Hijacks a `HKCU` registry key; custom commands execute when Event Viewer launches. Key is wiped after execution. |
| `exploit/windows/local/bypassuac_comhijack` | COM Handler Hijack | Builds COM handler registry entries in the current user hive. References high-level processes to load attacker-controlled DLLs. |

**After bypassing UAC:**
```console
meterpreter > getsystem    # Escalate to SYSTEM
meterpreter > getuid       # Verify SYSTEM-level access
```

## 11. Privilege Escalation by Abusing Boot or Logon Initialization Scripts

Attackers take advantage of **boot or logon initialization scripts** to escalate privileges or maintain persistence. Based on configuration settings, attackers can escalate privileges via local or admin accounts.

| Script Type | Platform | Details |
| :--- | :--- | :--- |
| **Logon Script (Windows)** | Windows | OS executes logon scripts when a user signs in. Attackers embed their script path here: `HKEY_CURRENT_USER\Environment\UserInitMprLogonScript` |
| **Logon Script / Login Hooks (macOS)** | macOS | Login hooks execute automatically on system login. The hook runs as **root**, so attackers leverage this to inject malicious payloads for persistence and privilege escalation. |
| **Network Logon Scripts** | Network (AD/GPO) | Allocated using AD or GPOs; executed using any valid user's credentials → can target multiple networked systems. |
| **RC Scripts** | Unix/Linux | Executed during system startup (`rc.common`, `rc.local`). Attackers embed malicious binary paths into these scripts → gain root access on reboot. |
| **Startup Items** | macOS | Run at the last stage of booting. Attackers create malicious files in `/Library/StartupItems/` → executed as root at bootup. The config file is `StartupParameters.plist`. |

## 12. Privilege Escalation by Modifying Domain Policy

Attackers modify the target domain's configuration settings to bypass security solutions and implant a **fake domain controller (DC)** to maintain a foothold and escalate privileges.

### Group Policy Modification
All user accounts have **read access** to GPOs by default; write access is restricted to specific users/groups.

| GPO Path | Attack |
| :--- | :--- |
| `\\<DOMAIN>\SYSVOL\<DOMAIN>\Policies\` | Access and modify group policies to create new accounts, disable internal tools, extract passwords in plaintext. |
| `<GPO_PATH>\Machine\Preferences\ScheduledTasks\ScheduledTasks.xml` | Modify to create a malicious scheduled task using scripts like `New-GPOImmediateTask`. |
| `<GPO_PATH>\MACHINE\Microsoft\Windows NT\SecEdit\GptTmpl.inf` | Modify user rights such as `SeEnableDelegationPrivilege` to create backdoors. |

### Domain Trust Modification
```cmd
# Collect information about trust domains:
nltest /domain_trusts

# Then: add a domain trust or modify existing trust settings to escalate privileges
# via Kerberoasting or pass-the-ticket attacks
```

## 13. Retrieving Password Hashes of Other Domain Controllers Using DCSync Attack

A **DCSync attack** exploits the Active Directory replication mechanism. An attacker with **domain replication rights** creates a virtual DC-like process to request (and receive) password hashes from real DCs without touching the DC directly.

### DCSync Attack Stages

| Stage | Action |
| :--- | :--- |
| 1 | External reconnaissance |
| 2 | Compromise the targeted machine |
| 3 | Internal reconnaissance |
| 4 | Escalate local privileges |
| 5 | Compromise credentials by sending commands to the DC |
| 6 | Admin-level reconnaissance |
| 7 | Malicious remote code execution |
| 8 | Gain domain admin credentials |

### Access Rights Required
Attackers need at least one of these AD rights to perform DCSync:
- **Replicating Directory Changes**
- **Replicating Directory Changes All**
- **Replicating Directory Changes in Filtered Set**

### How Attackers Compromise the Domain Controller (DC)

> This is how the DCSync attack is executed once the attacker has the required replication privileges:

1. The attacker **identifies the DC to compromise** and prepares a replication request.
2. Deploys tools such as **Mimikatz** to replicate the DC — or directly sends a `GetNCChanges` command as a request for replication of information on the DC.
3. The DC **accepts the request**, acknowledges the replication, and **hands over NTLM password hashes** to the attacker.
4. The attacker uses those hashes for **golden ticket attacks**, account manipulation, ransomware deployment, and LOTL (Living off the Land) attacks.

### DCSync Attack Tool: Mimikatz
🔗 **Source:** https://github.com/gentilkiwi/mimikatz

Mimikatz is a command-line tool that uses the **Microsoft Directory Replication Service Remote Protocol (MS-DRSR)** to replicate the behavior of a legitimate DC.

```bash
# Retrieve NTLM password hashes of an Administrator account:
mimikatz "lsadump::dcsync /domain:<domain name> /user:Administrator"
```

## 14. Privilege Escalation by Abusing Active Directory Certificate Services (ADCS)

**Active Directory Certificate Services (ADCS)** implements a PKI within the AD ecosystem for managing certificates. **Misconfigured ADCS templates** can lead to critical vulnerabilities allowing attackers to steal credentials, escalate domain privileges, and establish persistence.

**Tool used:** 🔗 **Certipy** (https://github.com/ly4k/Certipy)

### Steps to Abuse ADCS

```bash
# Step 1: Enumerate misconfigured ADCS templates (outputs JSON + TXT)
certipy find -u '<target_user>@<domain>' -p <password> -dc-ip <DC_IP> -vulnerable -enabled

# Step 2: Find ESC1 escalation opportunities
grep ESC1 certipy_output.txt

# Step 3: Request a certificate impersonating a domain admin via vulnerable template
certipy req -u '<username>@foobar.com' \
            -p '<PASSWORD>' \
            -dc-ip '<DC IP>' \
            -target '<target domain>' \
            -ca 'foobar-CA' \
            -template '<template name>' \
            -upn '<target admin UPN>'
```

> ⚠️ **ESC1 vulnerability:** Allows users with limited privileges to enroll and request certificates **for any specified domain object**, including domain administrators.

## 15. Other Privilege Escalation Techniques

| Technique | Platform | How It Works |
| :--- | :--- | :--- |
| **Access Token Manipulation** | Windows | Modify Windows access tokens to make a process appear to belong to a different user. Use `runas` or create spoofed tokens to acquire the security context of a privileged user. |
| **Parent PID (PPID) Spoofing** | Windows | Spoof the parent process ID (PPID) of a new process via the `CreateProcess API` to bypass tools that analyze parent-child relationships and evade security monitoring. |
| **Application Shimming** | Windows | Abuse the Windows Application Compatibility Framework (shims) to hook API calls. Some shims can bypass UAC (`RedirectEXE`), inject malicious DLLs (`InjectDLL`), etc. Shim database stored at `%WINDIR%\AppPatch\sysmain.sdb`. |
| **Filesystem Permission Weakness** | Windows | Replace original binaries (with world-writable permissions) with malicious binaries. If the service executes the binary as SYSTEM, the malicious binary also runs as SYSTEM. |
| **Path Interception** | Windows | Place a malicious executable in a directory that is searched early in the PATH before the legitimate binary. Leverages unquoted paths, PATH misconfiguration, or search order hijacking. |
| **Abusing Accessibility Features** | Windows | Replace accessibility feature executables in `C:\Windows\System32\` (e.g., Sticky Keys `sethc.exe`, Narrator `Narrator.exe`) with `cmd.exe` — executed at the login screen with SYSTEM privileges. |
| **SID-History Injection** | Windows/AD | Inject the SID value of an administrator account into the compromised user's SID-history attribute → grants that user elevated privileges and access to restricted resources. |
| **COM Hijacking** | Windows | Tamper with Component Object Model (COM) references in the registry. Replace legitimate COM DLLs/executables with malicious payloads that execute when the legitimate COM object is called. `HKCU\Software\Classes\CLSID\` is loaded before `HKLM` registry. |
| **Scheduled Tasks (Windows)** | Windows | Abuse `at` or `schtasks` utilities to schedule malicious programs to execute at startup, maintain persistence, or perform remote execution as SYSTEM. |
| **Scheduled Tasks / Cron (Linux)** | Linux | Abuse `cron` (`/etc/crontab`) to inject malicious scripts that run automatically on reboot with root privileges. |
| **Launch Daemon** | macOS | Install a new launch daemon configured to execute at boot using `launchd`/`launchctl` with a malicious plist file in `/Library/LaunchDaemons/`. |
| **Plist Modification** | macOS | Modify plist files in `/Library/Preferences/` (high privilege) or `~/Library/Preferences/` (user privilege) to execute malicious code on behalf of a legitimate user. |
| **Setuid and Setgid** | Linux/macOS | Exploit SUID/SGID-flagged binaries to run them with the owner's elevated privileges. Commonly abused binaries: `nmap`, `vim`, `less`, `bash`, `find`, `nano`, `cp`, etc. |
| **Web Shell** | All (Web) | Inject a malicious web-based script on a web server to maintain persistent access and escalate privileges by exploiting local vulnerabilities. |
| **Abusing Sudo Rights** | Linux/Unix | If attacker has sudo rights for a binary with file-write capability (e.g., `cp`), they can overwrite `/etc/sudoers` or `/etc/shadow` to grant full root access. |
| **Abusing SUID/SGID Permissions** | Linux | Find SUID/SGID binaries and abuse them to spawn a root shell. |
| **Kernel Exploits** | Linux | Exploit kernel vulnerabilities to execute arbitrary code with superuser privileges. |
| **Abusing '.' in PATH** | Linux/Unix | A '.' in the PATH means the current directory is searched first. Attacker places a malicious script named `ls` (or similar) in a directory → when a privileged user runs `ls`, the malicious version executes. |
| **Abusing Elevation Control (macOS)** | macOS | Abuse `AuthorizationExecuteWithPrivileges` API to gain root privileges without source validation. Programs using this API may also load world-writable files susceptible to malicious modification. |
| **Process Injection via Ptrace** | Linux | Use `ptrace()` system calls to inject malicious code into a running process (`PTRACE_POKETEXT`/`PTRACE_POKEDATA`) and manipulate registers (`PTRACE_SETREGS`) to redirect execution. |
| **Abusing MSI Files** | Windows | Exploit MSI "repair" functionality. Poorly configured `Custom Actions` running as `NT AUTHORITY\SYSTEM` can be triggered by standard users → allows file operations and arbitrary code execution as SYSTEM. |
| **NoFilter Attack (WFP)** | Windows 11 | Exploit the Windows Filtering Platform (WFP) to retrieve the handle of an access token from another SYSTEM-level process, duplicate it, and use it to escalate privileges without triggering detection. |

### Useful Commands for Specific Techniques

## 17. How to Defend against Privilege Escalation

> 💡 **Core principle:** Ensure users have the **lowest possible privileges** needed to use their system effectively (Principle of Least Privilege).

- Restrict interactive logon privileges.
- Run users and applications with the lowest privileges.
- Implement **multi-factor authentication (MFA)** and authorization.
- Run services as unprivileged accounts.
- Implement a privilege separation methodology to limit scope of programming errors.
- Use encryption to protect sensitive data.
- Reduce the amount of code that runs with a particular privilege.
- Perform debugging using bounds checkers and stress tests.
- Thoroughly test the system for application coding errors and bugs.
- **Regularly patch and update the kernel.**
- Change UAC settings to **"Always Notify"** to increase visibility of UAC elevation requests.
- Restrict users from writing files to the search paths for applications.
- Continuously monitor file-system permissions using auditing tools.
- Reduce privileges of user accounts and groups so only legitimate administrators can make service changes.
- Use **whitelisting tools** to identify and block malicious software.
- Use fully qualified paths in all Windows applications.
- Ensure all executables are placed in **write-protected directories**.
- In macOS, **prevent plist files from being altered** by making them read-only.
- Block unwanted system utilities or software that may be used to schedule tasks.
- **Regularly patch and update web servers.**
- Disable the default local administrator account.
- Detect, repair, and fix any flaws running in system services.
- Keep files read-only; provide write access only to users/groups that require it.
- Incorporate the provisioning and de-provisioning of accounts to prevent hijacking of orphaned accounts.
- Enable **Data Execution Prevention (DEP)** in Windows to block executable code requests.
- Regularly review and audit elevated accounts to ensure authorized access.
- Enforce **temporary or time-limited credentials** for privileged account access.
- Implement code signing and verification to authenticate applications and scripts.
- Enable **session recording and monitoring** to track privileged user activities.
- Test patches in a secured environment before deploying to production.
- Implement **JIT (Just-in-Time) access** for privileged users to limit access time.
- Frequently audit and update ACLs.
- Configure **Role-Based Access Control (RBAC)** to restrict access based on roles.
- Regularly scan IT infrastructure components to identify and patch misconfigurations.
- Harden system configurations (disable unnecessary services, remove unused software).
- Implement **application whitelisting** to allow only approved software to run.
- Adopt a **Zero-Trust security model** that assumes breach and verifies every request.

## 18. Defend against Abuse of Sudo Rights

- Implement a strong password policy for sudo users.
- Turn off password caching by setting `timestamp_timeout` to `0` — users must input password every time sudo is executed:
  ```bash
  Defaults timestamp_timeout=0    # Add to /etc/sudoers
  ```
- Separate sudo-level administrative accounts from the administrator's regular accounts.
- Update user permissions and accounts at regular intervals.
- Test sudo users with access to programs containing parameters for arbitrary code execution.
- Monitor sudo user logins and configuration alerts.
- Implement sudo logging and centralize the logs for analysis.

## 19. Defend against DCSync Attacks

- Examine permissions assigned to users and administrators. Keep track of accounts that request domain replication rights.
- Conduct security awareness training on system configuration, patch management, and threat detection.
- Deploy network surveillance tools (e.g., **Sean Metcalf**, **StealthDEFEND**) to track DC IP addresses and validate which IPs should be in the replication list.
- **Limit the "Replicate Directory Changes" permission** to only authorized users and service accounts.
- Regularly audit and review ACL-based misconfigurations.
- Deploy **deception technologies** such as honeypots and decoy credentials within the AD environment.

## 20. Defend against PPID Spoofing

- Verify PPID fields where information is stored to detect irregularities.
- Identify the legitimate parent process using the event header PID specified by ETW (Event Tracing for Windows).
- Periodically analyze Windows API calls such as `CreateProcess` for malicious PIDs.
- Monitor system API calls that assign PPIDs to new processes.
- Limit users and application permissions to create processes.
- Implement **application allowlisting** to reduce the attack surface and limit PPID spoofing.

## 21. Defend against Exploiting AD Certificate Services

- Keep the AD infrastructure (including AD CS servers and DCs) up to date with the latest security patches.
- Implement **Privileged Access Management (PAM)** solutions to control and monitor administrative access to AD CS servers.
- Use **multi-factor authentication (MFA)** to protect administrative accounts.
- Apply security baselines to harden the security configuration of AD CS servers.
- Implement **network segmentation** to isolate AD CS servers from untrusted networks.
- Use firewalls, network ACLs, and other network security controls.
- Follow the **principle of least privilege** by limiting administrative access to AD CS components.

## 24. Defending against Spectre and Meltdown

- Regularly **patch/update OSs and firmware**.
- Enable **continuous monitoring** of critical applications and services.
- Regularly patch vulnerable software such as **web browsers**.
- Install and update **ad-blockers and anti-malware** to block malware injection through compromised websites.
- Enable **traditional endpoint security tools** to prevent unauthorized system access.
- Block services and applications that allow **unprivileged users to execute code**.
- Never install unauthorized software or access untrusted websites from systems storing sensitive information.
- Use **Data Loss Prevention (DLP)** solutions to prevent leakage of critical runtime memory information.
- Frequently check with the **manufacturer for BIOS updates** and install them as instructed.
- Implement advanced hardware and software mitigations such as **speculative taint tracking**.
- Implement **Homomorphic Encryption (HME)** to securely handle crucial information.
- Ensure proper configuration of **virtualized CPU (vCPU)** environments.
- Utilize compiler options designed to mitigate Spectre vulnerabilities, such as **Retpoline** (a software construct) and **speculative load hardening**.
