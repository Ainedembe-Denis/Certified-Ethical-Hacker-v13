## 🕵️ HIDING FILES

After an attacker has performed malicious operations on a target system to gain escalated privileges, they embed and hide their malicious programs. The attacker can do this using rootkits, NTFS stream, and Steganography techniques, to prevent the malicious program from protective applications such as antivirus, anti-malware, and anti-spyware. Such a hidden malicious file allows the attacker to maintain their direct access to the system, even in the future, without the victim’s consent.

### 1. Rootkits

Rootkits are software programs designed to gain access to a computer without being detected. They exploit vulnerabilities in the OS to build a backdoor login process. Once the user enables root access, a rootkit may attempt to hide the traces of unauthorized access by modifying drivers or kernel modules and discarding active processes.

**How Attackers Place a Rootkit:**
- Scanning for vulnerable computers and servers on the web
- Wrapping the rootkit in a special package like a game
- Installing it on public/corporate computers through social engineering
- Launching zero-day attacks (privilege escalation, kernel exploitation, etc.)
- Sending phishing emails to trick users

**Objectives of a Rootkit:**
- To root the host system and gain remote backdoor access
- To mask attacker tracks and presence of malicious applications
- To gather sensitive data/network traffic
- To store other malicious programs and act as a bot server resource
- To secure continued access across reboots, system updates, or removals
- To spy on the user's activity (keystrokes, screenshots, or traffic)

#### Types of Rootkits

| Type | Description |
| :--- | :--- |
| **Hypervisor-Level** | Exploits hardware features (Intel VT, AMD-V) to run in Ring-1 and host the target OS as a VM, intercepting all hardware calls. |
| **Hardware/Firmware**| Hides in firmware (HDD, BIOS, network card) persistently since users do not inspect it for code integrity. |
| **Kernel-Level** | Runs in Ring-0 with highest OS privileges. Substitutes portions of kernel code or drivers to subvert OS operations. |
| **Boot-Loader-Level**| (Bootkits) Modify or replace the legitimate boot loader. Activates before the OS starts, ideal for hacking encryption keys. |
| **Application-Level**| Runs in Ring-3. Replaces standard application binaries or modifies application behaviors with patches/injected code. |
| **Library-Level** | Works high up in the OS to patch, hook, or supplant system calls with backdoor versions, hiding attacker information. |
| **Memory Rootkits** | Volatile rootkits residing solely in RAM without leaving traces on the disk. Highly elusive. |

#### How a Rootkit Works

Rootkits often use **System Hooking**, replacing the original function pointer with a rootkit pointer. 
- **Inline Function Hooking:** Modifies bytes of a function inside core DLLs (`kernel32.dll` and `ntdll.dll`) so process calls hit the rootkit first.
- **DKOM (Direct Kernel Object Manipulation):** Modifies kernel memory structures to hide processes, ports, or privileges by unlinking a process from the system process list and tricking the Windows event viewer.

*(Other popular rootkits: CopperStealer, Syslogk, Stealthy Universal Rootkit, Reptile, CosmicStrand)*

#### Detecting Rootkits

| Detection Method | Description |
| :--- | :--- |
| **Integrity-Based** | Compares current filesystem/memory snapshots against a clean, trusted baseline using tools like Tripwire or AIDE. |
| **Signature-Based** | Compares system processes/executables against a database of known rootkit sequence. Lower success against invisible rootkits. |
| **Heuristic/Behavioral**| Identifies deviations in normal OS patterns (e.g., Execution path hooking) to detect new rootkits. |
| **Runtime Execution**| Compares runtime execution profiling before and after a certain routine to find destabilized path instructions. |
| **Cross-View-Based** | Enumerates system files via APIs and compares the results against raw dataset traversing to identify DKOM hooks. |
| **Alternative Trusted Medium**| Shut down the infected system and boot from a clean USB drive to manually check storage for hidden traces. |
| **Analyzing Memory Dumps**| Create a static snapshot of RAM to detect/analyze active volatile rootkits. |
| **Virtualization-Based**| Deploy hypervisor security introspection to monitor guest OS VMs for virtual rootkit activity. |

**Steps to Manually Detect Rootkits:**
1. **Filesystem:** Run `dir /s /b /ah` and `dir /s /b /a-h` inside the infected OS. Reboot into a clean USB, run the same commands, and compare both using **WinMerge** to spot ghostware.
2. **Registry:** Export `SOFTWARE` and `SYSTEM` standard hives text files. Reboot into a clean USB (WinPE), natively mount and export the offline compromised registry hives, then compare using **WinMerge** to detect stealth configuration entries.

#### How to Defend Against Rootkits
- Reinstall OS/applications from a trusted source after backing up critical clean data.
- Regularly verify system file integrity using cryptographic digital fingerprints (like `MD5sum.exe`).
- Apply kernel memory dump analysis for signs of compromise.
- Install network and host-based firewalls, enforcing Principle of Least Privilege.
- Use Endpoint Threat Detection equipped with Machine Learning (ML) behavioral heuristics.
- Implement Application Whitelisting and use Secure Boot (verifies OS loader integrity).

### 2. NTFS Data Streams

NTFS utilizes Alternate Data Streams (ADS) to attach metadata to a file. A normal file has its primary data stream and security descriptor stream. ADS allows an attacker to inject and hide malicious code (like an `.exe`) behind a generic file (like `.txt`) without altering the visible file size, functionality, or display in standard Windows Explorer. The Master File Table connects the specific data stream to its physical disk location.

#### Creating and Manipulating NTFS Streams

**Creating ADS files using Notepad:**
```cmd
notepad myfile.txt:lion.txt
notepad myfile.txt:tiger.txt
```
*(The filesize of `myfile.txt` will remain exactly original, i.e., zero bytes).*

**Hiding and Executing a Trojan via ADS in an existing text file:**
```cmd
# 1. Hide Trojan in Readme text file
type c:\Trojan.exe > c:\Readme.txt:Trojan.exe

# 2. Create a symbolic link to the hidden executable stream
mklink backdoor.exe Readme.txt:Trojan.exe

# 3. Execute the Trojan via the shortcut
backdoor.exe
```

#### NTFS Stream Detectors

| Tool | Feature / Use Case | URL |
| :--- | :--- | :--- |
| **Stream Armor** | Discovers hidden ADS and cleans them using advanced auto-analysis and online threat verification. | [securityxploded.com](https://securityxploded.com) |
| **Stream Detector** | File-monitoring software to flag ADS streams. | [novirusthanks.org](https://www.novirusthanks.org) |
| **GMER** | Detects inline hooks and NTFS streams. | [gmer.net](http://www.gmer.net) |
| **ADS Scanner** | Robust NTFS alternative data stream scanning. | [pointstone.com](https://www.pointstone.com) |
| **Streams** | Sysinternals command-line utility to identify ADS. | [learn.microsoft.com](https://learn.microsoft.com) |
| **AlternateStreamView**| GUI utility by NirSoft to view all hidden streams. | [nirsoft.net](https://www.nirsoft.net) |

#### Defending against NTFS Streams
- Move suspected files to a File Allocation Table (FAT) partition. FAT strips ADS functionality and erases the stream data. Or copy to FAT and back.
- Use File Integrity Checkers like Tripwire to manage NTFS partitions against unauthorized streams.
- Utilize real-time monitoring software like EventSentry SysAdmin or ADSlist.
- Ensure the firewall is configured to block malicious outbound stream payloads.

### 3. Steganography

**Steganography** refers to the art of hiding data *behind* other data without the victim's knowledge to circumvent security policies. It hides the *existence* of a message, replacing bits of unused data in ordinary carrier files (e.g. graphics, sound, text, video). Compared to encryption, detection of steganography is significantly harder.

#### Classification of Steganography

**A. Technical Steganography (Physical/Chemical):**
- **Invisible Ink:** Fluid logic using colorless liquids (e.g., onion juice) visible upon heating/lighting.
- **Microdots:** Condensed text/image fitting into a single millimeter dot via a reverse microscope.
- **Computer-Based Methods (6 groups):**
  1. *Substitution Techniques:* Replaces insignificant bits (LSB) with secret info.
  2. *Transform Domain Techniques:* Hides info in significant areas using processing techniques (cropping/compression).
  3. *Spread Spectrum Techniques:* Spreads signals over broad frequencies independently of data (DSSS/FHSS).
  4. *Statistical Techniques:* Manipulates statistical "1-bit" distributions in the cover.
  5. *Distortion Techniques:* Implements a sequence of modifications on the cover. Requires original cover to reverse-engineer.
  6. *Cover Generation Techniques:* Generates an entirely unique digital object specifically to hide communication.

**B. Linguistic Steganography:**
- **Semagrams:** Hides information visually using signs, physical objects, or text spaces/flourishes in fonts.
- **Open Codes:** Secret message concealed inside legitimate carrier messages (overt communication).
  - *Jargon Codes:* Specific encoded pre-arranged keywords (e.g., "cue" codes).
  - *Covered Ciphers:* Null ciphers (hidden inside large blocks of mixed/useless data) and Grille ciphers (read through a stenciled sheet placed over the plaintext).

#### Types of Steganography & Associated Tools

| Tool / Type | Description / Mechanism | Info URL |
| :--- | :--- | :--- |

| **StegoStick** *(Document)*| Specifically utilized for placing data inside `.PDF`, `.DOCX`, `.CHM`, or `.EXE` formats. | [sourceforge.net](https://sourceforge.net) |
| **OmniHide Pro** *(Video)* | Embeds huge amounts of secret data inside moving video `.AVI` / `.MPG4` frames taking advantage of Discrete Cosine Transform (DCT) and continuous noise. | [omnihide.com](https://omnihide.com) |
| **DeepSound** *(Audio)* | Conceals data inside digital sound (`WAV`, `MP3`, `FLAC`) using Echo insertion, LSB coding, Phase Encoding, Tone insertion, or Spread Spectrum frequencies. | [jpinsoft.net](https://jpinsoft.net) |

**Using Snow for Whitespace Steganography:**
```cmd

# Options:
# -C Compress, -Q Quiet mode, -S Report approximate space available, 
# -p passwd (encryption), -m message (text string to inject)
```

#### Steganalysis & Attacks

**Steganalysis** is the reverse process: determining the encoded hidden message and recovering it if possible. It relies heavily on determining size variations, format changes, modification timestamps, or altered color palettes/compression anomalies.

**Classification of Steganalysis Attacks:**
- **Stego-Only Attack:** Attacker relies solely on possessing the stego-object. Every algorithm must be bruteforced.
- **Known-Stego Attack:** Knowing both the steganography algorithm and having access to the stego-object.
- **Known-Message Attack:** Given the stego-medium and the original message, the analyst deduces the algorithm technique used.
- **Known-Cover Attack:** Having the pristine original cover and comparing it directly to the stego-object to extract differences.
- **Chosen-Message Attack:** Running a chosen message through known tools to determine matching footprint patterns.
- **Chosen-Stego Attack:** Analyst has the stego-object and algorithm.
- **Chi-Square Attack:** Probability analysis comparing a stego-object vs original data (if difference is not exactly 0, data is assumed to be embedded).
- **Distinguishing Statistical Attack:** Statistical analysis of LSB anomalies/patterns.
- **Blind Classifier Attack:** Machine learning or blind detector trained on base modifications to spot anomalies natively.

## 🚪 ESTABLISHING PERSISTENCE

Attackers establish persistence to replicate malicious instructions repeatedly securely, making sure that if the system reboots or the victim deletes individual pieces of malware, an automated backdoor channel remains fully functional.

### Maintaining Persistence Using Windows Sticky Keys

The Windows Sticky Keys feature natively allows combination keys (Ctrl, Alt, Shift) to be fired repeatedly. An attacker can replace the `sethc.exe` sticky-key executable. After escalating privileges with Metasploit (`BypassUAC`), the attacker creates a backdoor linking the `Shift` key. When Shift is pressed 5 times sequentially on the login lock screen, a full system-level Command Prompt executes automatically.

### Abusing Boot or Logon Autostart Executions

OS boot or account logon parameters systematically invoke auto-run executables.
1. **Registry Run Keys:** Attackers monitor or hijack native system registry keys with active run permissions. Using the `winPEASx64.exe quiet applicationinfo` module enumerates valid services vulnerable to execution insertion.
2. **Startup Folder:** Dropping a RAT or remote payload directly into a public startup folder. Permissions are typically validated using `icacls "C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup"` or using Sysinternals `accesschk.exe`.

### Domain Dominance Through Different Paths

Domain dominance defines taking systematic administrative control over an organization's Domain Controllers (DCs) to intercept, pocket, and weaponize access to all networked resources. Typical steps involve using a compromised admin level account to execute actions:

1. **Remote Code Execution:** Creating and appending dummy AD processes using WMI or PsExec directly.
   ```cmd
   wmic /node:<DomainControllerName> process call create "net user /add PiratedProcess Du^^Y01"
   PsExec.exe \\<DomainControllerName> -accepteula net localgroup "Admins" PiratedProcess /add
   ```
2. **Abusing Data Protection API (DPAPI):** The DPAPI stores browser passwords and cryptography uniformly. A DC master key decrypts DPAPI universally. Using `mimikatz`:
   ```cmd
   # Get Master Key from Password
   dpapi::masterkey /in:"C:\Users\...\Protect\S-1-5-21-...\3e90dd9e..." /sid:S-1-5-21-... /password:**** /protected
   # Retrieve Backup/Local Master Key 
   sekurlsa::dpapi
   lsadump::backupkeys /system:<DCName> /export
   ```
3. **Malicious Replication:** Emulating a DCSync behavior to copy sensitive user profiles (like the Kerberos core `krbtgt`).
   ```powershell
   Invoke-Mimikatz -command '"lsadump::dcsync /domain:<TargetDomain> /user:krbtgt"'
   ```
4. **Skeleton Key Attack:** A memory-resident malware injected directly into the DC's Local Security Authority Server Service (LSASS). It mints a universal skeleton key (a master password) allowing domain-wide login under any username. Automatable using the Metasploit/Empire toolsets or `mimikatz` `privilege::debug misc::skeleton`.
5. **Golden Ticket Attack:** Abusing Kerberos architecture. After extracting `krbtgt` NTLM hashes via DCSync, the attacker forges a comprehensive **Ticket Granting Ticket (TGT)** mapping arbitrary groups/administrators to their current dummy session, effectively asserting complete, persistent network control indefinitely.
   ```cmd
   # Execution inside mimikatz
   kerberos::golden /domain:<domain_name> /sid:<SID> /rc4:<KRBTGT_Hash> /user:<username>
   ```
6. **Silver Ticket Attack:** Identical logic to the Golden Ticket attack, but localized to a *single local service* (like an SQL backend or singular HTTP service). It explicitly bypasses involving the central Domain Controller by generating a **Ticket Granting Service (TGS)** ticket directly.
   ```cmd
   mimikatz "privilege::debug" "sekurlsa::logonpasswords"
   ```
7. **Maintain Domain Persistence Through AdminSDHolder:** Add a dummy rogue user directly to the `AdminSDHolder` group's protective `ACL`. Within 60 seconds, the active `SDProp` subsystem propagates the configuration, granting that single dummy user "GenericAll" domain-wide admin privileges persistently.
   ```powershell
   Add-ObjectAcl -TargetADSprefix 'CN=AdminSDHolder,CN=System' -PrincipalSamAccountName <RogueUser> -Verbose -Rights All
   ```

### Maintaining Persistence Through WMI Event Subscription

WMI can trigger events (Startup, File creation, UserLogon) to run arbitrary executable payloads in a completely "fileless" sequence.
- **Using Script CMD / wmic:** Creating native `EventFilter` and `CommandLineEventConsumer` blocks natively to run dropping sequences silently inside a 60-second window setup in `.cimv2`.
- **Wmi-Persistence:** Utilizing `Install-Persistence -Trigger Startup -Payload "<payload.exe>"` to trigger an interval injection setup.
- **PowerLurk:** An automated framework (`Import-Module .\PowerLurk.ps1`) for generating complex `Register-MaliciousWmiEvent` bindings automatically.

### Overpass-the-Hash Attack

The overpass-the-hash (OPtH) attack abuses the NTLM protocol limitations. A local LSASS memory dump provides the hashed password or AES keys of a target user. Using `mimikatz` (`sekurlsa::ekeys`), the attacker injects that hash code backwards into the Kerberos Ticket requesting component, essentially exchanging a hash structure directly for a fully valid Kerberos TGT without ever performing a standardized text-based logon session.

## 🛡️ HOW TO DEFEND AGAINST PERSISTENCE ATTACKS

To successfully thwart Domain Dominance and Persistence attempts, administrators must restrict execution bounds heavily and enact deep logging configurations. 

- **Restrict Accounts/Privileges:** Deploy a Minimum Privileges Access Model (Principle of Least Privilege). Prevent domain users from being populated across local administrator groups over remote subsystems and networks.
- **Enforce Kerberos Limitations:** Monitor all Active Directory replication structures rigorously and evaluate Kerberos validation paths offline explicitly. Deploy signing protocols ensuring the PAC component is successfully signed by the valid Key Distribution Center's `krbtgt` account exclusively.
- **Change Default Identifiers:** Periodically enforce resetting the highly critical `KRBTGT` password. To ensure it propagates correctly to all domain environments, execute the password reset process explicitly twice to clear any stale cache keys preventing legacy tickets from successfully authenticating rogue accounts permanently.
- **Pass-the-Hash Restrictions:** Implement deep User Account Control (UAC) limitations specifically focused on external connection interfaces. Configure the registry `LocalAccountTokenFilterPolicy` appropriately to enact Pass-the-Hash protections.
- **Network Boundaries:** Configure internal Application Sandboxing structures systematically while clamping down inbound/outbound Windows Firewall filtering protocols strictly.
- **Deep Auditing:** Enforce advanced Endpoint logging procedures across infrastructure systems utilizing Advanced Threat Protection (ATP) alongside sophisticated Intrusion Detection Systems (IDS) employing predictive heuristic and behavioral profiling explicitly observing Registry and Task Scheduling edits.
- **Education/Hygiene:** Ensure widespread end-user training on zero-day phishing prevention methodologies. Revert all operational actions to encrypted, authenticated network tunnels (VPNs). Shut down all unused/extraneous port configurations aggressively.
