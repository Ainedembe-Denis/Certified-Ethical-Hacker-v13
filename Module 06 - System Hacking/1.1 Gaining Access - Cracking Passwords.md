## 1. Windows Authentication & Extracting Hashes

Windows authenticates its users with the help of three primary Microsoft protocols:

- **Security Accounts Manager (SAM) Database:** Windows manages user accounts and passwords in hashed format (a one-way hash). The SAM is implemented as a registry file locked by the Windows kernel at `%SystemRoot%\system32\config\SAM` and mounted under `HKEY_LOCAL_MACHINE\SAM`. It uses an **SYSKEY** function to partially encrypt password hashes.
- **NTLM Authentication:** A challenge/response strategy. The client encrypts a 16-byte random character string (a "nonce") provided by the Domain Controller with the hash of the user password. The DC retrieves the user's hash from the SAM and encrypts the nonce to verify the match.
- **Kerberos Authentication:** The upgraded default authentication protocol using secret-key cryptography, providing mutual authentication via a trusted third party called the **Key Distribution Center (KDC)** (comprises the AS and TGS).

> 💡 **LM Hashes Note:** NTLM supersedes the easily cracked LM hash. Vista and later disable LM hashes by default. If a password exceeds 14 characters, it is not possible to calculate an LM hash (a dummy value is stored instead).

### 📍 Tools to Extract Password Hashes

To make hashes available for offline brute-forcing, attackers must extract them using tools requiring **administrative privileges**.
- **pwdump7** ([tarasco.org](https://www.tarasco.org)): Dumps password hashes (one-way functions) from NT's SAM database by extracting the binary SAM and SYSTEM files.
- **Mimikatz** ([github.com/gentilkiwi/mimikatz](https://github.com)): Extracts plaintext passwords, hashes, PIN codes, and Kerberos tickets from memory.
- **Other Tools:** DSInternals ([github.com/MichaelGrafnetter/DSInternals](https://github.com)), PyCrack ([github.com](https://github.com)).

## 2. Types of Password Attacks

Password cracking attacks are classified into four main categories based on the attacker's approach:

### A. Non-Electronic Attacks
Exploits human behavior without technical system exploitation:
- **Social Engineering:** Tricking authorized users into breaking security procedures.
- **Shoulder Surfing:** Hovering near users to watch them enter passwords/PINs (e.g., at grocery store checkout lines).
- **Dumpster Diving:** Searching waste dumps, trashcans, or curbside containers for discarded password files or receipts.

### B. Passive Online Attacks
Passively monitoring data passing over a communication channel without leading to system changes:
- **Wire Sniffing:** Sniffing credentials during transit by capturing Internet packets (e.g., FTP, email out in plaintext) at the data link layer.
- **Man-in-the-Middle (MITM):** An attacker eavesdrops on traffic between two parties simultaneously.
- **Replay Attacks:** Packets and authentication tokens are captured using a sniffer and placed back on the network to replicate activities (like bank transfers).

## 3. Active Online Attacks & Practical Commands

Active attacks involve communicating directly with the target machine to gain password access.

### 📍 Dictionary & Brute-Force Attacks
- **Dictionary Attack:** Uses a text file of commonly used passwords, testing each one. Hackers improve success by adding string manipulations (e.g., anagrams) or tailoring lists to the target based on social media.
- **Brute-Force Attack:** Trying every combination of characters until the password breaks (an exhaustive key-search).

**Executing with John the Ripper:**
1. Download a wordlist (e.g., `rockyou.txt`):
   ```bash
   wget https://github.com/brannondorsey/naive-hashcat/releases/download/data/rockyou.txt
   ```
2. Generate a tailored/customized dictionary based on rules defined in `john.conf`:
   ```bash
   john --wordlist=</path_to/rockyou.txt> <path_to/output_wordlist.txt>
   ```
3. Start cracking NTLM hashes:
   ```bash
   john --rules --wordlist=</path_to/output_wordlist.txt> format=NT /path/to/ntlm_hashes.txt
   ```
4. View the cracked passwords:
   ```bash
   john --show /path/to/ntlm_hashes.txt
   ```

### 📍 Rule-Based Attacks
More powerful than basic brute-force when the attacker knows something about the password format (e.g., it ends in two digits).
- **Hybrid Attack:** Appending numbers/symbols to dictionary words (e.g., "system" -> "system1").
- **Syllable Attack:** Using combinations of letters to crack passwords that aren't known words.

### 📍 Password Spraying
Targets multiple user accounts simultaneously using a single commonly used password to avoid triggering account lockout policies on common ports (SMB 445/TCP, SSH 22/TCP, HTTP, etc.). Tools include **Metasploit**, **Rubeus**, **adfsbrute**, and **CrackMapExec**.

**Executing with THC-Hydra** ([github.com/vanhauser-thc/thc-hydra](https://github.com)):
```bash
# Specific login and password
hydra -l admin -p password ftp://localhost/

# List of logins, specific password
hydra -L default_logins.txt -p test ftp://localhost/

# Specific login, list of common passwords
hydra -l admin -P common_passwords.txt ftp://localhost/

# Two lists combined
hydra -L logins.txt -P passwords.txt ftp://localhost/
```

### 📍 Mask Attack
Similar to brute-forcing but utilizes a strict pattern/mask to drastically reduce cracking time based on known formats.

**Executing with Hashcat** ([hashcat.net](https://hashcat.net)):
- *Built-in Charsets:* `?l` (lowercase), `?u` (uppercase), `?d` (digits).
- *Custom Charsets:* `-1 ?l?u` determines charset 1 is any upper or lowercase letter.
```bash
# Crack a 6-char MD5 password (3 lowercase, 3 digits) [?l?l?l?d?d?d]
# -a 3 = brute-force attack | -m 0 = MD5 format
hashcat -a 3 -m 0 md5_hashes.txt ?l?l?l?d?d?d

# Crack password where first char is upper/lower, next 3 are lower, followed by '19', followed by 2 digits.
hashcat -a 3 -m 0 md5_hashes.txt -1 ?l?u ?1?l?l?l19?d?d

# Increment mode (unknown length between 6 and 10)
hashcat -m 0 -a 3 -i --increment-min=6 --increment-max=10 53ab0dff8ecc7d5a18b4416d00568f02 ?l?l?l?l?l?l?l?l?l?l
```

### 📍 Additional Active Techniques
- **Password Guessing:** Manually testing default passwords (e.g., for routers found on [routerpasswords.com](https://www.routerpasswords.com) or [cirt.net](https://cirt.net)). It can be automated via loops:
  ```cmd
  c:\>FOR /F "tokens=1,2*" %i in (credentials.txt)^ More? do net use \\victim.com\IPC$ %j /u:victim.com\%i^ More? 2>>nul^ More? && echo %time% %date% >> outfile.txt^ More? && echo \\victim.com acct: %i pass: %j >> outfile.txt
  ```
- **Trojans, Spyware, & Keyloggers:** Background malware explicitly logging user keystrokes silently.
- **Toggle-Case Attack:** Trying all upper/lowercase combos of a word (xyz, Xyz, xYz, XYZ, etc.).
- **Combinator Attack:** Merging two dictionaries together to crack full names or compound words.
- **Markov-Chain Attack:** Splitting passwords into 2-grams and 3-grams to develop new alphabets for matching.
- **GPU-based Attack:** Luring users to malicious sites/apps and using OpenGL APIs within the browser to intercept typed passwords.

## 4. Advanced Network Exploits (PtH, LLMNR, NTLM Relay)

### 📍 Hash Injection / Pass-the-Hash (PtH)
Instead of cracking the hash into plaintext, the attacker injects a compromised LM or NTLM hash directly into an authentication session (exploiting Windows SSO architecture).
1. Compromise a workstation and retrieve the admin hashes using **Mimikatz**.
2. Inject the retrieved hash into the attacker's local `lsass.exe` process to log onto the Domain Controller with those admin credentials.

### 📍 LLMNR/NBT-NS Poisoning
Exploits enabled-by-default Windows name resolution services (UDP 5355 and UDP 137). When DNS fails, Windows broadcasts to the network asking "Who is \\DtaServr?". The attacker responds falsely, capturing the victim's NTLMv2 hash.
- **Execution Tool:** **Responder** ([github.com/lgandx/Responder](https://github.com)).
  ```bash
  ./Responder -I eth0
  ```
- **Detection Tools:** **Vindicate**, **got-responded**, or **Respounder** ([github.com](https://github.com)).

### 📍 NTLM Relay Attack
Instead of cracking the captured hash offline, an attacker intercepts an NTLM request and relays it directly to the target server for immediate impersonation.
1. Use **Responder** to capture the request.
2. Use **impacket-ntlmrelayx** to forward the request to the SMB share:
   ```bash
   impacket-ntlmrelayx.py -of <path_to/SAM-NTLMv2dump file> -tf <path_to/relaytargets> smb2support
   ```

### 📍 Internal Monologue Attack
Designed to bypass Mimikatz prevention (Windows Credential Guard). It invokes a local procedure call to the NTLM authentication package using the SSPI context of the logged-on user to capture the NetNTLMv1 response without dumping memory, which can then be cracked offline.

## 5. Kerberos Vulnerabilities & Exploits

Kerberos, though highly secure, is vulnerable to offline cracking when attackers manipulate tickets.

### 📍 AS-REP Roasting (Cracking TGT)
Targets Active Directory user accounts that have the **"Do not require Kerberos preauthentication"** flag enabled.
- The attacker utilizes tools like `GetNPUsers.py` to request a Ticket Granting Ticket (TGT) without knowing the password.
- The Domain Controller responds with an AS-REP encrypted using the user's password hash, which the attacker then brute-forces offline.

### 📍 Kerberoasting (Cracking TGS)
Targets **service accounts** identified by Service Principal Names (SPNs). The attacker requests a Ticket Granting Service (TGS) ticket using their valid compromised domain user. The TGS is encrypted with the service account's RC4 hash. The attacker extracts it from memory (using **Rubeus**) and cracks it offline (using hashcat).

### 📍 Pass-the-Ticket (PtT) Attack
Dumping Kerberos tickets from memory using Mimikatz and passing them to other computers to authenticate without ever providing a password.
- **Silver Tickets:** Authorize access to specific services.
- **Golden Tickets:** Forged using the `KRBTGT` NTLM hash, granting domain-wide access to any resource.

## 6. Offline Attacks & Time-Memory Trade-offs

Offline attacks occur without communicating with the target system, boasting astronomical success rates due to speed and zero account lockouts.

### 📍 Rainbow Table Attack
A cryptanalytic time-memory trade-off utilizing a lookup table of precalculated cleartext passwords and their corresponding hashes. The attacker simply captures a hash and compares it directly against the table.
- **Creation Tool:** **rtgen** via RainbowCrack ([project-rainbowcrack.com](http://project-rainbowcrack.com)).
  ```cmd
  rtgen hash_algorithm charset plaintext_len_min plaintext_len_max table_index chain_len chain_num part_index
  ```

### 📍 Distributed Network Attack (DNA)
Utilizing the unused processing power of machines spread across a network to decrypt passwords. Managed by a central DNA Server.
- Tool Example: **Exterro Password Recovery Toolkit (PRTK)**.

## 8. Defensive Countermeasures & Attack Detection

### 📍 General Password Defenses
- Implement **Password Salting**: Adding random alphanumeric strings to a password before calculating the hash to completely defeat Rainbow Tables.
- Protect the SAM database by enabling the **SYSKEY** function.
- Do not store passwords in memory or cleartext. Store using strong hashing algorithms (bcrypt, Argon2, PBKDF2).
- Set an account lockout policy for a certain number of attempts.
- Rename high-privilege accounts (like `Administrator`) and restrict multi-site logins using geo-locking.

### 📍 Defending Against LLMNR/NBT-NS Poisoning
- **Disable LLMNR:** GPO -> Computer Config -> Admin Templates -> Network -> DNS Client -> Turn off multicast name resolution.
- **Disable NBT-NS:** Network Adapter Properties -> TCP/IPv4 -> Advanced -> WINS -> Disable NetBIOS over TCP/IP.
- Implement **SMB Signing** to severely mitigate NTLM Relay attacks.
- For critical services, force static DNS entries to abandon relying on weak local broadcast queries.

### 📍 Detecting SMB Attacks Against Windows
Attackers often target SMB (Server Message Block) due to its power to provide shared file/printer access. Detect and defend by:
- Monitoring for increased SMB traffic and unexpected SMB write requests.
- Detecting failed login attempts (possible Brute-Force).
- Spotting the use of tools like Mimikatz or Impacket via endpoint EDR software.
- Disabling older, highly vulnerable versions like **SMBv1** (cause of EternalBlue).
- Relying heavily on Network Segmentation and strict Firewall Rules restricting external IP access to SMB shares.
